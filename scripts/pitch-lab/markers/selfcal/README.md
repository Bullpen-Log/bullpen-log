# 마커 정답지 — 보정 장치 없이 몸 스티커로 카메라 맞추기 (2026-10-12 촬영)

3D 엔진(옆 · 뒤 영상)이 맞힌 관절을 채점할 **정답지**를 만든다. 촬영 때 바닥 스티커 · 막대(A) · 몸 보정(B1 · B2) · 시작 신호가
빠져서, 몸에 붙인 스티커 31개와 2D 관절(RTMW)로 시간 · 카메라를 대신 맞춘다. 상위 도구는 `../markers.py`(색 찾기 · 교차).

**저장소에 넣지 않는 것**: 영상(GPS 메타데이터가 들어 있다) · 찾은 자료(`work/det`, `work/kp`, `work/rec`) · 줄자 기록(`session-notes.json`).
맥북 · 데스크톱 모두 세션 폴더는 `~/bullpen-marker-lab/2026-10-12/`(영상은 `videos/투구NN_cN.mov`, 64개). 스크립트는 **그 폴더에서** 돌린다
(자료 폴더 = 지금 폴더/`work`, 바꾸려면 `MARKER_WORK`).

결과 파일(`results-2026-10-12/`): `cal16.json`(16개 투구 · 무리 거리 조건, **지금 기준**) · `offs16.json`(투구마다 시간 어긋남) ·
`calL_odd.json` · `calL_even.json`(홀짝 검증용) · `world_first.json`.

**카메라 실제 자리**(첫 세상 좌표): c1 아이패드 3루 쪽 7.0m · c2 15 Pro Max 뒤(2루 쪽) 4.1m · **c3 아이폰 11 홈 쪽 정면 5.9m(안내서의 1루 자리가 아님)** ·
c4 SE2 1루 쪽 6.2m, 높이 0.9~1.4m. 초점 ≈ c1 1450 · c2 1336 · c3 1517 · c4 1528px(c2 · c4 는 폰 사양 계산값 1332 · 1554 와 맞음).

**정확도(홀수 · 짝수 투구로 따로 맞춘 둘을 같은 관측에 대어 봄, 닮음 변환 뒤)**: 3D 차이 가운데 0.5~0.6cm · 상위 10% 1.4~1.7cm.

**겪은 함정**
- 초점은 데이터만으론 약하게 정해진다(초점 ↔ 카메라 거리). 투구 하나로는 5~10% 흔들렸고, 16개를 모으고 '뼈에 붙은 짝 거리 일정' 조건을 넣어 묶었다.
  그래도 c1(가장 멂) 초점은 반쪽마다 1395 / 1608px.
- 거리 조건을 cm 벌점으로 두면 LM 이 장면을 통째로 줄여 벌점을 없앤다(카메라 |t| 0.004 로 쪼그라듦) → **비율 벌점**(`RIGID=100` = 1% 흔들림 1px) + c2 거리 고정.
- 이름 짝 길이를 16개 투구 공통으로 두면, 몇 투구에서 궤적 하나가 다른 스티커로 붙은 것(예: 투구 9 의 L11-L13 35cm)이 전체를 망친다 → 투구마다 길이 따로, 10% 넘게 벗어난 (짝, 투구)는 뺌.
- scipy least_squares 에 초점을 px(1600)로 두면 거의 안 움직인다 — ÷1000 으로.
- 줄자 배율이 짝마다 약 8% 흩어진다: 정강이(무릎 밖~바깥 복사뼈) 44 vs 줄자 45cm 로 가장 맞고, 위팔(어깨 봉우리~팔꿈치 밖)은 28 vs 32, 넙다리(큰돌기~무릎 밖)는 48 vs 44.
- Modal 스크립트가 로컬 모듈을 import 하면 컨테이너에서 실패 → `modal.is_local()` 일 때만.

## 앞으로 (단계마다 사용자 허락 뒤)

**3단계 마무리 — 약 15분**
1. 16개 전부로 최종 보정: `LABELS=work/labels.json RIGID=100 K1=0 vpba.py ... cal16.json offs16.json cal_final.json`(비율 벌점).
   c1 초점이 아직 약하면 반쪽 둘의 평균 근처로 묶을지 정한다.
2. 미터: 정강이처럼 뼈끼리 붙은 짝 위주로 배율. 줄자가 어느 점에서 어느 점까지였는지 김민에게 한 번 더 확인하면 더 좋다(위팔 · 넙다리가 4cm씩 어긋남).
3. 바닥 · 방향: 멈춘 발 스티커 RANSAC(들어맞음 63%, 그 점 4mm 안) · x = 던지는 쪽.

**4단계 관절 가운데 — 1~2시간**
1. 빈 스티커 채우기: 투구마다 31개 중 15~21개만 3D(카메라 둘 이상에 동시에 보여야 함). 먼 c1 의 작은 스티커(4~5px)를 더 잘 찾고,
   골반처럼 한 덩어리인 스티커는 보이는 것으로 안 보이는 것을 채운다. 2D 궤적이 다른 스티커로 넘어가는 것(이름 틀림)도 고친다.
2. 가운데 계산: 팔꿈치 · 무릎 · 발목 · 손목 = 안쪽 · 바깥쪽 가운데, 엉덩이 = 골반 앞(P1 · P2) + 골반 폭 30cm 회귀(P3 · P4 는 대충 붙여 방향만),
   어깨 = 봉우리 스티커에서 아래로. 엔진이 '관절 가운데'를 내니 같은 것끼리 비교하려고.

**5단계 엔진 채점 — 약 1시간**: 같은 투구의 옆(c1) · 뒤(c2) 영상으로 엔진을 돌리고, 시간 · 좌표를 맞춘 뒤 관절별 위치(cm) · 각도(°) 오차를
구간별(다리 들기 · 착지 · 릴리스)로.

**그 뒤**: 6 엔진 고치기(오차 큰 관절 · 구간부터, 고칠 때마다 다시 채점) → 7 채점을 명령 하나로 도는 시험으로 →
8 두 번째 촬영(막대 휘젓기 1분 · 시작 박수 · 안내서 자리, 다른 투수 · 좌투 · 100% · 다른 장소) →
9 출시 기준(채점 숫자로 '몇 cm · 몇 ° 안이면 보인다' — 3D v2 정할 것 ③) → 10 출시 전 드라이브라인 자료 허락 · 실제 사용자 영상 확인.
