# 운동·메커니즘 영상 검수 — 현재 공통 세팅

2026-11-13 사용자 지시. 운동영상 세션의 최신 지시를 메커니즘 검수와 김민의 검수에 같은 방식으로 적용한다. 이전 안내의 ‘의견만 기록하고 전체 종료 후 수정’과 ‘매 영상 종료·재반복까지 기다리기’보다 이 문서가 우선한다. 이번 인계 자체로 영상·설명·DB를 일괄 수정하지 않는다.

## 진행 순서

1. `docs/reviews/handoff/README.md`에 따라 자기 기록을 수신하고 현재 항목·미완료 요청을 읽는다. 운동/메커니즘, 김민/금윤호 기록을 분리하고 현재 순서를 초기화하지 않는다.
2. 화면에 보이는 브라우저에서 현재 영상 하나와 제목·설명을 함께 연다. 운동은 `https://dugout-baseball.com/library/training?review=<실제 운동 ID>`, 메커니즘은 `https://dugout-baseball.com/library/mechanics?review=<실제 드릴 ID>`다. DB 항목 ID와 영상 파일 ID를 혼동하거나 추측하지 않는다. 모호하면 기존 목록에서 직접 선택한다.
3. 공통 플레이어로 재생한다. **반복 켜짐 상태만 확인하고 끝나서 다시 시작할 때까지 기다리지 않는다.** 내용 대조에 필요한 장면은 확인하되 반복 시험을 매번 하지 않는다. 재생바·정지·배속·확대를 사용하며 오류면 현재 항목을 유지한다. YouTube는 공식 화면과 지원 기능을 보존한다.
4. 시범·원본 제목·설명을 운동역학 및 국내외 원저·체계적 문헌고찰·공식 학회 자료와 대조한다. 직접 근거와 유사 운동의 간접 근거, 대상·도구·변형·부하·급성/장기 효과를 구분한다. 연구가 없는 최적 중량·횟수·휴식이나 구속 향상 보장을 만들지 않는다.
5. 현재 사용자가 정한 수정 방향과 이 공통 방식의 범위 안에서 **제목·소개·수행 방법·훈련 목적·필요한 처방/안전 문구를 구체화해 먼저 수정·저장**한다. 무엇을 왜 고쳤는지와 근거·한계를 짧게 보고하고 그 영상에서 사용자 확인을 받는다. 저장 성공뿐 아니라 다시 읽어 표시 결과를 확인한다. 불명확한 동작이나 중요한 정책 결정은 추측해 저장하지 않고 질문한다.
6. 사용자 확인 후 ‘다음/오케이’ 등 명시적인 이동 지시가 있을 때만 다음 영상을 연다. 반복 종료·시간 경과·설정 인계는 이동 승인이 아니다. ‘수정하고 다음’처럼 이미 이동을 지시했으면 같은 승인을 반복 요청하지 않는다.
7. ‘기록하지 말고 바로 수정’은 수정 메모만 쌓고 적용을 미루지 말라는 뜻이다. 컴퓨터 간 재개에 필요한 최소 기록은 계속 남긴다: 실제 ID/영상 판, 수정 전후·이유, 저장/재확인 결과, 사용자 확인 대기/완료, 다음 항목, 미해결 사항. 저장 후 읽기 검증하고 승인된 비민감 기록 공유 절차를 따른다.

## 운동 장비·부하 기록 추가 검수

운동영상에서는 `docs/shoot/exercise-load-review-standard-20261117.md`를 함께 읽고 각 영상의 실제 장비와 등록 장비, 받침과 중량, 시간·횟수·도구별 무게의 뜻, 밴드 저항/보조, 대체·복합 장비 및 1RM 적용 여부를 해당할 때 확인한다. 관리자 설정은 읽기 확인을 기본으로 하며 알 수 없는 설정과 잠긴 예외를 우회하지 않는다. 새 기준 자체는 장비 메타데이터·기록 의미·프로그램·기존 이력의 일괄 변경이나 서비스 테스트 허가가 아니다. 실기기 저장 왕복 검증은 미확인이다. 기존 영상·판정·사용자 확인 상태를 유지한다.

## 설명 구성과 메커니즘 추가 점검

- **어떤 운동/드릴인가:** 실제 동작을 간단히 설명한다. 원본 영어 제목 해설이나 불필요한 비교로 채우지 않는다.
- **이렇게 하세요:** 시작 자세 → 동작 순서 → 복귀, 장비·부하 선택과 중단 기준을 구체적으로 쓴다.
- **투수에게 왜 필요한가:** 훈련 목적과 관찰할 연결을 설명한다. 실제 투구 동작과 보조 운동을 동일시하거나 효과를 보장하지 않는다.
- 메커니즘은 해당 투구 단계·관찰점·흔한 실수·드릴 목적, 좌우 투수·촬영각도·개인차, 공 던지는 횟수와 일반 반복의 차이를 추가로 대조한다. 3D 엔진·AI 처방 알고리즘은 수정하지 않는다.
- 직접 촬영/참고만 있음/없음을 구분한다. 편집·재촬영이 필요하면 시간대와 이유를 제시한다. **미디어 교체·삭제·다운로드·재업로드·일괄 편집, 새 권리 이용은 별도 구체 지시 없이 실행하지 않는다.**
- 한국·미국·일본의 표현·안전·권리 쟁점을 사실·근거·미확인 사항별로 구분한다. 이 절차만으로 법률 검토 완료를 선언하지 않는다.

## 아이소메트릭 운동 공통 검수

어떤 운동인가에는 자세를 크게 바꾸지 않은 채 힘을 주는 아이소메트릭의 의미와 해당 운동의 실제 자세를 짧게 설명한다. 이렇게 하세요에는 장비, 힘의 방향과 해당 운동의 목적·시간에 맞는 노력, 호흡과 중단 기준을 명확히 적는다. 왜 필요한가에는 실제 근육이 저항에 힘을 내는 방식, 힘줄의 힘 전달, 근육 길이에 따른 힘 발휘와 투구 연관을 해당 동작에 필요한 범위에서 연결한다. 늘어난 근육 길이의 효과, 힘줄 적응, 움직임 전이와 구속 향상은 해당 자세·강도·근거를 확인하며 단정하지 않는다. 강도와 힘의 크기는 운동마다 정하며 모든 등척성 운동에 동일한 30초나 비최대 지시를 적용하지 않는다. 문장과 문단 배치를 일관되게 하고 반복 설명은 줄인다.

## 담당과 저장 경계

김민의 운동 분류는 워밍업·상체·하체·모빌리티, 금윤호는 파워·코어·운동 분류 암케어·회복보강이다. 별도 암케어 담당 경계는 기존 합의를 따른다. 메커니즘 검수 세팅 공유는 담당 재배분이 아니다.

김민은 자기 계정과 자기 진행을 사용하고 금윤호의 완료/판정을 복제하지 않는다. 현재 기록 동기화 도구의 허용 경로는 `yunho`뿐이다. 김민 기록은 `exercise/min/` 또는 해당 별도 검수자 경로로 분리하되, 도구가 그 경로를 지원한다고 가정하거나 yunho로 위장해 게시하지 않는다. 지원되지 않는 기록 공유는 안전한 문서 인계로 처리하고 경로 확장은 별도 구현으로 한다. 로그인 세션·비밀번호·서명 URL·영상 원본은 공유 문서에 넣지 않는다.

## 실제로 쓴 출처의 근거 등록(EX-REF04)

검수 판단·제목·설명·처방·안전 문구에 실제로 쓴 출처는 쓰는 그 순간 `docs/reviews/review-evidence-registrar.md`대로 자기 계정으로 `register`한다. 찾아보다 쓰지 않은 출처·검색 결과·열어만 본 페이지는 등록하지 않으며 도구가 저절로 모으지도 않는다. `--review`는 기록의 `review_id` 그대로, `--item`은 운동·드릴 DB ID를 알 때만, `--reading`은 실제로 읽은 범위만큼만(모르면 `unknown`) 넣는다. 인용 링크는 기록의 링크 칸에 따로 적고(링크 뒤에 한글을 붙여 쓰지 않는다), 받음표(opId·sourceId·useId)나 대기 `requestKey`를 넣은 쓴 곳(`purpose`)·운동/드릴 번호(`item_id`, 뺐으면 null)와 함께 비밀 없이 최소 재개 기록에 남긴다. 다른 맥에서 같은 쓰임으로 다시 등록할 때 기록에 `purpose`·`item_id`가 없으면 짐작하지 말고 처음 맥에서 retry한다. 쓰지 않아 버리거나 거둔 출처의 링크는 기록에 남기지 않고 링크 없는 표시만 둔다(남기면 audit이 늘 빠진 등록으로 멈춘다). 세션 시작 때 `retry --max 20`을 한 번 한다. 끝 번호 0은 이 맥에 보낼 대기가 남지 않았다는 뜻일 뿐이며, 기록에 대기로 적힌 requestKey가 결과에 없으면 `pending`의 `rejected[]`에서 찾는다. 인계 전에 자기 계정으로 `audit --reviewer yunho|kimmin`을 하며 `--records`는 receive/publish하는 checkout의 기록 절대 경로(`"$(git rev-parse --show-toplevel)/docs/reviews/handoff/…"`)로 준다. 로그인 전 `status`의 끝 번호 4는 정상이다. 이 등록은 검수 기록의 `receive`/`publish`(Git 공유)와 별개이며 세션·쿠키·대기열은 맥마다 따로라 복사하지 않는다. 2026-11-20 현재 R2 서버 코드가 운영에 배포되지 않아 운영 주소 등록은 대기로만 남는다. 대기나 시험 저장소 결과를 등록 완료로 보고하지 않는다. 김민 기록(`min/`)은 아직 audit할 수 있는 모양이 아니다.

## 김민·메커니즘 담당 세션에 전달할 시작 지시문

> 현재 공통 지침과 docs/shoot/video-review-current-workflow.md, 운동영상의 경우 docs/shoot/exercise-load-review-standard-20261117.md, docs/reviews/handoff/README.md, 내 담당 인계를 읽고 기존 검수를 이어가줘. 현재 영상·판정·순서를 보존하고 내가 맡은 분류만 검수해. 운영 라이브러리의 공통 플레이어를 화면에 보이게 열고 반복 켜짐만 확인해. 반복되는 순간을 기다리지 마. 각 영상의 제목·시범·설명을 운동역학과 논문/공식 학회 근거로 확인하고, 내가 정한 방향 안의 제목·설명·필요한 처방을 먼저 구체화해 수정·저장한 다음 다시 읽어 결과를 보여줘. 수정한 점·이유·근거의 적용 한계와 내가 확인할 장면을 알려줘. 불명확한 사실은 질문하고 미디어 자체를 임의로 편집·교체하지 마. 내가 다음을 승인할 때만 이동해. 실제 수정과 사용자 확인 상태는 분리해 최소 재개 기록을 저장·공유하고 다른 검수자 기록과 섞지 마. 실제로 판단이나 문구에 쓴 출처는 docs/reviews/review-evidence-registrar.md대로 쓰는 순간 내 계정으로 등록해 받음표나 대기 requestKey를 쓴 곳·운동/드릴 번호와 함께 기록에 남기고, 세션 시작 때 retry, 인계 전에 audit을 하되 대기나 시험 저장소 결과를 등록 완료라고 하지 마. 지금은 기존 현재 항목을 열어 세팅만 맞추고, 인계 때문에 내용을 일괄 수정하거나 다음으로 넘기지 마.
