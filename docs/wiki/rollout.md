# Sinker Wiki member rollout

The website and Sinker app offer the Wiki in the Library menu. Anyone with a valid Sinker session can read the approved catalog, including ordinary and pilot beta members. Existing Board and Admin policy remains in effect. The browser and app fetch the catalog only after verifying the active account and keep it out of persistent caches.

- Keep the reviewed snapshot outside Git, in the private Supabase bucket `sinker-wiki-private` under `v1/<sha256>.json`. The server-only release manifest pins the reviewed default by byte digest. Existing Supabase server access reads the single object, checks its size, hash, schema, and published status, then removes editorial backlog, removal records and private review notes before responding. Source links, review provenance and photo credit remain visible.
- The optional server-only `SINKER_WIKI_SHA256` Production setting can pin another reviewed digest. Set it to `off` to disable the reader on the next deployment. An empty or malformed override, missing object, digest mismatch or invalid content fail closed. Remove the override to restore the pinned default. Do not use a client-prefixed variable or bundle the snapshot or photos in web or app assets.
- Verify the web API first. `GET /api/board/wiki` returns 401 without a session, 200 for a signed-in member with valid storage, and a generic 503 when the catalog is disabled or unavailable. Check `Cache-Control: private, no-store, max-age=0`, including after a successful request. Verify the anonymous direct Storage endpoint and signed-in Storage policy deny access. Verify a normal member menu and article link, then distribute the compatible iOS update and check a cold link when a test device is available.
- Roll back with the last approved digest or disable the Wiki with the server setting and redeploy. Roll back web or Expo updates using the standard release procedures if necessary.
