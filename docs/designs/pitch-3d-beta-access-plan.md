# 출시 전 투구 3D 전용 베타 — 권한·인터페이스·출시 계획

2026-10-29. 사용자 확정: **투구 3D만 허용**, 스윙 3D 제외. 상태: 소스 조사 기반 설계, 제품 코드/계정/DB/배포 변경 없음. 실제 계정별 앱 동작은 이번에 실행하지 않았다.

## 1. 설계 결정

사용자의 기존 역할은 그대로 두고 출시 상태에 따른 기능 이용 정책을 별도 계층으로 추가한다. 대표관리자만 베타 기능 제한에서 제외한다. 준관리자는 일반 체험 화면에서는 일반 사용자와 동일한 투구3D 전용 경험을 보고, 기존 관리자 업무는 별도 관리자 진입에서 기존 권한 그대로 사용한다.

| 영역 | 일반 USER | 준관리자 MANAGER | 대표관리자 ADMIN |
| --- | --- | --- | --- |
| 투구3D 사용자 흐름 | 본인 자료 허용 | 본인 자료 허용 | 기존 권한 유지 |
| 스윙3D·기타 사용자 주요 기능 | 베타 잠금 | 베타 잠금 | 기존 권한 유지 |
| 계정·로그아웃·도움말·개인정보 관리 | 허용 | 허용 | 허용 |
| 관리자 업무 | 기존대로 불가 | 기존 허용 업무만 | 기존대로 |
| 베타 허용 목록 변경 | 불가 | 불가 | 운영 정책 관리 주체 |

기능 제한 예외는 `role === 'ADMIN'`만. `accountType === 'MASTER'`는 팀·레슨장 계정이므로 대표관리자 예외가 아니다. 기존 객체 소유권, 국가 제한, 동의, 비용·호출 한도는 베타 허용과 별도로 유지한다.

## 2. 코드에서 확인한 사실

- `lib/permissions.ts`: ADMIN 대표관리자, MANAGER 준관리자, USER 일반. 준관리자 현재 허용은 `adminHome`, `shoot`, `velocityAdmin`, `recording`, `abs`. `dev3d`는 미허용. 구현 시 최신 표를 다시 확인한다.
- `lib/dal.ts`의 `isMasterUser`는 ADMIN 또는 accountType MASTER다. 베타 예외에 재사용하면 일반 조직 계정까지 풀리는 문제가 생긴다.
- `lib/feature-locks.ts`는 투구·트레이닝·영양의 초기 설정 잠금이다. 이번 출시 잠금과 다른 의미이며 초기 설정 완료로 베타 제한이 해제돼서는 안 된다.
- 웹 투구3D `/videos/lab`는 잠글 상위 투구 `/videos` 안에 있다. 가장 구체적인 기능을 먼저 판별해야 한다. `/lab` 네이티브 경로와 웹 경로를 같은 capability로 연결한다.
- `native/src/app/analysis.tsx`와 `app/actions/app-analysis.ts`는 투구량/트레이닝 통계다. 이름이 analysis라고 투구3D로 허용하면 안 된다.
- 정식 투구3D 앱: `native/src/app/lab/index.tsx`, `new.tsx`, `guide.tsx`, `[id].tsx`. 목록의 ‘내 리포트’는 `pitch-lab.loadAppLabList('mine')` 사용.
- 웹 `app/(app)/videos/lab/page.tsx`, `loadAppLabList`, `loadAppLabDetail`은 현재 투구 첫 설정으로 보낼 수 있다. 전체 투구 설정을 열어주는 대신3D 필수 입력만 독립시켜야 한다.
- 분석 작업: `app/actions/pitch-lab.ts`의 `saveLabSample`, `requestPitch3dV2`, `checkPitch3dV2`, `loadPitch3dV2`, 목록·상세 및 관련 함수. 등록/재시도에도 기존 비용·동의·영상 검사를 유지한다.
- `/api/pitch-lab/upload-url`는 투구뿐 아니라 `sport=hit`도 처리한다. 엔드포인트 전체 허용이 아니라 sport와 작업 목적을 검사해야 한다.
- `app/api/rpc/registry.ts`는 모듈 단위 액션 등록. RPC 입구만 막으면 웹 Server Action 직접 호출은 남는다. 서버 액션/서비스와 개별 Route Handler도 검사해야 한다.
- `app.loadAppMe`는 현재 isAdmin과 초기 설정 locks를 반환. 베타 정책 버전과 기능별 상태를 별도 응답으로 전달할 수 있다.
- `native/src/shell/tab-bar.tsx` 현재 탭은 홈·투구·트레이닝·기록·덕아웃. `menu-store.ts`는 웹 브리지의 locked를 받는다. 기존 locked 값에 이유 없는 베타 잠금을 섞으면 설정으로 잘못 이동할 수 있다.

## 3. 허용 기능의 범위

투구3D는 버튼 하나가 아니라 완결된 작업이다: 촬영 안내 → 옆/뒤 영상 선택 → 필수 키/던지는 손/조건/동의 확인 → 업로드 → 분석 요청 → 진행 조회 → 실패 설명/허용된 재시도 →3D/원본/결과 → 내 분석 이력. 본인 자료 삭제 등 기존 데이터 관리도 유지한다.

분석 결과에 포함된 설명·기존 드릴 설명은 결과 읽기의 일부로 유지할 수 있다. 별도 운동 시작·처방 프로그램 등록·수행 기록·메커니즘 비교 워크플로는 기본 잠금이다. 결과 화면이 그것을 필수로 호출한다면 읽기 전용 결과 데이터를 분리한다. 드릴 영상이 결과 이해에 꼭 필요한 경우 해당 결과와 연결된 정확한 미디어만 허용하고 전체 라이브러리를 열지 않는다.

지원 영역: 로그인·가입·세션갱신·비밀번호복구·로그아웃·필수 약관·내 정보·계정삭제 등 개인정보 관리·앱 업데이트 확인·고객센터/버그 신고. ‘지원’이라는 큰 모듈 이름으로 다른 기능까지 허용하지 않는다. 가입 기본 권한을 바꾸거나 신규 사용자에게 관리자 역할을 부여하지 않는다.

잠금: 일반 투구 기록/구속 측정/ABS/타격/스윙3D/트레이닝/암케어/영양/전체 기록 통계/라이브러리/덕아웃 거래·커뮤니티·예약/팀 관련 사용자 업무. 준관리자의 기존 운영 업무 예외는 다음 절의 좁은 경계를 따른다. 서버 내부 인증된 운영 콜백과 사용자 기능을 구분한다.

## 4. 준관리자 권한 유지의 정확한 의미

관리자 메뉴 위치를 유지하고 ‘관리 업무’ 영역에서 기존 허용 도구를 보여 준다. 업무에 필요한 공용 촬영·녹화·구속·ABS 경로도 호출 체인을 추적해 최소한으로 허용한다. URL이 /admin 아래라는 이유 또는 role이 MANAGER라는 이유만으로 전체 기능을 우회하지 않는다.

서버는 해당 작업과 기존 permission, 입력, 리소스 범위를 함께 확인한다. 클라이언트가 `mode=admin` 또는 헤더를 붙인다고 예외가 생겨서는 안 된다. 일반 기능과 관리 업무가 같은 서버 함수를 쓰면 명시적인 업무 동작/입력 범위를 나누거나 기존 권한 검사를 강화한다. 기존에 가능하던 관리자 업무가 계속 완료되는지 실제 통합 시험으로 입증한다. 불가하던 회원/역할 관리·3D 개발 관리가 새로 열려서는 안 된다.

## 5. 서버 정책

초기 버전은 DB 변경 없이 버전 관리되는 서버 정책 모듈을 권장한다. `releaseStage: restricted_beta | released`, `policyVersion`, 일반 사용자 capability 허용 목록, 지원 작업, 관리자 업무 정책을 명시한다. 향후 토글 관리자 UI가 필요하면 별도 범위로 설계한다. 클라이언트 공개 환경변수만으로 접근을 결정하지 않는다.

판정 결과는 `allowed`, `locked_beta`, `setup_required`, `permission_denied`처럼 원인을 구분한다. 정상 사용자 기능의 기본값은 베타 단계에서 거부, 미분류 기능도 거부한다. 기존 역할/소유권 검사를 통과한 뒤 기능 출시 여부를 검사한다. 대표관리자도 기존 보안/동의/비용 검사를 우회하지 않는다.

정책은 기능키, 웹/native 경로, RPC 함수, Server Action, API 작업을 연결하는 검토 가능한 목록으로 관리한다. 경로는 세그먼트 경계와 쿼리를 분석한다. `/videos/lab` 예외를 `/videos`보다 먼저 처리하고 `sport=hit`, `view=log` 등 같은 경로의 다른 동작도 분리한다.

UI 가드는 편의용. 실제 강제는 서버 작업에서 데이터 조회·파일 URL 발급·업로드 예약·GPU 실행·쓰기 전에 수행한다. RPC는 일관된403 `FEATURE_LOCKED_BETA` 응답을 전달하고 웹 액션도 각자 이 정책을 검사한다. 기존 인증 오류와 앱 업데이트 오류를 베타 잠금으로 오인하지 않는다.

비로그인 요청도 제한된 사용자 기능을 공개 API로 우회하지 못하게 한다. 공개 로그인/정책 문서는 유지하고, 익명 상품·지도·커뮤니티 조회 등 현재 공개 서비스는 목록을 작성해 출시 정책에 맞게 잠금 처리한다. 인증된 결제 웹훅·기존 주문의 정산/환불/데이터 권리 처리는 새 구매 기능과 구분하고 중단하지 않는다.

## 6. 현재 앱 틀을 유지하는 화면

기존 테마·로고·서체·카드·하단 탭 형태·안전영역·모션을 유지한다. 새 앱을 별도로 만들지 않는다.

홈은 현재 카드 스타일로 다음 순서:
1. 작은 ‘베타 체험’ 상태, ‘지금은 투구3D 분석을 체험할 수 있어요.’
2. 대표 카드 ‘투구3D 분석’ + 주요 버튼 ‘새 분석 시작’ + 보조 ‘촬영 방법’.
3. 진행 중인 분석이 있다면 그 상태와 이어보기. 중복 분석을 권하지 않음.
4. ‘내 분석’ 최근2~3건과 전체보기. 전체 기록 탭과 혼동하지 않음.
5. 작은 ‘준비 중인 기능’ 묶음. 각 항목 잠금 아이콘과 ‘준비 중’ 표기. 큰 잠금 카드로 홈을 다시 채우지 않음.

하단 기본 탭의 순서와 라벨을 유지: 홈 정상, 투구·트레이닝·기록·덕아웃은 잠금. 투구3D는 홈에서 바로 들어가므로 잠긴 투구 탭을 통과할 필요가 없다. 분석 목록은 ‘내 분석’에서 열고 일반 기록은 잠긴다. 더보기는 지원/계정 메뉴와준관리자 관리 업무만 활성화, 나머지 주요 기능은 잠금 요약.

잠긴 탭을 누르면 기존 화면을 유지하고 작은 안내만 표시: ‘아직 준비 중인 기능이에요. 지금은 투구3D 분석을 체험해 주세요.’ 잠긴 화면을 먼저 띄우거나 설정 완료로 유도하지 않는다. 하단 드래그/스와이프/뒤로가기/딥링크 모두 같은 제한. 접근성에서 사용 불가와 이유를 전달하고 안내가 눌러지는 컨트롤은 안내 버튼으로 의미를 명확히 한다. 색만 흐리게 처리하지 않는다.

투구3D에서 뒤로가기는 베타 홈/내 분석으로 돌아온다. ‘투구’ 상위 페이지가 잠겨 있어도 막다른 경로가 생기지 않는다. 사용자 첫 설정은3D 필수 입력만 받고 초기 투구/영양/운동 설문을 강제로 거치지 않는다. MEMBER/MASTER 계정도 역할 변환 없이3D를 사용할 수 있는지 홈 리다이렉트를 검토한다.

## 7. 기존 앱·캐시·오프라인

서버 정책을 앱 시작/로그인/복귀 시 확인하고 userId+policyVersion으로 캐시를 분리한다. 미확인 상태에서는 기능이 잠깐 열리지 않게 로딩/제한 상태. 네트워크 장애 때 정책을 임의로 전체 허용하지 않는다. 잠긴 탭의 화면 컴포넌트와 prefetch도 실행하지 않는다.

기존 로컬 기록/초안/대기열은 지우지 않는다. 잠긴 기능의 대기열은 보류하고 자동 재시도/계정 간 전송을 막는다. 잠금 오류를 일시 서버 장애로 취급해 반복하지 않는다. 로그아웃/역할 변경/정책 변경 때 열려 있는 화면과 캐시도 다시 판정한다.

옛 앱은 서버에서 막아도 로컬 전용 기능이나 이미 받은 자료까지 즉시 회수할 수 없다. 기존 앱 버전별 정책 지원 여부와 업데이트 안내를 확인한다. 필요한 경우 최소 지원 버전 정책을 기존 체계로 설계한다. ‘모든 설치본을 즉시 완전히 잠갔다’고 주장하지 않는다.

이미 발급된 signed URL은 만료 전까지 사용할 수 있을 수 있다. 새 발급은 서버에서 검사하고 수명/캐시를 조사한다. 정책 전환 전 수락한 작업은 내부적으로 안전하게 마무리하되 새 작업 시작은 다시 판정한다. 내부 GPU/저장 처리 콜백을 사용자 기능 잠금으로 일괄 막지 않는다.

## 8. 세 차례 검토와 단계별 구현

1차 권한 검토: ADMIN/MANAGER/USER × PLAYER/MEMBER/MASTER × 익명. 준관리자 기존 업무를 열되 일반 기능 우회는 차단하는 표 확정.
2차 의존성 검토: 신규 계정이3D 등록→분석→결과까지 갈 때 필요한 서버·미디어·온보딩 경로를 추적. /videos 상위 잠금, sport=hit 공용 업로드, 처방 버튼의 우회 검사.
3차 전환 검토: 옛 앱/열려 있는 세션/직접 URL/오프라인 대기열/캐시/진행 중 작업/출시 전환과 되돌리기 검사.

실행 순서: 기능·작업 목록 → 순수 정책과 테스트 → 서버 가드 → 정책 bootstrap/캐시 → 앱 홈·탭·직접 경로 → 웹/공개 API 동일 정책 → 통합/시각 검수 → 승인된 배포.

서버 제한 활성화 시 옛 앱이 오류를 반복할 수 있으므로 클라이언트 호환 준비와 배포 순서를 함께 정한다. 운영 적용은 사용자 배포 요청이 있을 때. 출시 전환은 정책 값만 바꾸며 역할/사용자 기록/초기 설정 상태를 일괄 수정하지 않는다. 베타 해제 후에도 기존 권한 및 초기 설정 규칙은 유효하다.

## 9. 검증 완료 기준

- USER·MANAGER는 투구3D 전체 흐름 완료, 스윙3D/일반 주요 기능 차단.
- ADMIN 기존 기능 정상. USER+MASTER, MANAGER+MASTER가 대표 예외를 얻지 않음.
- 준관리자 adminHome/shoot/velocityAdmin/recording/abs 업무 회귀와 dev3d/역할관리 거부.
- 직접 웹 Server Action, RPC, 개별 API, 업로드 sport 변경, native 딥링크, 웹뷰·알림 링크 우회 시험.
- 거부 시 DB 쓰기·업로드 발급·GPU 호출이 전혀 실행되지 않았음을 모의 의존성으로 확인.
- 본인/타인 샘플 권한, 신규 계정 설정 루프 없음,3D 종료 후 잠긴 부모로 이동 없음.
- 같은 함수의 읽기/쓰기/관리 목적 구분, 미분류 신규 액션은 기본 거부.
- 계정 교체·정책 복귀·오프라인·대기열·옛 앱 동작 검수.
- iPhone 작은 화면/큰 화면, iPad, 큰 글씨/VoiceOver와 웹 기본 진입 확인. 실제로 확인한 기기만 보고.
- 분석 엔진 품질 개선은 이번 목표가 아니다. 실제 GPU 비용/운영 데이터 변경 없이 모의 처리로 정상·대기·실패·재시도 검증. 실분석 비용 시험은 별도 승인 범위.
- 결과물: 기능 접근표, endpoint inventory, before/after 화면, 통합 시험 결과, 알려진 옛 앱·signed URL 한계, 활성화/출시/되돌리기 절차.
