# 3D 투구 리포트 → 진단 → 메커니즘 처방 설계 (2026-10-21)

김민: "3D 투구분석으로 리포트를 만들고, 그걸 바탕으로 메커니즘 투구 드릴과 연동해 바로 문제 해결 처방까지.
가장 중요한 건 가장 신뢰할 수 있는 데이터로 최대한 정확하게 진단하는 것, 두 번째는 그 진단을 메커니즘 파트와 연동하는 것."

## 0. 원칙

1. **틀린 '고칠 점'이 가장 나쁘다.** 틀린 진단은 틀린 처방이 되고, 사용자는 맞는 동작을 고친다. 그래서 확실할 때만 진단한다(놓치는 쪽을 택한다).
   지금 판정도 같은 원칙이다 — 마커 15구에서 앱이 잘못 낸 '고칠 점' 0(`docs/designs/pitch-mechanics-checks.md` 3절).
2. **잴 수 있는 것만 진단한다.** 마커 정답으로 엔진 오차를 잰 지표만 진단에 쓴다. 못 잰 지표는 숨기거나 '참고'로만.
3. **무료는 1구, 프로는 최대 3구**(2026-10-21 김민 결정 — 10절). 엔진 한 구 오차가 같은 선수의 구마다 흔들림보다 커서(분리 3.4° vs 1.5°)
   여러 구가 더 정확하지만, 사용자 번거로움 · GPU 비용 때문에 무료는 1구. 1구는 구마다 거르기를 세게 한다(3-2).
4. **한 번에 하나를 고친다.** 주 문제 하나(+ 부 하나까지). 투구 사슬의 앞쪽 문제가 뒤쪽 문제를 만들기 때문에 앞쪽부터.
5. **처방은 다시 재서 확인한다.** 처방이 끝나면 3D 로 다시 재서 같은 지표를 견준다. "좋아졌어요" 단추가 아니라 숫자로.

## 2. 흐름

```
촬영 1구(무료) · 최대 3구(프로), 옆 · 뒤 두 대
 → 구마다 엔진(지금 그대로) → 구마다 지표(mech-checks)
 → 품질 거르기(구 · 지표마다: 영상 검사 · 확신 · 엔진 오류값)
 → 여러 구 합치기(평균 + 구 사이 흔들림)
 → 지표마다 판정(등급 A 지표만 경계 · 고칠 점 가능)
 → 진단: 주 문제 1 (+ 다음 1) · 잘하는 것 · 판정 못 한 것
 → 리포트 화면
 → 처방: 경계 이상 요소마다 처방 한 장 → 메커니즘 3주(9세션)
 → 끝나면 다시 3D → 같은 지표 전후 비교 → 다음 처방
```

## 3. 진단 신뢰 (가장 중요)

### 3-1. 지표 등급

지표마다 등급을 매기고, **A 만 '고칠 점'(=처방 대상)을 낼 수 있다.** B 는 '보통'까지만(참고 문구), C 는 화면에 안 낸다.

| 지표(요소) | 엔진 오차(마커) | 판정 일치 | 지금 등급 | 근거 · 할 일 |
| --- | --- | --- | --- | --- |
| 드리프트 — 니업 때 골반이 축발보다 앞(드리프트) | 0.7cm · 상관 0.95 | 9/13 (10-16) | **A** | 경계 구만 어긋남 |
| 앞무릎 펴짐 착지 → 릴리스(브레이크, 3-5절) | 3.8° · 상관 0.81(10-15 엔진) | 판정 없음 | **A 후보** | 지금 판정(골반 감속 + 무릎 더 굽음)을 이것으로 바꿈. 감속은 자세히에만. 4차 100% 투구로 재확인 |

| 니업 → 착지 골반 내려간 몫(드롭, 3-5절) | 다리 길이의 1% · 상관 0.99 ✅ | 판정 없음 | **A 후보** | 마운드 기준표뿐 — 평지는 '보통'까지. 보폭(키의 1.1%)은 숫자만 |
| 최대 분리 크기 · 시점 | 골반 오차 9.6~17.5° | 10/13 | **C** | 두 대로 골반 못 잼(4-3절) — 숨긴 채 둠 |
| 착지 골반 수평 | 4.5° | — | **C** | 그대로 숨김 |
| 착지 때 어깨 벌림 = 팔 늦음(스로잉, 3-5절) | 4.1° · 상관 0.76(K4 도 같은 2D) | 판정 없음 | **B** | 4차 마커(팔 스티커 · ④ 카메라)로 재확인되면 A 후보. 레이백 · 팔 가속 · 아래팔 들림은 C(안 씀) |

**A 가 되는 조건**(모두):
1. 마커 촬영 **3회 이상 · 투수 2명 이상 · 전력(100%) 투구 포함**으로 잰 오차.
2. 판정 일치 85% 이상이고 **잘못된 '고칠 점' 0**.
3. 엔진 오차 × 2 < 기준표의 '정상 폭'(아래 10% ~ 가운데). 아니면 B.

지금은 1번(투수 한 명 · 70~80%)이 모든 지표에서 모자라다 → **4차 촬영(100% · 가능하면 다른 투수)이 P0 의 재료**.

### 3-2. 리포트 한 번의 품질 관문

- 구마다: 올리기 전 영상 검사(있음, `pitch-lab-guard.ts`) · 지표 확신 30 밑 제외(있음) · 엔진 오류값 제외(있음, 블록).
- 여러 구: **구 사이 흔들림이 그 지표의 '같은 선수 흔들림 + 엔진 오차'의 2배를 넘으면** 그 지표는 '판정 안 함'(엔진이 어느 구에서 틀린 것).
- 구 수: 무료 1구 · 프로 최대 3구. **'고칠 점' 문턱은 잘못 짚는 확률을 구 수와 상관없이 같게 맞춘다**(김민 2026-10-21 — 처음엔 둘 다
  '엔진 오차 × 2', 프로 3배 안을 견준 뒤 이것으로. 3배면 같은 투수가 무료에서 '고칠 점' · 프로에서 '보통'이 되어 돈을 낸 쪽이 피드백을 덜 받는다).
  - 문턱 여유 = **2 × σ(n)**, σ(n) = √(치우침 흔들림² + (공마다 엔진 흔들림² + 같은 선수 흔들림²) ÷ n). n = 판정에 쓴 구 수.
  - 치우침 흔들림(투수 · 촬영마다 엔진이 한쪽으로 늘 틀리는 몫)은 구를 늘려도 안 줄어 **문턱의 바닥**이 된다. 공마다 흔들림과 나눠 재는 것은
    P0(마커 투수 2명 이상 · 3회 촬영)에서. 그 전에는 보수적으로 엔진 오차 전체를 치우침으로 둔다 — 그러면 3구 문턱도 1구와 거의 같아서
    (분리 σ(1) 3.7° · σ(3) 3.5°) **프로의 '더 꼼꼼함'은 P0 에서 치우침 몫을 잰 뒤에 생긴다**.
  - 분리를 예로(엔진 3.4° · 같은 선수 1.5°): 1구 σ = √(3.4² + 1.5²) = 3.7° → 여유 7.4°, 잘못 짚을 확률 약 2.3%(z 2).
    P0 에서 치우침 2° · 공마다 2.7° 로 나뉘면 σ(3) = √(2² + (2.7² + 1.5²)/3) = 2.7° → 여유 5.4°(1구보다 2° 기준에 가까이).
  - 3배를 쓰지 않는 까닭: 피드백을 줄이고, 구 수가 늘수록 이득이 사라진다. 고칠 점이 없어도 처방은 늘 나간다(6-2).
- 1구의 진짜 위험은 그 한 구에서 엔진이 크게 틀리는 것(구끼리 견줄 수 없다) → 1구 리포트는 지표 확신 문턱을 30 → 45 로 올리고, 엔진 오류값
  거르기(블록의 무릎 40° · 감속 115% 같은)를 지표마다 둔다. 걸린 지표는 '판정 안 함' + "다시 찍어 주세요".
- 같은 날 · 같은 사람 · 같은 카메라 자리만 한 리포트로 묶는다.

### 3-3. 기준표

- **라이선스**: OpenBiomechanics 는 CC BY-NC-SA 4.0(비상업). 우리가 퍼센트 문턱으로 다시 셈한 값도 상업 앱에 쓰면 걸릴 수 있다 → **정할 것 ①**.
- **수준**: 자료가 대학 위주(평균 84.7mph). 중 · 고교 · 사회인에게 대학 아래 10% 를 '고칠 점' 문턱으로 쓰면 많이 걸린다.
  우선은 타이밍 · 순서 지표(몸통이 도는 때 %, 착지 때 상체)처럼 구속과 상관이 작은 지표를 앞세우고, 크기 지표는 성장기에 '고칠 점'을 내지 않는다.
- 길게는 **우리 사용자 자료로 기준표**(리포트가 쌓이면 나이 · 수준 · 구속대별 분포). 이게 라이선스 · 수준 문제를 함께 푼다.

### 3-4. 치우침

지금은 보정하지 않고 문턱을 넓혀 다룬다(2026-10-13 결정). 투수 2명 이상 · 3회 이상 자료에서 치우침이 같은 방향 · 같은 크기면 그때 보정을 넣는다.

| 몸통 회전 — 릴리스 때 옆 기울기 | 팔 높이와 맞아야 함(T) · 48° 는 팔 부담과 관련(D 사례) | 18 / 22 / 28° · −0.05 · 팔 높이와 +0.65 | 2.5° · 0.99 | **판정 안 함**(팔 높이를 못 잼) — 숫자만 자세히에 |
| **스로잉** — 착지 때 어깨 벌림(팔꿈치가 어깨선까지 올라왔나) | 착지 때 팔꿈치가 어깨선(벌림 약 90°)(T PDF 원문 · D 2018) · '팔이 늦게 올라옴' 사례 77 → 86°(D) · Escamilla 오버 · 스리쿼터 89° · 사이드 84° | 72.0 / 78.6 / 85.8° · +0.03(구속과 무관 — 팔 부담 · 타이밍 지표) | 4.1° · 0.76(치우침 +4.5) | 고칠 점: 아래 10% − 2σ(≈63°) 밑. 보통: 아래 25%(79°) 밑. **4차 마커(팔 스티커)로 재확인 전엔 B** |
| 스로잉 — 착지 때 아래팔 들림(외회전) | 빠른 투수가 오히려 작음(미국 45° vs 한국 68°, T) · 채찍형 무리는 큼(D) — 서로 엇갈림 | −6 / 11 / 32° · −0.01 | 10.4° · 0.89(치우침 +10) | **안 씀**(좋고 나쁨이 갈리지 않고 엔진도 약함) |

주의:
- **마운드 vs 평지**(김민 2026-10-21 — 아래 안으로 정함): 자료는 실험실 마운드다. 던진 곳은 올릴 때 이미 고른다(`LabMeta.ground`).
  1. **평지도 그대로 판정 — 드리프트 · 상하체 분리 · 브레이크 · 스로잉.** 드리프트는 내딛기 전 순간, 분리는 도는 각도, 브레이크는 착지 무릎에서 얼마나
     폈나(경사로 착지 무릎이 달라도 차이를 봄), 어깨 벌림은 몸통 기준 각도라 경사 몫이 작다.
  2. **평지는 '참고'까지만 — 드롭 · 몸통 앞 기울기.** 내리막으로 떨어지는 마운드에서 둘 다 자연히 커지는데 그 몫을 아직 못 쟀다. '고칠 점' · 처방 대상으로
     안 내고 참고 문구만("앞으로 더 숙일 여지가 있어요"). 예외: 드롭의 '거의 안 가라앉음 · 뜸'은 평지도 고칠 점(다리를 벌리면 평지에서도 골반이 내려간다).
  3. **평지 기준 만드는 법 — 같은 투수 마운드 · 평지 짝 촬영**(2명 이상 · 각 5구 · 같은 날 야외 마운드). 두 곳 차이가 엔진 오차보다 작으면 같은 표,
     크면 차이만큼 표를 옮겨 평지 표. 평지 사용자 영상으로 분포를 만드는 길은 안 쓴다(아마추어가 많아 그 아래 10% 가 '나쁨'의 기준이 못 된다).
  4. 촬영 안내(5-1)에 한 줄: "마운드에서 찍으면 볼 수 있는 항목이 늘어나요." 평지도 그대로 받는다.
  - 마커 투수 평지 값(10-12, 드롭 0.19 · 앞 기울기 9.8°, 둘 다 자료 아래 10% 밑)은 3번 짝 촬영 전엔 판정 근거로 안 쓴다.
- 엔진 정확도는 우투 한 명 · 70~80% · 10-15 엔진. P0 에서 지금 엔진 · 4차(100%)로 다시 재고, 위 문턱(2σ)을 그 숫자로 바꾼다.
- 브레이크의 지금 판정(감속 70% 밑 + 무릎 15° 더 굽음)은 위 안으로 바꾼다(감속은 자료에서 구속과 거의 무관).

**상태 네 칸**(김민 2026-10-21 — 경계 이상부터 드릴 처방). 위 표의 '보통' 문턱은 아래 칸으로 읽는다. 나쁜 쪽이 큰 값인 지표(더 굽음)는 거꾸로.

| 상태 | 자리 | 처방 |
| --- | --- | --- |
| 좋아요 | 아래 25% 위 | 없음 |
| 보통 | 아래 10% ~ 25% | 없음 |
| **경계** | 아래 10% − 2σ ~ 아래 10% — 기준 밑인데 엔진 오차 안 | **보조 드릴** |
| **고칠 점** | 아래 10% − 2σ 밑 — 엔진 오차를 빼도 기준 밑 | **집중 드릴** |

- 드리프트는 지금 판정 그대로 쓴다: 지금 '고칠 점'(0.06 밑) = 고칠 점, 그 위 2σ(엔진 0.7cm ≈ 다리 길이 0.01, 0.06 ~ 0.07) = 경계.
- 참고(B 지표 · 평지 드롭 · 평지 앞 기울기 · 성장기 크기 지표)는 경계 · 고칠 점이 되지 않는다 — 처방 없음.
- σ 는 구 수로 줄어(3-2절) 프로는 경계 폭이 좁다 — 같은 값이 무료에선 경계, 프로에선 고칠 점이 될 수 있다(P0 뒤).

## 4. 진단 고르기 — 주 문제 하나

순수 함수 `lib/pitch-3d/v2/diagnosis.ts` — 입력: 구마다 `MechChecks` + 판정, 나이 · 손 · 키. 출력:

```ts
type Diagnosis = {
  pitches: number;                    // 판정에 쓴 구 수 — 문턱 여유 2 × σ(pitches)(3-2절)
  tier: 'free' | 'pro';               // 무료 1구 · 프로 최대 3구
  primary: Finding | null;            // 없으면 경계 이상 없음 → 드릴 처방 없음
  secondary: Finding | null;
  strengths: Finding[];               // 좋아요인 A 지표
  notJudged: { key: MechKey; why: string }[];
};
type Finding = {
  key: MechKey;                       // 지표
  element: MechanicsElementName;      // 드리프트 · 드롭 · 상하체 분리 · 브레이크 · 몸통 회전 · 스로잉
  fault: FaultKey;                    // 문제 종류 — 처방 표의 열쇠(6-1)
  level: 'improve' | 'edge';          // 고칠 점 · 경계(3-5절 상태 네 칸)
  severity: number;                   // 문턱에서 벗어난 정도 ÷ 엔진 오차
  value: number; norm: { p10: number; p50: number }; unit: string;
  frame: number | null;               // '그 순간 보기'
};
```

고르는 규칙:
1. 후보 = 등급 A 지표 중 경계 · 고칠 점. B 는 후보가 아니다(참고 문구만).
2. **사슬 차례**: 드리프트(1) → 드롭(2) → 상하체 분리(3) → 브레이크(4) → 몸통 회전(5) → 스로잉(6). 앞쪽 문제가 뒤쪽을 만든다
   (예: 몸통이 일찍 열리면 레이백이 줄고 밀어 던진다 — elements.ts [D5] [T6]). **고칠 점이 있으면 그중 가장 앞쪽, 없으면 경계 중 가장 앞쪽이 주 문제**, severity 는 같은 요소 안에서만 견준다.
3. 다음 문제 = 사슬 차례 그다음 후보(고칠 점 · 경계 섞어서), 주 문제와 같은 요소면 안 씀. 그 뒤 후보는 '다음 차례'(6-2절).
4. 성장기(만 16세 미만): 크기 지표는 후보에서 뺀다, 타이밍 · 순서 지표만.
5. 후보가 없으면 '지금 동작을 지켜요' + 잘하는 것, 드릴 처방 없음(6-2절).
6. 평지(3-5절): 드롭 · 몸통 앞 기울기는 후보에서 뺀다(드롭의 '안 가라앉음 · 뜸'만 남김).

## 5. 리포트 화면 (웹 PC · 앱)

무료(1구) 틀부터 만든다(김민 2026-10-21). 촬영 안내는 5-1, 틀은 5-2 ~ 5-8. 프로는 같은 틀에 구 수 · 구 사이 검사만 더한다(P6).

### 5-1. 리포트 촬영 안내 (문안, 2026-10-21)

지금 촬영 안내(`lib/pitch-lab-guide.ts` · 웹 `/videos/lab/guide` · 앱 `lab/guide`)는 **한 구 분석용**이다. 자리 · 화면 담기 · 폰 설정 ·
옮기기 · 실패 까닭은 그대로 쓰고, 리포트에 필요한 규칙만 더한다. 화면에 넣는 때는 P1(리포트 묶기)과 같이 — 리포트가 없는데
'찍으면 리포트'라고 쓰면 거짓이 된다.

**머리**: 투구 진단 리포트 — 한 구를 찍어 올리면, 지금 가장 먼저 고칠 점과 드릴 처방을 드려요(프로는 최대 3구로 더 꼼꼼하게).
마운드에서 찍으면 볼 수 있는 항목이 늘어나요(평지도 돼요 — 3-5절).

**준비**
- 폰 2대 · 삼각대 2개 · 녹화를 켜고 끌 사람 1명(영상 하나가 길면 올리기 한도를 넘어요 — 240fps 6초 ≈ 20MB).
- 불펜 피칭 전처럼 몸을 다 풀어요.
- 밝은 곳(밝을수록 손이 덜 번져요). 상의는 바지 안에 넣거나 몸에 붙는 옷으로, 엉덩이 · 어깨가 보이게.

**찍는 법** — 자리 · 화면 담기 · 폰 설정은 지금 안내 그대로, 여기에 다섯 가지를 더해요.
1. **직구만, 실전처럼 세게.** 구종이 섞이면 동작이 달라 평균이 흐려지고, 가볍게 던지면 실제 문제가 안 드러나요. 기준 자료도 전력 투구예요.
2. **2~3구 찍고, 화면에 가장 잘 담긴 한 구를 올려요(프로는 최대 3구).** 공마다 두 폰을 던지기 2초 전에 같이 켜고, 팔로스루 1초 뒤에
   같이 멈춰요. 영상 짝 하나가 공 하나예요. 찍는 건 공짜라 넉넉히 찍고 고르면 다시 찍을 일이 줄어요.
3. **(프로 2~3구) 폰은 처음 자리 그대로.** 공 사이에 삼각대를 건드리지 않아요. 움직였으면 그 뒤 공은 다음 리포트로.
4. **한 번에, 같은 곳에서.** 같은 날 30분 안에. 마운드와 평지를 섞지 않아요. 공 사이 쉬는 건 평소처럼.
5. **공마다 바로 확인.** 두 폰 다 찍혔는지, 발끝 · 머리 · 손이 화면 안인지. 잘못 찍힌 공은 빼고 한 구 더 던져 채워요.

**올리기**: 옆 · 뒤 짝으로 올리면(지금과 같음) 분석 뒤 리포트가 나와요. 공 하나에 1~2분. 프로는 같은 날 공을 최대 3개까지 한 리포트로 묶어요.

근거: 1번 — 기준표(OpenBiomechanics)가 전력 투구, 구종마다 동작 차이. 2 · 3번 — 엔진 한 구 오차 > 같은 선수 흔들림(0절 3번), 카메라 자리는
공마다 다시 맞추지만(자기 보정) 같은 자리가 구 사이 흔들림을 줄인다. 4번 — 평지 · 마운드는 무대 · 각도 기준이 다르다. 5번 — 영상 탓 실패(LAB_FAIL_FIX)
는 분석 뒤에야 알아 다시 찍기 어렵다. 옷 · 밝기는 엔진이 막는 조건이 아니라 오차를 줄이는 권장(엉덩이 2D 오차가 골반 판정의 주범 — 4-3절).

### 5-2. 언제 생기나 — 분석마다 하나

- 3D 분석이 끝나면(job done) 그 샘플로 리포트를 바로 만든다. 따로 누르는 단추 없음. 진단은 결과 JSON 에서 셈하는 순수 함수라 GPU 를 더 안 쓴다.
- **무료 한도 = 분석 월 2회(= 리포트 2개, 가정 — 11절)**. 비용이 분석에서 나므로 리포트가 아니라 분석을 센다. `requestPitch3dV2` 가 세고, 넘으면 GPU 를
  안 부르고 "이번 달 무료 분석을 다 썼어요. 11월 1일에 다시 돼요." **바뀌는 점**: 지금 3D 분석은 일반 사용자에게 한도 없이(하루 실패 10번만) 열려 있다.
- 세지 않는 것: 영상 탓 · 서버 탓 실패(리포트가 안 나옴), 엔진이 바뀌어 같은 샘플을 다시 분석, 관리자 계정.

### 5-3. 저장 모양 — `lib/pitch-3d/v2/report.ts`

```ts
type PitchReport = {
  v: 1;
  id: string;
  tier: 'free' | 'pro';
  samples: string[];                  // 무료 1개 · 프로 최대 3개
  jobIds: string[];                   // 그 분석 결과(analysis-v2-{jobId}.json)
  engine: string;                     // 엔진 지문 — 지금 엔진과 다르면 '예전 엔진' 띠
  criteria: string;                   // 기준 판(3-5절 표 · 문턱) — 바뀌면 '기준이 바뀌었어요' 띠 + 다시 셈 단추
  createdAt: string; shotOn: string;  // 만든 날 · 찍은 날(영상 머리)
  ground: 'mound' | 'flat'; hand: 'R' | 'L'; youth: boolean;
  items: ReportItem[];                // 여섯 요소, 사슬 차례(4절)
  diagnosis: Diagnosis;               // 4절
  rx: ElementRx[];                    // 경계 이상 요소마다 처방 한 장(6-1절), 사슬 차례 · 많아야 2장
  later: MechanicsElementName[];      // 경계 이상인데 이번 처방에 못 넣은 요소 — '다음 차례'
};
type ReportItem = {
  element: MechanicsElementName;
  status: 'improve' | 'edge' | 'fair' | 'good' | 'note' | 'unsure';  // 고칠 점 · 경계 · 보통 · 좋아요 · 참고 · 판정 안 함
  fault: FaultKey | null;             // 경계 · 고칠 점일 때 문제 종류(6-1절)
  why?: 'gradeB' | 'flat' | 'youth' | 'lowConf' | 'implausible' | 'notMeasured';  // 참고 · 판정 안 함 까닭
  metric: { key: string; value: number; unit: string; norm: { p10: number; p25: number; p50: number }; cut: number } | null;
  frame: number | null;               // '그 순간' 장면
};
```

- 스토리지 `{user}/pitch-lab/_reports/{id}.json`(7절). **스냅숏이다** — 기준이 바뀌어도 옛 리포트는 그대로 두고 띠만(사용자가 본 진단이 몰래 바뀌지 않게).
- 상태는 3-5절 '상태 네 칸'. A 지표만 경계 · 고칠 점이 될 수 있다. 품질 관문(3-2)에 걸리면 '판정 안 함'.

### 5-4. 화면 — 다섯 칸(앱 먼저, 웹 PC 는 두 칸)

| 차례 | 칸 | 내용 |
| --- | --- | --- |
| ① | 머리 | '투구 진단 리포트' · 날짜 · 칩 [마운드 · 1구 · 오른손]. 예전 엔진 · 기준 바뀜이면 띠 하나 |
| ② | 결론 | 한 문장 + 요소 칩 + [처방 시작]. 고칠 점 → "착지한 뒤 앞무릎이 더 굽어요. 여기부터 고쳐요." · 경계만 → "동작이 좋아요. 브레이크를 다듬으면 더 좋아져요." · 경계 이상 없음 → "지금 동작을 지켜요." · 판정 못 함 → "이 영상으로는 판정이 어려워요" + 다시 찍기 |
| ③ | 그 순간 | 3D 인형(주 문제 장면에 멈춤) + 원본 옆 · 뒤 같은 장면 · 기준 띠(아래 10% · 가운데 · 내 값 점 · 문턱 선). 작은 글 "이 한 구 기준이에요" |
| ④ | 여섯 요소 | 흐름 차례 목록. 줄 = 요소 이름 · 상태 칩. 누르면 펼침: 값과 단위 · 기준 띠 · 뜻 한 줄(elements.ts `why`) · [그 순간 보기]. 참고 · 판정 안 함은 까닭 한 줄 |
| ⑤ | 처방 | 경계 이상 요소마다 한 장(6-1절 '처방 한 장'): 요소 · 문제 한 줄 · 느낌 신호 · 주차별 드릴(기초 → 연결 → 통합) · 세기 · 횟수 · 다음에 볼 목표. 맨 위에 "3주 · 주 3번 · 9세션", 밑에 [처방 시작]. 다음 차례 요소가 있으면 한 줄. 경계 이상이 없으면 칸 없음 |

- 다시 재기 안내 · 프로 안내 · 바닥 글 칸은 두지 않는다(김민 2026-10-21). 다시 재기는 처방을 마칠 때 메커니즘 화면이 알린다(6-3절).
- 웹 PC: 왼쪽 ③(sticky, 지금 `lab-detail.tsx` 와 같은 60%) · 오른쪽 ② ④ ⑤. 휴대폰 웹은 막혀 있으니(proxy) 앱이 주인.
- 칩 색은 지금 메커니즘 점검 카드(`mech-card.tsx`) 그대로, 경계는 고칠 점 색의 테두리만. 참고는 회색 테두리, 판정 안 함은 점선.
- 숫자는 ④ 펼침 · ③ 기준 띠 · ⑤ 목표에만. ② 결론에는 숫자를 안 쓴다(몸이 무엇을 하는지로).

**모양(김민 2026-10-21 '좀 더 고급스럽게')** — 앱 디자인 규칙(sky 하나 · 해요체 · 카드 테두리 없음) 위에서:
- 머리는 큰 제목 '투구 진단' + 한 줄(날짜 · 던진 곳 · 손 · '이 한 구 기준'). 칩 줄 대신 글 한 줄.
- **② 결론과 ③ 그 순간을 한 장으로**: 3D 무대색(`#151722`) 카드 위에 인형(주 문제 장면에 멈춤 · 문제 관절만 주황, 각도 호 · 값 하나), 그 밑 니업 · 착지 · 릴리스
  시간 띠(그 순간 점), 문제 꼬리표 · 결론 두 줄(큰 글) · 왜 중요한지 한 줄. 원본 영상 두 칸은 이 카드를 누르면 펼친다.
- **④ 여섯 요소는 목록 대신 '투구의 흐름' 사슬**: 가로 선 위 점 여섯(좋아요 초록 · 보통 회색 · 경계 주황 테두리 · 고칠 점 주황 · 참고 점선). 점을 누르면 밑에서
  그 요소의 한 줄 · 큰 숫자 · 기준 띠(고칠 점 · 경계 · 보통 · 좋아요 네 칸 + 내 값 점 + '문턱' 표시)가 바뀐다. 처음엔 주 문제가 골라져 있다.
- **⑤ 처방**: 위에 1주 기초 · 2주 연결 · 3주 통합 세 칸(이번 주 칸만 sky). 요소마다 이름 + 집중 · 보조 꼬리표, 느낌 신호는 왼쪽 선을 단 인용 한 줄,
  드릴은 썸네일 줄, 목표는 '19° → 8° 밑' 한 줄(지금 값은 회색 · 목표는 초록). 맨 밑 알약 [처방 시작] + "메커니즘 프로그램의 드릴 칸이 이 처방으로 바뀌어요".
- 숫자는 고정폭(`text-numeric`), 색은 sky(누름) · 주황(문제) · 초록(목표 · 좋아요) 셋만. 그림자 · 그라데이션 없음.

### 5-6. 들어가는 길

- 무료는 리포트 하나 = 샘플(구) 하나라 **주소를 새로 만들지 않는다** — 지금 결과 화면(웹 `/videos/lab/[id]` · 앱 `lab/[id]`)을 리포트 화면으로 바꾼다(5-9절).
  리포트 번호 = 샘플 번호. 프로(P6)에서 여러 구를 묶을 때 그때 `report/[id]` 를 더한다(앱 길 등록 NATIVE_ROUTES 는 1번 세션 몫 — 보고로).
- 3D 동작 분석 첫 화면의 목록이 '내 리포트'(5-9절), 메커니즘 화면의 처방 카드에 [리포트 보기](6-4절).

### 5-7. 글 규칙

- 해요체 · 줄표 없음 · 코칭 기관 이름 없음. 문제는 '몸이 무엇을 하는지'로, 결론 글은 문제(fault)마다 하나(`FAULT_TEXT`).
- 1구라는 말은 "이 한 구 기준" 하나. '정확도 낮음' · '덜 정확' 같은 말은 안 쓴다(10절 — 무료는 한 구로 볼 수 있는 만큼).
- 기준 자료를 '프로 기준'이라 부르지 않는다(대학 위주). "잘 던지는 투수 자료".

### 5-8. 무료 틀에서 안 하는 것

- 여러 구 평균 · 구 사이 흔들림 검사(3-2절) — 프로(P6).
- 전후 비교 그래프 — P3.
- 리포트 공유 · 코치에게 보내기 — 팀 · 레슨장과 같이 나중에.

## 6. 메커니즘 연동 (두 번째로 중요)

### 6-1. 요소 → 문제 → 처방 한 장

요소(6개)는 너무 넓다 — 같은 브레이크라도 '착지 뒤 무너짐'과 '안 펴짐'은 드릴이 다르다. 그래서 **문제(fault)** 를 한 층 더 두고, 문제마다 처방 한 장의
틀을 정한다. 문제는 지표의 모양으로 가른다(엔진이 재는 것만).

| 요소 | 문제(fault) | 가르는 조건 | 느낌 신호(elements.ts `cues`) | 드릴 방향 · 후보(김민이 고름) | 다음에 볼 목표 |
| --- | --- | --- | --- | --- | --- |
| 드리프트 | `drift.stuck` 다리를 들 때 몸이 투구판 위에 머묾 | 드리프트 경계 이상 | "다리를 가장 높이 든 자리는 투구판보다 한 뼘 앞." | 다리 들며 앞으로 가는 이동 — 워킹 와인드업 · 스텝 비하인드 스로우 · 드롭 스텝 스로우 | 드리프트 0.086 위 |
| 드롭 | `drop.float` 니업 뒤 안 가라앉음 · 뜸 | 골반 내려간 몫 5% 밑 또는 뜸 | "뒷엉덩이와 뒤꿈치에 앉으며 간다." | 뒷다리 힌지 — 레터럴 힌지 바운드 · 스위치 풋 드롭 힌지 스로우 · 다르빗슈 드릴 | 골반 내려간 몫 아래 25%(0.31) 위 |
| 드롭 | `drop.shallow` 덜 가라앉음(마운드) | 그 밖 경계 이상 | "투구판을 2루 쪽으로 끌어당긴다." | 같은 묶음, 기초 건너뜀 | 같음 |
| 상하체 분리 | `sep.openAtPlant` 앞발이 닿을 때 상체가 이미 열림 | 착지 때 상체 경계 이상 | "앞어깨를 닫은 채 앞발을 딛는다." | 착지 자세 — 스플릿 스탠스 스로우 · 반대다리 스플릿 스탠스 스로우 · 글러브 팔 밴드 스로우 | 착지 때 상체 기준 안 |
| 브레이크 | `block.collapse` 착지 뒤 앞무릎이 무너짐 | 더 굽음 위 10%(11.9°) + 2σ 넘음 | "앞다리는 벽, 밀려나지 않는다." | 버티는 근력 먼저 — 지지 홀드 TKE · 스플릿 스탠스 무릎 아이소메트릭 프레스 → 앞다리 위 회전 → 스플릿 스탠스 스로우 + 모멘텀 | 더 굽음 위 25%(7.8°) 밑 |
| 브레이크 | `block.soft` 무너지진 않는데 안 펴짐 | 그 밖 펴짐 경계 이상 | "골반이 돌며 앞무릎이 펴진다." | 펴며 도는 쪽 — 핸드홀드 고관절 내회전 · 턴 앤 번 스로우 | 무릎 펴짐 아래 25%(2°) 위 |
| 몸통 회전 | `trunk.upright` 공을 놓을 때 몸통이 서 있음 | 릴리스 앞 기울기 경계 이상(마운드) | "뒷어깨를 목표 쪽으로 돌려 보낸다." | 앞다리 위에서 찹 · 슬램 — 힌지 오버더톱 슬램 · 피벗 픽오프 · 턴 앤 번 스로우 | 앞 기울기 아래 25%(22°) 위 |
| 스로잉 | `arm.late` 앞발이 닿을 때 팔이 덜 올라옴 | 착지 어깨 벌림 경계 이상(4차 뒤 A) | "팔이 어깨 높이에 올라온 뒤에 몸통이 돈다." | 팔 길 — 라소 드릴 · 텐 토즈 스로우, 차례는 느린 동작 → 50~60% → 60~75%, 2×8 [T7] | 어깨 벌림 아래 25%(79°) 위 |

- 드릴 이름은 지금 라이브러리(`docs/mechanics/drill-review-2026-10-16.md` 분류) 에서 뽑은 **후보**다. 문제 → 드릴 표의 확정은 김민(메커니즘 세션)이
  `lib/mechanics/prescriptions.ts` 에 한다(묶음 이름 `familyTitle`, 단계 기초 · 연결 · 통합). 고르지 않은 문제는 그 요소의 쉬운 드릴로 떨어진다.
- 목표 숫자는 3-5절 기준표의 아래 25%(좋아요 문턱). 기준표가 바뀌면 같이 바뀐다.

**처방 한 장의 모양**(3D 세션이 리포트에 담고, 메커니즘 세션이 읽는다):

```ts
type ElementRx = {
  element: MechanicsElementName;
  fault: FaultKey;
  level: 'improve' | 'edge';          // 고칠 점 = 집중 · 경계 = 보조
  slots: 1 | 2;                       // 세션마다 드릴 칸 수
  weeks: { week: 1 | 2 | 3; stage: '기초' | '연결' | '통합'; drills: string[] }[];  // familyTitle

  cue: string;                        // 느낌 신호 한 줄
  target: { key: string; now: number; goal: number; unit: string };  // 다음 재기에서 볼 것
};
```

## 10. 요금제 (2026-10-21 김민 결정)

| | 무료 | 프로 |
| --- | --- | --- |
| 리포트 한 번의 구 수 | 1구 | 최대 3구 |
| '고칠 점' 문턱 | 2 × σ(1) — 잘못 짚을 확률 약 2% | 2 × σ(구 수) — 같은 확률로 기준에 더 가까이(경계 문제까지) |
| 월 횟수(가정 — 정할 것) | 2회 | 8회 |
| 경계 | 넓다 — 경계도 보조 드릴을 받는다 | 좁다(σ 가 구 수로 줄어) — 같은 값이 고칠 점으로 또렷해진다(P0 뒤) |

- 무료도 틀린 진단은 없게 한다 — 무료 = '덜 정확'이 아니라 '한 구로 볼 수 있는 만큼'. 화면 말도 "프로는 더 꼼꼼한 진단".

- 비용은 분석한 구 수에 비례 → 월 횟수 제한이 꼭 있어야 한다. 프로 한 명 최대 GPU 월 약 1,300~2,400원(8회 × 3구 × 55~100원)을 요금에 넣는다.
- 구 수 · 횟수 확인은 서버(`requestPitch3dV2`, 하루 실패 10번 막기와 같은 자리)에서. 화면은 보여 주기만.
- 앱 안에서 프로를 팔면 애플 인앱결제(수수료 15~30%). 결제 화면은 덕아웃 결제(금윤호, 지금 껍데기)와 맞추고, 요금제 확인 함수 하나를 같이 쓴다.
- 팀 · 레슨장(코치가 선수 여럿)은 나중에 따로.
