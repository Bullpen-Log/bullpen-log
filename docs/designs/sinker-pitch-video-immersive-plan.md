# 싱커 투구 영상 비교 몰입 화면 설계

작성 2026-11-03. 최신 사용자 요구: 위쪽 공백 제거, 영상을 상단과 각 칸 끝까지 사용, 주변 인터페이스를 검게, 한 영상을 반투명하게 겹침, 아래쪽 도구와 도구 숨김. 이번 산출물은 구체적인 계획과 [영어 실행 명세](./sinker-pitch-video-immersive-claude-prompt.md)다.

## 핵심 결정

영상 무대는 화면 상단에서 시작하고, 일반 상태의 조작부만 아래에 둔다. 위쪽 제목은 별도 높이를 차지하는 줄 대신 영상 위의 작은 오버레이로 옮긴다. 영상 칸의 바깥 패딩·카드 테두리·둥근 모서리를 걷고 검은 무대 안에서 끝까지 쓴다.

화면을 빈틈없이 채우는 **채움**과 머리·발·공의 원본 전체를 보는 **전체**를 명시적으로 구분한다. 비율이 다른 영상을 왜곡 없이 빈틈없이 넣으려면 일부 가장자리가 잘릴 수 있다. 기본은 사용자가 요청한 채움이며, '채움 · 일부 잘림' 상태와 한 번 누르는 전체 보기를 제공한다. 새 설정이 없는 이전 문서도 표시 기본값은 채움으로 읽되 기존 확대·이동·기준은 초기화하지 않는다. 사용자가 명시적으로 저장한 전체 보기 선택은 복원한다. 원본 파일과 원본 좌표는 바꾸지 않는다.

새 비교의 기준 맞추기는 분할 화면에서 한다. 기준 지정 후 첫 재생 화면은 A 위에 B를 진하기45%로 겹쳐 보여준다. 사용자가 분할로 바꾸면 그 선택을 존중한다. 기존 비교 문서는 저장된 보기·진하기를 복원하고 임의로 초기화하지 않는다.

## 현재 공백이 생기는 이유

검토 소스: `compare/workspace-layout.ts`, `ui/workbench.tsx`, `ui/pane.tsx`, `compare/geometry.ts`. 실제 아이폰 스크린샷을 새로 측정한 결과가 아니다.

1. `one`·`stack`·`side` 모두 남는 높이를 위에 두고 영상을 무대 아래에 붙인다. 예전의 '영상과 타임라인을 붙인다'는 목표가 상단 공백을 만드는 구조다.
2. 칸 자체를 원본 비율의 contain 사각형으로 계산하므로, 특히 세로 영상 두 개를 나란히 놓으면 전체 무대 높이를 다 쓰지 못한다.
3. 화면 뿌리는 일반 테마의 `c.page`다. 영상 주변과 조작부가 라이트 테마에서는 밝아져 영상 몰입이 약해진다.
4. Pane에는 둥근 모서리10과 테두리2가 있고, 무대 기본 거터4·간격4가 있다.
5. 겹쳐 보기에는 B 농도0.3/0.5/0.7과 공간 맞춤이 이미 있지만 설정 안쪽에 있다. OverlayBox는 두 영상을 다시 그리며 일반 Pane의 확대·이동과 동일한 변환 경로를 사용하지 않는다.
6. 한 영상 크게 보기 모달은 있지만 두 영상의 비교 모드·겹침·같은 재생 상태를 그대로 쓰는 도구 숨김은 별도로 설계해야 한다.

현재 순수 배치 함수에 무대390×571pt, 세로9:16 영상 두 개를 넣은 계산 예:

| 모드 | 영상 사각형 | 무대 위쪽 빈 높이 |
| --- | --- | --- |
| 자동 분할 | 각189×336pt, y235 | 235pt |
| 겹침 | A321.2×571pt, x34.4 | 0pt, 대신 좌우 여백 |

이는 해당 입력의 계산값이다. 사용자 기기의 실제 높이나 화면 좌표라고 보고하지 않는다. 상단 정렬만 바꾸면 공백이 아래로 이동하므로, 채움 방식·도구 배치·겹침·몰입 상태를 같이 바꿔야 한다.

## 화면 구성

### 일반 비교

```text
┌─────────────────────────────┐
│ ‹            겹침/분할    ⛶ │ 작은 오버레이, 안전영역 안
│                             │
│      A + 반투명 B            │ 영상 무대, 상단부터 끝까지
│      또는 A │ B / A 위 B     │ 카드 패딩·둥근 프레임 없음
│                             │
├─────────────────────────────┤
│ ─────────●───────────────── │ 타임라인, 터치영역44pt
│ 함께/A/B  ‹  ▶  ›  속도     │ 검은 바탕의 공통 재생 줄
│ 맞추기  그림  장면  메모  ⋯ │ 작고 일정한 도구 줄
└─────────────────────────────┘
```

- 화면·안전영역 바탕은 #000, 도구 배경은 #0B0B0D~#151518 범위, 기본 글자는 #F5F5F7, 보조 글자는 충분한 대비의 회색으로 시작한다.
- 기존 싱커 강조색과 아이콘을 유지한다. 덕아웃 또는 앱 전체 테마를 바꾸지 않는다. 도구 팝업·선택창·메모 편집도 비교 화면의 검은 팔레트를 공유한다.
- 상태 막대 아이콘은 이 화면에 맞는 밝은 색을 사용하고 다른 화면으로 나갈 때 원래 설정을 복원한다. 앱 전체 설정 파일로 강제하지 않는다.
- 영상 바탕은 화면 끝까지 그릴 수 있지만 뒤로·보기 전환·복원 등 터치 조작은 노치·Dynamic Island·홈 인디케이터의 안전영역 안에 둔다. 안전영역 패딩을 영상과 조작에 중복으로 주지 않는다.
- 도구는 기본적으로 아래다. 짧은 가로·큰 글씨에서는 도구 수를 페이지로 줄이고, 그래도 공간이 부족할 때만 작은 옆 도구 구성 또는 명시적 편집 상태를 쓴다. 영상이 사라질 만큼 큰 도구 열을 상시 유지하지 않는다.

### 도구 숨김

```text
┌─────────────────────────────┐
│                     도구 ↙  │ 44pt 이상 복원 버튼
│                             │
│                             │
│        영상 A + B            │ 위·아래 조작의 예약 공간 해제
│        또는 분할 비교        │ 전체 창을 쓰는 검은 영상 무대
│                             │
│                             │
└─────────────────────────────┘
```

- 별도 영상 모달이나 새 디코더를 만들지 않고 같은 두 플레이어·기준·재생 위치·속도·반전·그림·겹침 농도를 유지한다.
- 머리·타임라인·재생·도구를 숨기고 그 높이와 옆 도구 폭 예약도 해제한다. 단순 opacity:0으로 빈 자리를 남기지 않는다.
- `도구 숨기기` 한 번으로 진입하고, 항상 남는 작은 `도구 보이기` 버튼 한 번으로 복귀한다. 화면 탭도 복원할 수 있지만 그리기·핀치·영상 이동·타임라인 드래그의 끝 동작이 탭으로 오인되지 않아야 한다.
- 첫 버전은 명시적인 숨김을 기본으로 한다. 재생을 시작했다고 바로 도구를 자동으로 없애지 않는다. 추후 자동 숨김을 넣더라도 VoiceOver·그리기·키보드·팝업·드래그 중에는 작동하지 않는다.
- 뒤로 동작은 먼저 몰입 상태를 끝내고 원래 비교로 돌아간다. 그 다음 뒤로가기가 기존 탐색 계약을 따른다. 복귀가 재생 시작·멈춤 명령을 임의로 보내면 안 된다.
- 도구 표시 전환은 약180–220ms의 짧은 전환을 시작값으로 하되, 모션 줄이기에서는 즉시 또는 단순 페이드로 한다. 영상이 찌그러지거나 재시작되지 않아야 한다.

## 영상 채움과 상단 정렬

### 별도로 계산할 네 가지

1. 화면 전체 경계.
2. 도구가 실제 차지하는 경계.
3. A/B 칸 경계.
4. 각 칸 안의 원본 영상 표시·잘림 사각형.

분할에서는 두 칸이 무대의 사용 가능 영역을 빈 구멍 없이 나눠 쓴다. 바깥 거터0, 칸 사이 구분선0~1pt를 시작값으로 한다. 영상을 찌그러뜨려 맞추지 않는다. 각 칸은 같은 높이/폭의 실제 분할 셀이고 영상은 그 안에서 비율을 보존한 채 채워진다.

채움에서는 cover 변환을 계산하고 손가락으로 구도를 옮길 수 있게 한다. '전체'에서는 contain으로 바꾸고 표시 묶음을 상단에 정렬한다. 남는 검은 영역은 원본 비율에 필요한 부분으로 한정한다. 원본에 이미 들어 있는 검은 띠를 자동으로 없앤다고 약속하지 않는다.

자동 배치는 실제 영상 크기뿐 아니라 잘림 정도와 작은 쪽의 가독성도 고려한다. 사용자가 고른 분할 방향은 보존한다. 다른 비율의 원본에 같은 자르기 비율을 강요하지 않는다. 반전·회전·확대·이동·공간 맞춤과 주석의 화면↔원본 좌표 변환이 같은 경로를 써야 한다.

**투구 분석의 중요한 보호:** 채움에서 손·공·발이 잘릴 수 있음을 작은 상태로 표시한다. `전체`와 `구도 초기화`를 한 번의 메뉴 진입 안에 둔다. 잘린 원본을 삭제하거나, 화면상 겹쳐 보이는 정렬을 실제 몸통 각도·3D 일치로 해석하지 않는다. 측정은 원본 좌표·보정값으로 계산한다.

## 반투명 겹쳐 보기

- '흐리게'는 기본적으로 선명도를 낮추는 블러가 아니라 **B 영상의 진하기를 낮춰 A와 함께 보는 것**으로 구현한다. 공·손·관절 윤곽은 선명하게 남긴다.
- 기본 A100%, B45%. `B 진하기45%`처럼 무엇을 조절하는지 명확히 표시한다. 0%는 A만, 100%는 B만이라는 끝점 의미를 유지한다.
- 겹침 모드에서는 타임라인 가까이에 진하기 조절을 쉽게 열 수 있게 한다. 25/50/75% 빠른 값, 5% 미세 조절, 터치영역44pt 이상의 슬라이더를 제공한다. 좁은 화면에는 조절기만 한 페이지로 보인다.
- `겹침 ↔ 분할`은 한 번의 조작으로 전환한다. `위 영상 A/B 바꾸기`는 기존 소스 A/B 교환과 다른 표시 동작이다. 사건·기준·메모를 바꾸지 않는다.
- B의 이동·크기 조절은 시간 맞춤과 별개다. 크기·위치를 바꿔도 원래 기준 시각은 변하지 않는다. 초기화는 공간 맞춤만 지운다.
- 반반 비교는 선택 가능한 부가 보기로 남긴다. 켜져 있을 때 진하기 조절이 무시되는 구조라면 상태와 조절기를 명확히 구분한다.
- 두 영상이 모두 동일한 무대를 사용하고, 서로 다른 원본 비율·반전·확대에도 매핑이 일치해야 한다. 투명한 B 바깥에 불필요한 검은 판을 깔아 A를 덮지 않는다.
- 플레이어를 새로 만들거나 같은 플레이어를 여러 VideoView에 무분별하게 붙여 구현하지 않는다. 기기의 실제 합성 지원은 별도 검증 대상이다.

## 기존 교정과의 우선순위

클로드에서 진행 중인 [SS01–SS07 교정](./sinker-pitch-video-single-screen-remediation-claude-prompt.md)을 유지한다. 새 명세는 상단 정렬·검은 주변·기본 채움·겹침 접근·도구 숨김에 대해서만 기존 표현 규칙을 대체한다.

- SS01·SS02의 도구 경계·도달 가능성은 계속 필수다. 검은 배경으로 잘림을 가리면 안 된다.
- SS03·SS04의 키보드·한글·붙여넣기·초안 보호를 유지한다. 편집 중에는 몰입 버튼을 비활성화하거나 초안을 보존해 편집을 명시적으로 닫고 전환한다.
- SS05·SS06의 재생 중단·A/B 대상 일관성은 몰입·겹침에서도 동일하다.
- SS07의 큰 글씨·VoiceOver·44pt 조작을 유지한다. 작은 아이콘처럼 보여도 실제 복원 타깃을 줄이지 않는다.
- 예전의 '무조건 contain'·'영상은 아래 정렬'·'bottomGap이 항상0'에 해당하는 시험은 최신 표시 모드별 계약으로 바꾼다. 단순히 시험을 삭제하지 말고 새로운 경계·원본 보존·빈 공간 조건으로 대체한다.
