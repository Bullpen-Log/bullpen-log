# 투구 영상 분석 — 스크롤 없는 한 화면 설계

작성: 2026-11-02. 사용자 최신 지시를 반영한 UI 개정안이다. **계획·프롬프트 작성이며 구현/기기 검증 완료 보고가 아니다.**

영어 실행 명세: [sinker-pitch-video-single-screen-claude-prompt.md](./sinker-pitch-video-single-screen-claude-prompt.md).

## 1. 이번에 바꿀 기준

**영상이 주인공이고, 영상을 보며 바로 시간을 움직이고 도구를 써야 한다.** 분석 화면을 문서처럼 위아래로 읽는 구조를 폐기한다. 영상을 찾으러 위로, 조작하러 아래로 이동하는 동작은 허용하지 않는다.

- 앱이 소유하는 이 기능의 화면·도구·목록에서 세로/가로 자유 스크롤과 바운스를 없앤다.
- 보기·맞추기·그리기·장면 분석 중에는 영상·타임라인·재생 조작이 같은 화면에 항상 보인다. 키보드가 공간 대부분을 차지하는 편집 모드만 재생 조작을 저장·취소로 잠시 바꾸고, 완료 시 같은 위치로 복원한다.
- 기능을 없애서 맞추는 것이 아니라 **모드 전환·작은 팝오버·버튼식 페이지**로 한 번에 보이는 내용만 바꾼다.
- 타임라인 드래그, 영상 확대·확대된 영상 내부 이동, 도형 편집은 필요한 조작으로 유지한다. 화면 전체의 스크롤과 구분한다.
- iOS 사진/파일 선택기·카메라·공유 시트·권한 창은 OS 화면이다. 내부 스크롤을 앱이 막는다고 약속하지 않는다. 앱 자체 영상 선택 목록은 페이지 방식으로 만든다.
- 새 UI는 기존 버그 교정 명세 F01–F08과 원래 R01–R42를 유지한다. 이전 명세의 '작은 화면은 문서를 스크롤하게 한다'는 내용은 이 기능에 한해 최신 지시로 대체한다.

## 2. 현재 소스에서 확인한 문제

검토 기준 `760d9859`의 `native/src/compare/ui/workbench.tsx`, `pane.tsx`, `panels.tsx`를 읽었다. 다른 세션이 수정할 수 있으므로 구현 직전 다시 확인해야 한다.

1. Workbench의 부모가 ScrollView이고 영상·재생 패널·도구를 세로로 쌓는다.
2. Pane마다 제목 줄(최소44)·보조 설명·기준 줄·영상 바깥 여백이 반복된다.
3. 영상 높이는 실제 남은 공간이 아닌 `winH * 0.31` 등으로 제한된다.
4. `boxAspect`를 양쪽에 공통 적용한다. 원본 비율이 다른 경우 불필요한 레터박스가 늘 수 있다.
5. 재생 패널이 별도 카드(패딩16, 여러 줄·칩)이고 영상 아래에 배치된다.
6. 도구 안에도 가로 ScrollView, 긴 사건/메모 목록, 스크롤 시트가 있다.
7. 그리기를 켜면 부모 스크롤을 막지만 현재 위치에 그대로 고정한다. 한 화면 설계가 아니라 긴 화면의 일부만 잠그는 방식이다.

이는 소스 구조 확인이다. 실제 아이폰 화면 좌표·터치·가독성을 측정한 결과라고 표현하지 않는다.

## 3. 고정 화면 구조

세로 기본 구성:

```text
┌─────────────────────────┐
│ ‹  영상 비교       ✓  ⋯ │ 짧은 머리, 시작값44pt
├─────────────────────────┤
│                         │
│       영상 A · B         │ 남는 공간을 영상에 배정
│  실제 비율에 맞는 배치   │ A/B·반전 표시만 작게 겹침
│                         │
├─────────────────────────┤
│ −0.20 ───●──── +0.80     │ 타임라인, 터치영역44pt
│ 함께 ▾  ‹   ▶   ›  ½×   │ 공통 재생 조작44pt
├─────────────────────────┤
│ 맞추기  그리기  장면  ⋯ │ 작은 도구 도크44–48pt
└─────────────────────────┘
```

수치는 시작값이고 큰 글씨에서는 실제 높이를 잰다. 안전영역은 한 번만 적용한다. 비교 도구에 들어온 동안 전역 하단탭은 기존 라우트 계약에 맞춰 숨겨 영상 공간을 확보하고, 뒤로가면 원래 탭으로 복귀한다. 이미 숨겨져 있으면 추가 공간을 예약하지 않는다.

반복되는 '함께 보기' 제목, A/B 각각의 긴 제목 줄, 카드 바깥 패딩, 기본 도움말, 진단 수치 설명을 상시 표시에서 뺀다. 촬영일·구종·출처·긴 이름은 해당 영상의 정보 메뉴로 옮긴다. 저장 실패·원본 없음·잠금 등 필요한 오류는 작더라도 알아볼 수 있게 남긴다.

## 4. 영상 크기와 배치

### 실제 공간으로 계산

`영상 가능 높이 = 작업 화면 실제 높이 − 안전영역 − 실측 머리 − 실측 타임라인/재생 조작 − 실측 도구 도크 − 필요한 간격`

`onLayout`으로 작업 영역을 재고 순수 레이아웃 함수에 전달한다. READABLE/전체 창/모달 폭을 섞지 않는다. 큰 기기의 목록용 최대720 제한을 영상 작업 공간에 무조건 적용하지 않는다.

기본 글씨·키보드 닫힘·도구 패널 닫힘에서 영상 영역은 사용 가능 높이의 대략 65–75% 이상을 목표로 한다. 작은/가로/접근성 화면에서 불가능하면 실제 수치를 보고하고 모드/페이지를 바꾼다. 목표를 맞추려고 내용을 자르거나 글씨·터치를 줄이지 않는다.

### 원본 비율에 따라 배치

- 세로 영상 두 개: 세로 아이폰에서도 **나란히**가 영상 자체 면적을 더 크게 만들 수 있다.
- 가로 영상 두 개: 세로 아이폰에서 **위아래**가 유리할 수 있다.
- 혼합 비율: 후보 배치의 실제 contain 영상 면적을 계산해 결정한다. 한쪽에 공통 가로세로 비를 강요하지 않는다.
- 회전 시 자동 후보를 다시 계산하지만, 사용자가 지정한 배치는 따로 저장·복원한다.
- 자동 배치는 최초/자료 변경/유효한 컨테이너 변경 때 결정한다. 작은 픽셀 차이로 배치가 계속 바뀌지 않게 히스테리시스를 둔다.
- 두 영상의 실제 표시 면적 합과 작은 쪽의 사용성을 함께 평가한다. 어느 한쪽이 거의 안 보이는 결과는 피한다.
- '실제 영상 프레임 사이의 간격' 시작값4–6pt, 페이지 바깥 영상 거터4–8pt. 기존 카드식 패딩16·여러 겹 카드·두꺼운 모서리를 줄인다.
- 마지막 실제 영상 아래쪽과 타임라인 사이의 불필요한 빈 공간은 보통8–12pt 이내를 목표로 한다. 남는 공간이 생기는 비율에서는 이를 숨기지 말고 배치/가로 전환/집중 보기를 제공한다.

**원본 비율을 보존하면 남는 공간이 완전히 없어지지는 않는다.** 사람의 머리·발·릴리스 손을 자동으로 잘라 화면을 채우지 않는다. 두 영상을 동시에 보는 기본 배치에 더해 A/B 집중 보기·겹쳐 보기·가로 보기를 한 번 조작으로 제공한다. 집중 보기는 사용자가 선택한 모드이며 두 영상이 동등하게 보이는 기본 비교를 대체하지 않는다.

## 5. 재생 조작

- 공통 타임라인은 영상 바로 아래의 고정 위치다. 분석 도구 패널을 열어도 아래로 밀리거나 다른 페이지에 숨지 않는다. 공간이 부족한 키보드 편집 모드의 임시 전환은 6절 규칙을 따른다.
- `함께/A/B` 선택은 하나의 작은 선택기로 통일한다. 선택 모드를 항상 표시한다.
- 이전 장면·재생/멈춤·다음 장면·속도만 기본 노출한다. 반복·소리·정밀 시간 입력은 추가 메뉴로 제공한다.
- 타임라인은 얇게 보이더라도 터치 영역44pt 이상이다. 활성화/값/수정 단계를 VoiceOver로 제공한다.
- 반복 시작·끝 핸들은 같은 타임라인에 표시한다. 손잡이가 겹치면 선택 후 이전/다음 장면으로 미세 조정한다.
- 탐색 시작 시 멈춤, 연속 드래그 seek 병합, 마지막 목표 우선, 양쪽 도착 확인과 기존 동기화 규칙을 유지한다.
- 시점·속도·소스 변경 때 저장/복원/버퍼링 교정 기능이 사라지지 않아야 한다.

## 6. 도구 사용을 단순하게

### 맞추기

긴 안내 카드 대신 작은 상황 도크로 `A 선택 → 현재 장면 지정 → B 선택 → 현재 장면 지정 → 완료`를 진행한다. 동일한 타임라인과 이전/다음 버튼을 계속 사용한다. 기본 사건은 앞발 착지, 사건 선택은 작은 메뉴다. 두 기준이 있으면 `다시 맞추기`와 `취소`를 제공한다. 의미가 다른 기준을 표시만 바꿔 동일 사건으로 인정하지 않는다.

### 그리기

한 번 누르면 마지막 사용 도구로 들어간다. 기본 빠른 도구는 선·각도·자유선·점이다. 나머지는 '도구 전체'의 페이지형 그리드로 제공한다. 도구·색·굵기·A/B·완료를 동시에 열지 않는다.

- 현재 도구·그릴 영상·undo·완료는 작지만 고정된 위치에 둔다.
- 색/굵기는 해당 버튼을 누를 때만 여는 작은 팝오버다.
- 손가락 근처 확대 루페와 점 손잡이 선택을 제공해 손에 가린 지점을 조정한다. 새 디코더 요구가 있으면 기능 범위를 솔직하게 적는다.
- undo 한 번이 하나의 그리기/드래그 완료 동작을 되돌리도록 한다. 드래그 중 모든 샘플을 별도 undo 단계로 쌓지 않는다.
- 점 하나 조정·전체 이동·삭제를 구분한다. 닿는 실제 영역은44pt 이상이다.
- 그리기는 영상을 멈추고, 끝내면 이전 비교 모드로 돌아간다. '완료'를 찾으러 화면을 움직이지 않는다.

### 투구 장면

장면을 모두 긴 목록으로 펼치지 않는다. `무릎 / 손 분리 / 착지`와 `외회전 / 릴리스 / 팔로스루`처럼 페이지 또는 한 사건씩 선택하는 작은 패널을 쓴다. 현재 사건에서 A/B 시각·지정/지움만 다룬다. 측정 결과는 별도 요약 페이지로 보고, 주요 장면은 타임라인의 탭 가능한 마커로 이동한다.

### 메모·정보·출력

- 메모는 페이지당 1개 또는 화면에 맞는 소수 개수, 이전/다음으로 이동한다.
- 키보드가 열리면 재생을 멈추고, 작지만 실제 영상 미리보기를 남긴다. 메모 편집용 조작으로 문맥 도크를 교체한다.
- 긴 메모는 기존 내용을 자르지 않고 명시적인 편집 페이지로 분할한다. 입력창 내부 자동 스크롤에 기대지 않는다. 페이지 변경/닫기/취소에도 초안을 보존한다.
- 영상 정보·도움말·내보내기 설정은 항목별 페이지다. 원본/분석 데이터와 기능은 유지한다.
- 파일이 생성되지 않는 내보내기 기능을 활성 완료 기능처럼 보여주지 않는다.

## 7. 스크롤 금지와 예외의 정확한 범위

| 대상 | 처리 |
| --- | --- |
| 비교/정렬/한 영상/그리기/장면/메모/설정 화면 | 앱 소유 자유 스크롤 없음 |
| 도구 선택·메모 목록·영상 정보·사건 목록·스토리보드 | 버튼식 페이지·모드 전환, 자동 scroll-to-focus 없음 |
| 앱 내 영상 선택 | 검색/필터 + 한 화면에 들어가는 카드 + 이전/다음 페이지 |
| 타임라인·확대 영상·도형 조정 | 조작 목적의 drag/pan 유지, 페이지 위치 불변 |
| iOS 사진/파일/공유·권한·시스템 메뉴 | OS가 관리, 내부 스크롤 제한을 약속하지 않음 |
| 앱 바깥 다른 탭/영상 라이브러리 | 기존 스크롤 유지, 비교용 진입에만 전용 페이지 선택기 적용 |

전체 앱/다른 화면에 전역 스크롤 금지를 적용하지 않는다. 숨겨진 콘텐츠에 접근하지 못하는 방식의 `overflow:hidden`/`scrollEnabled=false`만으로 해결하지 않는다. 앱 소유 내용을 실제 가용 공간에 배치하고 긴 내용은 페이지로 이동할 수 있게 만든다.

## 8. 상태·안전·접근성

보기/맞추기/그리기/사건/메모/출력 모드는 한 번에 하나만 활성화한다. 팝오버를 겹쳐 쌓지 않는다. 닫기·뒤로가기는 팝오버→도구 모드→비교 화면 순으로 처리하고 자료 선택 취소는 기존 비교를 복원한다.

작은 화면·키보드·큰 글씨에서는 메뉴 페이지당 항목 수를 줄인다. 글씨 배율을 강제로 막거나44pt 터치를 줄여 맞추지 않는다. VoiceOver는 현재 영상→타임라인→재생→도구의 논리 순서로 이동하며 화면 밖으로 스크롤하려는 동작을 유발하지 않는다.

레이아웃·모드 변경 때 디코더를 다시 만들지 않고 원본 asset/player identity를 유지한다. 영상의 원본 좌표 주석이 확대/회전/새 배치에서도 같은 지점에 붙는지 확인한다. 원본 변경·계정 변경·저장 충돌의 기존 보호 규칙과 버그 교정 F01–F07을 유지한다.

## 9. 구현 단계와 완료 기준

1. 현재 다른 세션 변경과 F01–F08 교정 상태를 확인한다. 레이아웃/도구 변경을 저장 엔진 교정과 분리해 충돌을 줄인다.
2. 실측 기반 순수 `workspace-layout` 계산과 고정 View 프레임을 만든다. 기본 영상·타임라인·재생·도크부터 연결한다.
3. 원본 비율별 자동 배치·A/B 집중·가로 구성을 연결한다. 플레이어/시점/그림이 유지돼야 한다.
4. 맞추기·그리기·사건 도구를 상황 패널과 페이지식 메뉴로 옮긴다.
5. 메모/키보드/정보/출력/앱 영상 선택까지 스크롤 의존을 제거한다.
6. 전체 상태·치수·접근성·기존 흐름 회귀와 화면 내 경계를 검증하고 남은 기기 시험을 보고한다.

필수 확인:

- 모든 기본 조작과 실제 영상 프레임이 동시에 보이고 타임라인 접근에 스크롤이 필요 없음.
- 앱 소유 화면/패널에 상하·좌우 스크롤, 바운스, wheel/trackpad에 의한 페이지 이동이 없음.
- 페이지 단위로 모든 기존 도구·긴 내용·오류·설정에 도달 가능.
- 무영상/한 영상/두 영상, 세로/가로/혼합, 긴 이름, 실패/로딩에서도 버튼이 화면 밖으로 가지 않음.
- 실제 표시 영역·contain 프레임 면적·조작 거리·안전영역/키보드와의 교차를 측정한다. stage 사각형만 커졌다고 영상이 커졌다고 보고하지 않는다.
- 320×568·375×667·390×844·430×932pt 및 각각 가로, 아이패드/분할창, 기본/160%/200% 글씨, 라이트/다크/네이비 확인.
- **시뮬레이터·Metro 금지**는 유지한다. 순수/모의/가능한 비시뮬레이터 검사를 수행하고, 물리 기기의 실제 영상·터치·키보드 검증은 미검증이면 그대로 적는다.

이번 산출물은 이 계획과 영어 프롬프트다. 앱 구현·클로드에 새 지시 전송·커밋·푸시·배포는 이 문서 작성에 포함하지 않았다.
