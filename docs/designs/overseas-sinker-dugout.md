## 1. 핵심 결론과 추천 구조

1. **앱은 셋이다 — 싱커 하나(한 · 미 · 일 공통), 한국 덕아웃 앱 하나.** 미국 · 일본 덕아웃 앱은 만들지 않는다. 싱커 안의 '덕아웃' 탭이 그 나라 커뮤니티다. 덕아웃 앱(`com.bullpenlog.dugout`)은 App Store 배포 국가를 한국만으로 둔다.
2. **나라는 '구성'이고 언어 · 단위 · 시간대는 따로다.** 계정의 나라(`User.country`, 이미 있음)가 탭 · 기능 · 덕아웃을 정하고, 언어는 iOS 앱 언어, 단위는 기기 설정, 시간대는 기기 시간대를 따른다.
3. **게시물의 나라는 쓰는 순간 글에 박는다.** `CommunityPost.country`(기본 'kr') 하나를 더하고, 댓글 · 좋아요 · 저장 · 신고는 글의 나라를 따른다. 기존 글은 기본값으로 모두 한국 글이 된다. 계정 나라를 바꿔도 예전 글은 그대로다.
4. **DB 를 나라마다 셋으로 나누지 않는다.** 출시(베타) 단계는 지금 서울 DB 하나 + 나라 칸으로 간다. 미국 사용자가 늘면 `overseas-regions.md` 의 미국 동부 DB 로 미국 계정을 옮긴다 — 나라 칸이 있으면 옮길 줄을 고르는 일이 쉬워진다.
5. **가장 큰 일은 번역 · 시간대 · 미성년 보호다.** 해외판 기능 대부분은 이미 있다(일부는 관리자 전용). 하지만 화면 글은 전부 한국어(약 1만 6천 줄), 날짜는 전부 한국 시간, 가입은 생년월일만 받고 보호자 동의가 없다.
6. **영상 공유는 '공유용 사본'으로.** 일반 회원의 투구 영상은 폰에만 있다. 공유할 때 고른 영상만 공유용으로 한 번 올리고, 글은 개인 원본이 아니라 그 사본만 가리킨다. 그래야 개인 영상을 지워도 글이 안 깨지고, 글을 지워도 개인 영상이 안 지워진다(지금은 둘 다 서로를 지울 수 있다 — 5-6절).

## 5. 나라별 덕아웃 — 데이터 · 권한 · 공유

### 5-1. 지금 구조 [코드]
- `CommunityPost`(schema 1782-1831): category · tag · title · body · media(4개) · card(스냅샷 JSON) · form · **region · district(한국 시 · 도와 시 · 군 · 구 — 번개 · 팀 글만)** · meetAt · hiddenAt …. 나라 칸 없음. 색인 createdAt · (category, createdAt) · userId.
- 딸린 표: Comment · Like · Save · Block(사람 대 사람) · Join · Message(글에 묶인 대화) · Report(SetNull) · Moderation · Notification(link 문자열).
- 목록은 `listWhere()`(`lib/community-load.ts:90-111`) 하나로 모인다 — 웹 목록 · 앱 목록 · 싱커 덕아웃 홈 인기 · 최신 · 번개.
- 따로 거르는 곳: 검색 `lib/search.ts:63-80` · 덕아웃 홈 인기 `lib/market/load.ts:414` · 답 기다리는 질문 `community-load.ts:264` · 운영 지표 `lib/community-ops.ts:313-373`.
- id 로 여는 곳(나라 확인 없음): `loadCommunityPost`(298) · 대화방(522, 555) · `loadPostExtras`(221) · `app/actions/community.ts` 의 좋아요 · 저장 · 댓글 · 참여 · 닫기 · 결과 · 메시지 · 신고 · 이의.
- 알림은 글에 이미 닿은 사람(글쓴이 · 참여자 · 채택된 답)에게만 간다 — 퍼뜨리는 알림 없음.
- 공유 = 주소 복사(`components/community/community-post-actions.tsx:43-60`), 글마다 OG 없음, 사이트맵에 커뮤니티 없음.

### 5-2. 나라를 어떻게 정하고 지키나 [제안]
- **칸 하나: `CommunityPost.country String @default("kr")`** + 색인 `(country, createdAt)` · `(country, category, createdAt)`. 기본값이라 기존 글은 모두 'kr' 로 채워진다 — 따로 옮기는 스크립트가 없다.
- **정하는 때**: 글을 만들 때 서버가 쓴 사람의 덕아웃 나라(처음엔 `countryOf(User.country)`)를 넣는다. 화면이 보낸 값은 안 믿는다. 고치기(`updatePost`)는 나라를 안 바꾼다.
- **글에서 따라오는 것**: 댓글 · 좋아요 · 저장 · 참여 · 신고 · 알림은 칸을 따로 두지 않고 글의 나라를 따른다(한 곳에만 있으니 어긋날 수 없다).
- **region · district 는 그대로 '한국 안 지역'**. 나라와 섞지 않는다. 미국 · 일본 글은 region 을 비운다(번개 · 팀 게시판이 없으니 저절로).
- **계정 나라를 바꾸면**: 새 글부터 새 나라. 예전 글은 예전 나라 덕아웃에 남고, 내 활동(`loadMyCommunity`)에는 나라 표시와 함께 다 보인다.

### 5-3. 어디에 거르기를 넣나 [제안]
| 곳 | 규칙 |
|---|---|
| 목록 · 싱커 덕아웃 홈 · 앱 목록 | `listWhere` 에 `country` 한 줄 — 셋이 한꺼번에 |
| 검색 · 덕아웃 홈 인기 · 답 기다리는 질문 | 각 where 에 같은 줄 |
| 상세(id) | 읽기는 된다 + 다른 나라 글이면 '미국 Dugout 글' 표시 · 쓰기(댓글 · 좋아요 · 참여 · 메시지)는 막음 (Q5 확정) |
| 서버 쓰기 동작 | 글을 읽은 뒤 `post.country === 보는 사람 덕아웃 나라` 확인 한 함수(`assertSameDugout`) |
| 신고 | 다른 나라 글도 신고는 된다(안전이 먼저) |
| 관리자 | 신고 · 글 목록에 나라 고르개, 지표는 나라별 |
| 알림 | 그대로(글에 닿은 사람만이라 나라가 섞이지 않는다) — 글 주소만 |
| 사이트맵 · OG | 지금 없음. 만들 때 나라 · 언어 붙여서 |

같은 규칙이 흩어지지 않게 `lib/community-country.ts` 한 곳(보는 사람의 덕아웃 나라 · where 조각 · 같은 나라 확인)에 둔다.

### 5-4. 다른 나라 덕아웃 보기 — 선택지
1. 안 보임(링크로만 읽기) — **권장(출시)**. 커뮤니티가 작을 때 섞이면 언어가 엉킨다.
2. 설정에서 '다른 나라 덕아웃 구경' 읽기 전용 — 사람이 모인 뒤.
3. 합친 피드 + 번역 — 운영 · 번역 비용이 커서 나중.

### 5-6. 영상 · 감각 기록 공유 [코드 → 제안]
**지금** [코드]
- 내 영상 = `UserVideo` 줄 + 투구 · 타격 기록의 영상 경로를 합쳐 보인다(`lib/my-videos-load.ts:13-89`). 구속 클립 · 3D 샘플은 빠짐.
- 감각 메모(`UserVideo.feelNote`, 영상 하나) ≠ 투구 기록 메모 · 좋았던/아쉬운 감각(`PitchLog.memo · cuesGood · cuesBad`, 그날 한 번) ≠ 운동 총평(`DailyTrainingNote`). 서로 복사되지 않는다.
- 일반 회원 영상은 폰에만(`{userId}/local-<uuid>`). 서버는 재생 주소를 못 만든다(`lib/storage.ts:198-199`).
- 기록 카드는 스냅샷이지만 영상은 경로만 들고 볼 때마다 주소를 만든다 → **원본을 지우면 카드 영상이 조용히 사라진다**.
- 지우기가 서로를 친다: 영상 · 기록 지우기의 `referencedPaths`(`lib/video-refs.ts:36-70`)가 글의 media · card 를 안 봐서 글이 쓰는 파일을 지울 수 있고, 글 지우기(`app/actions/community.ts:303,343`)는 확인 없이 media 를 지운다.
- 앱의 글쓰기는 글만(`native/src/app/community/new.tsx`) — 영상 · 카드는 웹뷰 덕아웃에서.

**제안 흐름**: 내 영상 → 영상 고르기 → [덕아웃에 올리기] → 미리보기 화면 → 올림 → 댓글은 앱 안 알림.
1. **미리보기**: 맨 위에 '미국 Dugout 에 올라가요'(나라 이름 크게). 그 밑에 실제로 보일 것만 — 영상(자른 구간) · 제목 · 본문 · 갈래(폼 질문 / 훈련 기록 / 팁). 감각 메모는 '본문에 넣기' 단추로 **복사**(이후 개인 메모를 고쳐도 글은 그대로). 구속 · 투구 수 · 날짜는 하나씩 켜는 칩(기본 꺼짐). 체크인 · 통증 · 영양 · 팔 상태는 칩 자체가 없다.
2. **공유용 사본**: 글은 개인 경로를 절대 안 가리킨다. 폰에만 있는 영상 → 고른 구간만 720p 로 줄여 `{userId}/share-<uuid>.mp4` 로 한 번 올림. 서버에 이미 있는 원본(관리자 등) → 저장소 안 복사(다시 안 올림). 같은 영상을 두 번 공유하면 내용 지문(sha256)으로 같은 사본을 쓴다.
3. **올리기 실패 · 중단**: 글 초안을 폰에 남기고(지금 운동 · 영상 대기열 `native/src/videos/outbox` 와 같은 방식), 영상이 다 올라간 뒤에만 글을 만든다. 다시 열면 '이어서 올리기'. 반쯤 올라간 사본은 글이 안 만들어지면 하루 뒤 정리.
4. **지우기 관계**: 글 지우기 = 사본만 지움(개인 원본 그대로). 개인 영상 · 기록 지우기 = 글 그대로(사본이라서). 탈퇴 = 둘 다(지금처럼 사용자 폴더 통째).
5. **개인 기록 고치기**: 글은 스냅샷 — 미리보기에 '기록을 나중에 고쳐도 글은 그대로예요' 한 줄.
6. **다른 사람이 찍힌 영상**: 올리기 전 확인 한 줄('함께 찍힌 사람에게 허락을 받았어요'). 미성년 다른 선수 얼굴은 9절 정책을 따름.
7. **비용**: 사본은 구간 · 720p 라 원본의 10~20%, 지문으로 중복 없음.
8. **지금 고칠 버그(한국에도 해당)**: `referencedPaths` 에 글 media · card 영상을 넣고, 글 지우기는 참조 확인 뒤 지운다. 공유용 사본으로 바꾸면 이 문제가 사라지지만 그 전에도 고칠 만하다.

### 5-7. 미국 · 일본 덕아웃 화면 [제안]
- **피드 하나 + 고르개 셋**(전체 · 폼 질문 · 훈련 기록 · 팁). 지금 판으로는 `question` + tag `form` · `free` + tag `record` · `free` + 새 tag `tip` — 새 표 없이 나라별 게시판 설정(`communityBoardsFor(country)`)만.
- 폼 질문: 영상 필수, 답 채택 · 해결됨 · 답 달리면 알림(지금 있음). 첫 화면 위에 '답을 기다리는 질문' 줄(지금 `waitingQuestions`).
- 훈련 기록: 오늘 한 운동 · 그날 느낌(선택 칩으로 구속 · 투구 수).
- 팁: 드릴 · 훈련 경험. 운동 라이브러리 항목을 붙일 수 있게(나중).
- 후속 단계(초기 필수 아님): 코치 배지 · 팀 공간 · 팔로우 · 개인 채팅 · 랭킹 · 장소 찾기. 개인 채팅 · 장소는 미성년 보호 부담이 커서 가장 뒤.

## 6. 언어 · 단위 · 시간대 · 기존 데이터

| 설정 | 기본값 [제안] | 바꾸기 | 저장 |
|---|---|---|---|
| 나라 구성 | **앱스토어 계정 나라**(StoreKit storefront — KOR · USA · JPN) — 사용자가 고르지 않는다(김민 Q3) | 앱스토어 계정 나라가 바뀌면 따라 바뀜 · 관리자만 시험용 고정 | `User.country`(있음) |
| 덕아웃 나라 | 나라 구성과 같음 | 따로 없음 | — |
| 앱 언어 | iOS 앱 언어(기기 언어) | iOS 설정 › 싱커 › 언어 | 기기 + 서버(푸시 글용 `User.language`, 푸시를 붙일 때) |
| 단위 | 미국 mph · lb · ft-in(설정에서 km/h · kg · cm), 한 · 일 km/h · kg · cm | 앱 설정(지금 있음) | 기기(지금 그대로) — 저장값은 늘 미터법 |
| 시간대 · 날짜 | **기기 시간대 · 기기 날짜**(김민 Q10) | 기기를 따라 바로 바뀜(여행 포함) | 요청마다 기기 시간대를 보냄 + 서버가 먼저 보내는 것(푸시)용으로 `User.timeZone` |

**나라 = 앱스토어 계정 나라**(김민 Q3 — 처음 요청의 '스토어만으로 확정하지 말 것'을 김민이 바꿈). 기기 언어 · 위치는 안 쓴다.
- 앱이 켤 때 storefront 나라를 서버에 알린다(앱 모듈에 함수 하나 — `Storefront.current?.countryCode`, 3글자). 서버가 KOR → kr · USA → us · JPN → jp 로 `User.country` 에 쓴다.
- 대표관리자는 storefront 를 따르지 않는다 — 시험 전환(`setMyCountry`)이 덮이지 않게. 관리자 화면 '앱스토어 나라로'를 누를 때만 따른다(2단계에서 이렇게 해 DB 칸을 더하지 않았다).
- 그 밖 나라 storefront(TestFlight 시험자 · 배포 국가를 넓힐 때)는 마지막으로 알려진 값, 없으면 한국(Q14). PC 웹은 당분간 한국 사용자만 — 웹 가입은 한국(Q15).
- storefront 가 바뀌면 새 글부터 새 나라 덕아웃. 예전 글 · 기록은 그대로.

**시간대** [코드]
- 날짜 열쇠는 늘 한국 날짜(`lib/pitch-stats.ts:85-111` — 주석에 '해외에서도 한국 날짜'), `toDateKey` 129개 파일 · `appNow` 105개 파일, 따로 박힌 +9시간 · `+09:00` 23곳(번개 · 레슨 · 예약 알림 · 영양 시각 · 3D 하루 한도 …), 앱 `untilKstMidnight`(`native/src/app/index.tsx:285`), 폰 시간으로 셈하는 곳 약 17곳(섞임).
- 저장은 `@db.Date` 날짜 열쇠(37칸)라 **이미 남긴 기록의 날짜는 시간대와 상관없이 보존된다**. 바뀌는 것은 '오늘이 며칠인가'와 하루가 바뀌는 때뿐.

**[제안 — 김민 Q10: 시간대 · 날짜 넘어감은 모두 기기 기준]**
1. 앱 · 웹이 **모든 요청에 기기 시간대(IANA, 예 `America/Chicago`)를 머리글로** 보낸다(앱 rpc · fetch · 웹뷰 쿠키, PC 웹은 브라우저 시간대 쿠키). 서버의 `toDateKey(d)` 기본 시간대 = 그 요청의 시간대(시험 계정 날짜 `lib/clock-server.ts` 와 같은 자리에서 읽음), 머리글이 없으면(옛 앱) 한국. 한국 사용자는 숫자가 하나도 안 바뀐다.
2. 그래서 '오늘' · 자정 · 연속 일수 · 하루 한도가 기기 날짜와 늘 같다. 앱 `untilKstMidnight` 는 기기 자정으로. 폰 시간으로 셈하던 17곳은 그대로 맞아진다.
   서버가 먼저 보내는 것(푸시 · 하루 정리)만 `User.timeZone`(마지막 기기 시간대)을 쓴다.
3. 따로 박힌 23곳을 시간대 인자로. 레슨 · 연습장 · 번개(한국 전용)는 'Asia/Seoul' 그대로 둬도 된다 — 장소가 한국이라서.
4. 서머타임: IANA 이름(`America/New_York`)으로 `Intl` 이 처리. 시험 날: 미국 2026-11-01(끝) · 2027-03-14(시작) 새벽 1~3시, 자정 직전 · 직후 기록.
5. 시간대를 바꾸면 과거 기록은 그대로, 연속 일수 같은 셈만 새 시간대로.

**단위** [코드 → 제안]: `lib/units.ts` 를 그대로 쓴다. 입력 → 저장 변환은 이미 끝(웹 · 앱 13곳). 남은 일은 'km/h' · 'kg' 글자를 박아 둔 약 110곳을 `formatSpeed` · `formatWeight` 로. 투구량 · 부하 셈은 저장값(미터법)만 쓰니 표시 단위와 무관 — 시험으로 고정(같은 기록, 단위만 바꿔 부하 지수 같은지).

**번역** [코드 → 제안]
- 규모: 화면 글 있는 파일 약 1,000개(app 352 · components 190 · native 225 · lib 241), 서버 동작 오류 글 약 1,000개, 날짜 글 `'${m}월 ${d}일'` 66곳, 조사 함수(`lib/korean.ts`) 25곳, 운동 · 드릴 이름 · 분류 값이 DB 안 한국어.
- 길: 웹(덕아웃 · 트레이닝 일부가 웹뷰라 웹이 먼저) next-intl 류 하나, 앱은 같은 사전을 쓰는 가벼운 함수(expo-localization 으로 기기 언어). 서버 오류는 '오류 코드 + 사전'으로 바꿔 화면이 그 언어로 그린다. 운동 라이브러리는 번역 칸(JSON `{en, ja}`) — 분류 값('어깨')은 키로 두고 표시만 번역.
- **범위를 줄인다**: 해외판에 보이는 화면(투구 · 내 영상 · 구속 · 트레이닝 · 암케어 · 메커니즘 · 덕아웃 · 설정 · 가입 · 오류)만 먼저. 타격 · 영양 · 덕아웃 한국 기능 · 관리자는 번역 안 함.
- 투수 용어는 현지 코치 둘(미 · 일) 검수 — 9절.

**업데이트 섞임** [코드]: 서버(`lib/app-update.ts:68-92`, `app/api/app-update/route.ts:21-37`)는 runtimeVersion 하나로만 고른다 — 묶음 ID · 변형 · 채널을 안 본다. 묶음 ID 가 다르면 지문이 달라져 운영 업데이트를 안 받을 것으로 보이나(추정), 굽기에서 `EXPO_UPDATES_FINGERPRINT_OVERRIDE` 로 운영 지문을 넣으면 운영 묶음(싱커 설정까지)을 받는다.

**권장**
1. 매일 견주기는 **A**. 시험 글은 관리자 계정이 아니라 나라별 시험 계정(AGENTS 3번 — 각자 시험 계정)으로.
2. 정말 나란히 볼 때만 **B 한 개**(예: `com.bullpenlog.app.dev` 를 미국으로 고정)를 맥에서 깔기. 나라 고정은 시험 앱이 보내는 머리글을 서버가 **관리자 계정일 때만** 받는 식.
3. B 를 만들기 전에 업데이트 서버에 채널 확인을 더한다: 앱 설정 `updates.requestHeaders` 에 `expo-channel-name`(운영 'production', 시험 'test'), 서버가 채널별 폴더(`updates/<channel>/<runtime>/…`)를 보게. 운영은 채널이 없으면 'production' 으로 읽어 지금 깔린 앱이 안 깨지게.
4. 정식 출시는 싱커 하나(4.3). 시험 앱은 심사에 내지 않는다.
