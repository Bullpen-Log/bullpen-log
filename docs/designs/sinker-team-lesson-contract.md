# 싱커 팀 · 레슨장 — 0단계 계약(2026-10-25)

계획 문서 '싱커 팀 · 레슨장 계획'(claude.ai 문서, https://claude.ai/artifact/FaPUa1mXdDsCgWm3SkPS1j)의 0단계 산출물이다.
표 · 서버 동작 · 공유 규칙 · 앱 화면을 여기서 정하고, **두 사람(김민 · 금윤호)이 이 문서에 합의하면 1단계를 시작한다.**
이 문서를 쓰는 동안 코드 · DB 는 바꾸지 않았다.

정한 것(계획 문서 '사용자 결정' 1~9): 예약 · 수강권 · 결제는 덕아웃 · 초대 코드만으로 독립 사용 · 마스터 계정엔 내 싱커 없음 ·
영상 피드백은 일지에 합침 · 경기 · 새 부상 관리는 뒤로 · 덕아웃 안 쓰는 레슨장은 싱커에서 예정 활동만 적음 · 코치가 적은 투구는
선수 기록에 바로(선수는 정정 요청) · 떠난 선수도 받은 일지는 읽기만 · 계정 잇기 전 일지는 옮기지 않음.

**2026-10-26 개정 — 공간 · 역할별 내비게이션(8절).** 팀 · 레슨장은 계정 종류가 아니라 '공간'이다. 선수 계정 하나로 내 싱커와 여러 조직에 동시에 속하고, 위 막대 고르개로
공간을 바꾸면 아래 탭이 공간 · 역할에 맞게 바뀐다. 바꾸기는 나가기 · 공유 바꾸기가 아니다. 앱 내비게이션 · 고르개 · 나가기 자리 · 공간 상태는 **8절이 기준**이고, 아래 2-2 의 탭 줄은 8절로 대체한다.

**2026-10-26 확장 후보 검토(10절).** OOTP · FM 참고 후보 A~H 평가 · 권하는 첫 판(훈련 보드 · 다시 쓰기 · 오늘 브리핑) · 미루기 · 표 제안 — 설계만, 정할 것은 10-10. 플레이북(F)은 김민 결정으로 뺌.

**2026-10-26 화면 녹화 검토(9절).** 팀 관리자 화면의 판 확인 · 지적 A~H · 셸 · 오늘 구조 · 관리자↔선수 흐름 빈칸 · 고칠 것 세 묶음 · 확인 시나리오 — 다음 단계는 **9절이 기준**.

**2026-10-26 개정 — 팀 훈련은 전체 → 조 → 예외(11절).** 팀은 대부분 다 같이 훈련한다. 팀 공간의 기본 흐름은 '선수 한 명씩 배정 · 한 명씩 기록'이 아니라
'훈련 하나를 한 번 적고, 다르게 한 선수만 고친다'이다. 팀 훈련의 계획 · 실제 기록 · 결과는 **11절이 기준**이고, 4절 '수행일지' · 9-6 ①-6 · 10-4 의 선수별 흐름은 11절의 예외 고치기로 들어간다.
레슨장(회원 중심 일지 · 숙제)은 바꾸지 않는다.

## 3. 2단계 — 레슨장(마이그레이션 묶음 M2)

모두 더하기다. 새 칸은 비워 둘 수 있거나 기본값이 있다(AGENTS 2번).

```prisma
model OrgEvent {
  // 지금 칸 그대로 + 아래
  /// 'planned' 예정 · 'done' 실시 · 'canceled' 취소 — 지도 활동 확인(출석 아님, 수강권과 무관)
  status   String    @default("planned")
  doneAt   DateTime?
}

model LessonNote {
  // 지금 칸 그대로 + 아래
  /// 어느 지도 활동의 일지인가. 저장할 때 활동이 없으면 그날 'done' 레슨 활동을 만들어 잇는다
  eventId    String?
  /// 일지에 붙인 영상(저장소 경로) — 코치가 찍었거나 선수 투구 영상에서 고른 것
  videoPaths String[] @default([])
  editedById String?
  updatedAt  DateTime @default(now()) @updatedAt
  @@index([eventId])
}

model PitchLog {
  // 지금 칸 그대로 + 아래
  /// 조직 활동에서 나온 투구(코치가 적었거나 선수가 그 활동에 이은 것)
  orgEventId String?
  /// 같은 저장 요청을 다시 보내도 한 줄 — 앱이 만든 키. 옛 줄은 null
  clientKey  String?
  @@unique([userId, clientKey])
  @@index([orgEventId])
}

/// 숙제 — 회원 한 명에 한 줄. 상태가 'done' 이면 실제 수행 기록을 가리킨다
model OrgAssignment {
  id             String    @id @default(uuid())
  orgId          String
  memberId       String
  noteId         String?
  assignedById   String
  /// [{ exerciseId?, guideId?, sets?, reps?, holdSec?, note? }] — 라이브러리 운동 · 드릴만(자유 글 운동 없음)
  items          Json
  dueDate        DateTime? @db.Date
  /// 'assigned' · 'in_progress' · 'done' · 'excused' · 'canceled'
  status         String    @default("assigned")
  doneSessionId  String?
  donePitchLogId String?
  doneAt         DateTime?
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt
  @@index([memberId, status])
  @@index([orgId, createdAt])
}

/// 일지 · 숙제에 다는 말 — 코치의 영상 시점 코멘트 · 회원 질문 · 정정 요청 · 숙제 영상 제출을 한 표에. '받은 것' = 회원이 쓴 줄 중 안 푼 것
model OrgComment {
  id           String    @id @default(uuid())
  orgId        String
  memberId     String
  noteId       String?
  assignmentId String?
  authorId     String
  /// 'comment' · 'question' · 'fix'(정정 요청) · 'submit'(숙제 영상)
  kind         String    @default("comment")
  body         String    @db.Text
  videoPath    String?
  /// 영상의 몇 초에 단 말인가
  atSec        Float?
  resolvedAt   DateTime?
  createdAt    DateTime  @default(now())
  @@index([noteId])
  @@index([assignmentId])
  @@index([orgId, resolvedAt])
}
```

**운동량 규칙(2단계)**

- 일지의 **투구 수**는 저장할 때 선수 `PitchLog` 로 남긴다(`enteredById` = 코치, `orgId`, `orgEventId`, `clientKey`). 선수가 그날 직접 남긴 투구 기록이
  있으면 새로 만들지 않고 코치가 고른 그 줄에 `orgEventId` 만 잇는다. 선수 확인 없이 들어가고 선수는 `OrgComment kind 'fix'` 로 정정을 요청한다(결정 7).
- 일지의 **운동**은 2단계에서는 일지에만 둔다(부하에 안 셈). 라이브러리에서 고르게 해서 나중에 옮길 수 있게 `exerciseId` 를 남긴다.
  까닭: 운동 판(`TrainingSession`)이 선수 하루에 하나(`@@unique([userId, date])`)이고 요약(`UserExerciseLog`)도 하루 · 운동마다 한 줄이라,
  코치 운동을 그대로 넣으면 선수의 그날 운동과 부딪힌다. 이 문제는 팀 수행일지(3단계)에 꼭 필요해서 3단계 전에 푼다(4절).
- 숙제는 선수가 트레이닝 탭에서 하면 그 운동 판이 실제 수행이 된다. `OrgAssignment.doneSessionId` 로 가리킨다.
- 일지를 지우거나 고치면 그 일지가 만든 `PitchLog` 만 같이 고치거나 지운다(`orgEventId` + `enteredById` 로 찾음). 선수가 직접 남긴 줄은 연결만 푼다.
- 계정을 아직 잇지 않은 회원(`userId` 없음)의 일지는 `PitchLog` 를 만들지 않는다. 이어도 옮기지 않는다(결정 9).

### 8-2. 공간과 역할(정한 것)

- **공간**은 화면 묶음이지 계정 종류가 아니다. 선수 계정 하나로 내 싱커를 쓰면서 여러 팀 · 레슨장에 동시에 속한다. 들어가기(초대 코드)는 내 싱커를 바꾸지 않고, 계정을 더 만들거나
  계정 종류를 바꾸지 않는다.
- 탭은 **고른 공간 + 그 조직에서 서버가 인정한 역할**로 정한다. 역할은 선수 계정이면 늘 '선수/회원'(PLAYER), 코치 쪽(MASTER · STAFF)은 마스터 계정만(`lib/org/join.ts` 가 선수 계정의 코치 코드를
  막는다 · `coachOrg` 가 `isMasterUser` 를 본다). 관리자(ADMIN, 선수 계정)는 내 싱커 + 제가 만들었거나 코치로 든 조직(지금 `loadMySpaces` 그대로).
- **마스터 계정엔 내 싱커가 없다(결정 3).** 고르개에는 관리 권한이 있는 조직만. 선수로도 뛰는 코치는 선수 계정을 따로 쓴다.
- **공간 바꾸기 ≠ 로그아웃 · 계정 바꾸기 · 들어가기 · 나가기 · 공유 바꾸기.** 바꾸기는 서버에 아무것도 쓰지 않는다. 소속 · 기록 · 공유 범위는 그대로다.
- **경계(결정 1)**: 예약 · 일정 바꾸기(예약) · 수강권 · 결제 · 정산은 덕아웃. 싱커 조직 탭에 예약 관리 · 수강권 잔액 · 결제 단추를 두지 않는다. 덕아웃은 조직 공간 아래 탭에 넣지 않고 더보기의
  '덕아웃 열기'(이름표에 덕아웃이라고 씀)나 그 흐름 안 링크로만. 레슨장은 덕아웃 예약 없이 초대 코드만으로 쓴다.

### 8-4. 흐름

**들어가기**: 더보기 › 소속 관리 › 코드로 들어가기(또는 초대 링크 `/join?code=` → 앱 `org/join`) → 공유 범위 고르기 → 들어가면 그 공간으로 바로 옮길지 묻는다(기본 '옮기기').
덕아웃 예약 확정으로 연결된 회원은 고르개에 '공유 대기' 표시로 뜨고, 그 공간에 처음 들어가면 보여 줄 기록부터 고른다(2-1 2번 그대로).

**바꾸기**: 공간 탭 첫 화면들의 위 막대 가운데(또는 제목 줄)에 지금 공간 이름 + ▾. 누르면 아래 시트:
`내 싱커` / `○○ 야구팀 · 선수` / `△△ 레슨장 · 회원` … (+ 아래 '소속 관리' · 선수면 '코드로 들어가기'). 고르면 그 자리에서 아래 탭이 바뀌고 그 공간의 마지막 탭(처음이면 첫 화면)이 뜬다.
내 싱커에서는 **홈 머리(종 옆)와 더보기 맨 위**에 같은 고르개를 둔다 — 둘 다 앱 화면이라 웹 다리가 필요 없다(내 싱커의 홈 · 투구 · 트레이닝 · 영양은 웹뷰를 덮는 앱 화면이고,
타격 · 덕아웃만 웹이다). 투구 · 타격 · 덕아웃 탭에서는 아래 탭의 홈 · 더보기가 한 번 누름 거리라 따로 안 그린다(8-9 U1).
조직이 하나도 없는 선수에게는 고르개를 안 그린다(지금 내 싱커 모습 그대로) — 들어가는 길은 더보기 › 소속 관리.

**돌아오기**: 어느 조직 공간이든 탭 첫 화면의 고르개에서 '내 싱커'를 누르면 내 싱커 아래 탭과 마지막 화면이 곧바로 돌아온다. 조직 공간은 웹뷰 위에 덮는 앱 화면이라(투구 탭이 웹뷰를 덮는 것과 같은 방식)
웹뷰 · 판 넘기기 · 종목 바 상태가 그대로 남는다. 상세 화면(일정 하나 · 회원 카드 · 일지 쓰기 …)에는 고르개 대신 '뒤로' — 뒤로는 늘 그 공간의 탭 첫 화면까지 가고, 거기 고르개가 있다.
돌아오기는 `leaveOrg` · `saveConsent` 를 부르지 않고 소속 상태를 바꾸지 않는다(8-7 시험이 소스로 본다).

**조직 일에서 개인 운동 열기**: 숙제 · 내 훈련의 '운동하기'는 내 개인 운동(`/workout`)을 연다(숙제는 지금처럼 '오늘 운동에 넣기'로 오늘 판에 넣은 뒤). 주소에 출발지(`from=org:<orgId>:<memberId>:<탭>`)를 달고,
운동을 마치면(`/workout-done`) 그 조직 공간의 그 탭으로 돌아온다. 출발지가 더는 유효하지 않으면(그새 나감 · 빠짐) 내 싱커로 돌아오며 한 줄 알린다. 운동 기록은 개인 기록 하나뿐이고(복사 없음),
숙제 완료는 지금처럼 그 기록을 읽어 맞춘다(2단계 규칙).

**나가기**: 더보기 › 소속 관리 › 그 팀/레슨장 › 나가기 → 확인 시트
"○○에서 나가면 코치가 내 기록을 더는 못 봐요. 받은 레슨일지는 읽기만 할 수 있고, 다시 들어가려면 새 초대 코드가 필요해요. 내 싱커 기록은 그대로예요." [나가기 · 취소].
나가면 그 공간이 고르개에서 빠지고, 지금 그 공간이었으면 내 싱커로. 떠난 조직의 받은 일지는 소속 관리 '지난 소속'에서 읽기만 — 거기서 쓰기 · 말 · 영상 · 숙제 바꾸기는 안 되고,
그 조직의 지금 화면(오늘 · 일정 · 공지)이나 코치 권한은 열리지 않는다. 다시 들어가는 길은 새 초대 코드뿐이다.

**알림 · 딥링크**: 지금 싱커 앱에는 푸시 받기가 없다(`expo-notifications` 없음) — 알림은 앱 종의 목록과 웹 알림 목록에서 누른다. 푸시가 생기면 같은 처리를 쓴다.
조직 알림의 주소는 `/org/open?org=<orgId>&as=p|c&to=<앱 화면 주소>`. 앱은 누르면 공간 목록을 다시 받아 확인한 뒤
① 그 공간이 지금 소속이면 그 공간으로 옮기고(8-5 쓰던 글 보호) 목적 화면을 연다 ② 지난 소속이면 받은 일지 알림만 '지난 소속'의 그 일지로, 나머지는 "이제 볼 수 없는 소식이에요" ③ 권한이 없으면 같은 한 줄.
개인 알림(체크인 · 운동 · 영양 …)은 지금 그대로 내 싱커로 — 조직 공간에 있으면 내 싱커로 옮겨 연다.
같은 주소를 **웹에도** 둔다(`/org/open` · `/org/lost` 웹 페이지) — PC 웹 알림 목록에서 누르거나, 아직 새 화면 묶음을 안 받은 옛 앱이 웹으로 열 때 404 가 나지 않게:
마스터 계정은 `/manage`, 선수는 '앱에서 열어 주세요' 안내, 옛 앱(앱 UA)은 `/today`.

### 8-5. 상태 · 권한 · API

**앱 상태**
- 마지막 공간은 로그인한 사람마다: `bullpen-space:<userId>` = `'me'` 또는 `<orgId>:p|c`. 로그아웃(`resetAccount`)이 다른 계정 것까지 지우지 않아도 열쇠가 사람마다라 섞이지 않는다.
- 조직 공간의 탭 · 쌓인 화면 상태는 공간마다 따로(공간 열쇠별 마지막 탭). 내 싱커의 탭 · 종목 바(`sportOfPath`) 상태와 섞지 않는다 — 조직 공간에 있는 동안 내 싱커 상태는 손대지 않는다.
- 켤 때 · 다시 로그인할 때: 저장된 공간을 `loadMySpaces` 응답(서버 권한)으로 확인한 뒤에만 연다. 확인 전에는 같은 사람의 받아 둔 목록으로 탭 모양만 먼저 그리고, 내용은 각 화면이 서버에서 받는다.
- 잃었을 때: 선수 → 내 싱커 + "○○ 공간을 더는 볼 수 없어 내 싱커로 왔어요". 마스터 → 다른 관리 조직이 있으면 그것(첫째), 없으면 '조직 없음' 화면. **마스터에게 내 싱커를 대신 열지 않는다.**
- 다시 확인하는 때: 앱이 앞으로 올 때 · 공간을 바꿀 때 · 조직 동작이 '권한 없음'을 돌려줄 때 · 알림을 눌렀을 때.
- 껍데기: 조직 공간에 있는 동안 웹이 보내는 막대 알림(`tabs` · 웹 창 앞 · 체크인 막대 끔 · 주소)은 내 싱커 상태에만 적고 조직 아래 탭은 바꾸지 않는다. 내 싱커 덮개(홈 · 투구 · 트레이닝 · 영양)는
  조직 공간에서는 그리지 않는다. 웹뷰는 그대로 붙어 있어 돌아오면 그 자리다.
- 마스터 계정: 내 싱커가 없으니 껍데기가 웹뷰에 개인 화면(`/today` → `/manage` 돌아가기)을 싣지 않고 조직 공간부터 연다. 웹뷰는 '덕아웃 열기' 같은 명시 링크에만 쓴다.
- 받아 둔 값 · 안 읽은 수 · 늦게 온 답은 사람 + 조직 열쇠로만: `useLoad` 열쇠에 늘 `orgId` · `memberId` 를 넣는다(지금 그렇다) · 안 읽은 수(받은 것 · 공지)는 공간 열쇠별 ·
  공간을 바꾸면 앞 공간 화면이 내려가 늦게 온 답은 버려진다(`alive` · `latest`). 앞 공간에서 끝난 쓰기의 알림 글에는 조직 이름을 붙인다("○○에 저장했어요").
- 쓰던 글: 고르개는 탭 첫 화면에만 있고 쓰기 화면(일지 · 숙제 · 메뉴 · 수행일지 · 공지 · 일정 · 말)은 그 위에 쌓이므로, 고르개로 바꾸다 쓰던 글이 걸리는 일은 없다.
  걸리는 때는 둘 — ① 쓰는 중에 다른 조직 알림을 누름 → "저장 안 한 내용이 있어요" [머무르기 · 버리고 옮기기](S단계 — 남겨 두기는 나중에: 남긴 글을 (사람 · 조직 · 화면 · 대상) 열쇠로 폰에 두고 같은 조직의 같은 화면을
  다시 열면 되살린다) ② 쓰는 중에 그 조직 권한을 잃음 → 화면을 걷지 않고 저장만 막고("이 조직에 더는 쓸 수 없어요") 글은 고를 수 있게 둔다. 폰에 둔 글은 다른 계정이 로그인하면 지운다
  (구속 세션 `dropDraftNotOf` 와 같은 규칙). 글은 연 때의 `orgId` 를 쥐고 저장도 그 `orgId` 로만 — **바뀐 공간으로 몰래 보내지 않는다.**

**서버 · API**
- 앱이 고른 `orgId` 는 권한이 아니다. 모든 조직 동작은 지금처럼 부를 때마다 `coachOrg` · `myMember` 로 다시 본다(1~3단계 시험이 지킨다).
- 지난 소속(LEFT)은 받은 일지 읽기만: **선수 쓰기 동작은 모두 `status === 'ACTIVE'` 를 본다.** 지금 빠진 곳 — `app-lesson.ts markMyHomework` · `homeworkToToday`(떠난 회원도 숙제를 바꾸거나
  오늘 운동에 넣을 수 있다), `loadMyHomework` 는 떠난 회원에게 빈 목록. S단계에 고치고 org:test 에 '선수 쓰기 동작은 ACTIVE 확인' 소스 시험을 더한다.
- `loadMySpaces` 모양: `spaces` = 지금 소속만(고르개), `former` = 떠난 소속(소속 관리 '지난 소속'), `hasSinker` 그대로. 서버에 '마지막 공간'은 두지 않는다(2-1 표의 `last` 는 뺌).
  모양이 바뀌므로 `scripts/native-api-shapes.json` 을 갱신하고, 옛 앱 판이 `left` 를 읽는 곳이 없는지 본다.
- 권한 없음 답: 조직 동작의 `NO_ACCESS`(`{ ok: false, to: '/today' }`)는 앱 `useLoad` 가 `leaveTo('/today')` 로 쌓인 화면을 다 걷고 웹 홈을 연다(마스터는 거기서 다시 `/manage` → `/org`).
  조직 동작은 `{ ok: false, to: '/org/lost' }` 를 돌려주고, 껍데기의 웹 주소 가로채기(`nativeOfWeb`)가 그 주소를 웹으로 보내지 않고 받아 공간을 다시 확인해 위 '잃었을 때'대로 옮긴다.
  서버가 먼저 배포되므로 옛 앱이 받으면 웹 `/org/lost` 페이지가 받는다(8-4).
- 마스터 계정은 선수 초대 코드를 못 쓴다(`lib/org/join.ts` 에 한 줄, 오류 글 '선수 코드는 선수 계정으로 넣어 주세요') · `loadMySpaces` 는 마스터 계정의 선수 소속을 안 돌려준다.
- 알림 주소: `app-lesson.ts` · `app-team.ts` · `org-notes.ts` · `lessons.ts`(예약 확정 알림)의 조직 알림 `link` 를 8-4 주소로. 알림 목록 · 종의 안 읽은 수는 그대로(사람 단위).
- 공간을 바꿔도 기록은 복사하지 않는다: 내 싱커는 내 모든 기록, 조직 공간은 그 조직 · 역할에 허락된 것만(`memberScope`). 내 훈련의 '코치가 남긴 수행'은 내 운동 세트(`orgEventId` 가 그 조직 일정)를

### 8-7. 받아들임 시험(S단계 관문)

2. 내 싱커 → 레슨장 → 팀: 레슨장 회원 탭(홈 · 레슨일지 · 숙제 · 더보기) → 팀 선수 탭(오늘 · 일정 · 내 훈련 · 더보기)으로 정확히 바뀜.
3. 바꾸기 · 돌아오기는 소속 · 공유 · 역할을 안 바꿈: 소스 시험 — 고르개 · 공간 상태 코드가 `leaveOrg` · `saveConsent` · `joinOrgApp` 를 부르지 않음, 폰 — 바꾸기 앞뒤 회원 · 공유 줄 같음(공지 읽음처럼 화면을 볼 때 남는 기록은 별개).
4. 여러 조직 · 다른 역할: 선수 계정은 모든 조직에서 선수/회원 탭만, 마스터 계정은 코치 탭만, 관리자는 내 싱커 + 관리 조직.
5. 마스터: 조직 하나 → 바로 그 조직 코치 탭 · 고르개에 내 싱커 없음 / 여럿 → 고르개에 관리 조직만 / 없음 → '조직 없음' 화면, 어디서도 내 싱커가 안 열림.

7. 잘못 저장된 공간으로 다시 켬(나간 조직 · 다른 계정 열쇠 · 지운 조직): 내용을 그리기 전에 확인 · 6과 같은 대로 옮김.
8. 요청 중 · 쓰던 글이 있을 때 바꾸기: 앞 공간의 늦은 답이 새 공간 화면을 안 덮음 · 쓰던 글은 [남겨 두고 옮기기 · 머무르기]를 묻고 남긴 글은 원래 조직에서만 되살아남 · 새 공간으로 보내지는 일 0.
9. 다른 조직 · 지난 소속을 가리키는 알림: 지금 소속이면 그 공간으로 옮겨 열림, 지난 소속은 받은 일지만 읽기, 그 밖은 "이제 볼 수 없는 소식이에요".
10. 조직 사이 새는 것 0: A 조직 공간에서 B 조직 회원 · 일지 · 안 읽은 수가 안 보임(받아 둔 값 열쇠 · RPC 응답 모두).
11. 개인 기록 · 운동 · 부하가 두 번 안 생김: 공간을 몇 번 바꿔도 운동 판 · 투구 기록 · 부하가 같음, 숙제에서 연 운동은 개인 기록 한 줄.
12. 싱커 조직 탭에 예약 · 수강권 · 결제 단추 0(소스 시험: 조직 탭 · 더보기 화면에 그 동작 이름이 없음, 덕아웃은 '덕아웃 열기' 링크만).
13. 내 싱커 탭 · 종목 바 그대로: 홈 · 덕아웃 · 투구 · 타격 · 더보기, 투구 · 타격 안 종목 바 · 잠금 · 판 넘기기가 S단계 앞과 같음.
14. 떠난 회원의 쓰기 0: 떠난 뒤 숙제 바꾸기 · 오늘 운동에 넣기 · 말 · 영상 · 참석 응답이 모두 막힘.
15. 마스터 계정이 선수 초대 코드를 넣으면 막힘 · 마스터의 고르개에 선수 공간 0.

### 9-3. 공간 셸 — 싱커 한 틀로(새 로고 · 새 디자인 체계 없음)

- **머리 한 줄**: 왼쪽 싱커 이름표(`native/src/shell/wordmark.tsx` 를 홈 머리보다 작게) · 가운데 고르개 두 줄(위 조직 이름 ▾, 밑 작은 글 '팀 · 대표') · 오른쪽 알림 종(내 알림, 같은 `useUnreadNotifications`).
  내 싱커 홈 머리와 같은 자리 · 높이 · 굴리면 접힘. 지금처럼 이름 · 역할 · 고르개가 세 줄로 떨어지지 않는다.
- **카드**: 설정 목록처럼 '묶음 하나 = 카드 하나, 안은 줄'(`settings-list` 꼴). 그림자는 머리 카드 하나만, 나머지는 평평. 한 줄짜리 정보를 카드 하나로 세우지 않는다.
- **빈 상태**: 묶음에 한 줄 + 다음 할 일 단추 하나('+ 첫 일정' · '선수 초대 코드 보내기'). 같은 화면에 빈 카드를 셋 이상 쌓지 않는다.
- **글자 · 간격**: 지금 `TYPE` 토큰 그대로. 큰 글씨에서 줄이 넘치면 줄바꿈(높이 고정 없음). 테마 셋 · 안전 영역 · 탭 막대 누름은 그대로.

### 9-4. 팀 관리자 화면 구조(탭은 8-3 그대로 — 오늘 · 일정 · 훈련 · 선수단 · 더보기)

**오늘** — 위에서 아래로, 숫자는 모두 눌러서 그 목록으로(거른 선수단 · 그 일정). 자료가 없으면 0 대신 그 칸을 안 그린다.
1. 오늘 일정 줄(여럿이면 차례로): 시각 · 이름 · 응답(가요 n · 못 가요 n · 답 안 함 n) · 메뉴(있음 / '메뉴 만들기') · 끝났으면 수행일지(남김 n / 참석 n). 없으면 '오늘 일정이 없어요 · + 일정' 한 줄 + 다음 일정 하나.
2. 살필 선수(묶음 넷, 있는 것만): **주의 · 위험**(기록으로 판정, 까닭 한 줄) · **기록 부족**(최근 7일 투구 없음 · 체크인 안 함 — 정상으로 안 보임) · **투구 기록 비공개** · **앱 연결 대기 · 공유 동의 대기**.
3. 받은 것: 질문 · 정정 요청 · 숙제 영상 · 안 본 수행 보고(9-6) — 줄을 누르면 그 기록과 말 화면(C).
4. 빠른 일: + 일정 · 훈련 준비(가까운 일정의 메뉴) · 투구 기록 적기.

**일정** — 위 한 주 띠(일곱 칸 작은 날짜, 일정 있는 날 점) + 밑 그 주 일정 목록(날짜 머리 + 줄). 빈 날은 안 그린다. '+ 일정' 하나(날짜는 띠에서 고른 날).
**훈련** — S단계 그대로(다가오는 · 지난 2주), 줄에 '메뉴 없음'은 경고색 대신 '메뉴 만들기' 글 단추.
**선수단** — 위 거르개 칩(전체 · 살필 · 기록 부족 · 비공개 · 연결 대기) + 줄(이름 · 태그 · 상태 한 단어) · '+ 선수 등록'. 오늘의 숫자가 이 칩으로 들어온다.
**더보기** — 초대 코드(선수 · 코치, 코치 코드가 없으면 '코치 초대 코드 만들기' 한 줄) · 공지 · 덕아웃 열기 · PC 안내 · 설정 · (마스터) 계정.

### 9-6. 고칠 것 — 세 묶음

**① 자료 정확성 · 오해 부르는 상태**(먼저)
1. A: `loadOrgToday` 가 묶음 넷(주의 · 위험 / 기록 부족 / 비공개 / 연결 · 동의 대기)을 돌려준다 — 정보 부족은 '정상'으로 안 셈. DB 변경 없음.
2. B: 숙제 뜻을 넷으로 — **실제 기록**(처방 세트 · 횟수 · 초를 채운 세트, 숙제를 낸 **시각** 뒤, 코치 대신 세트 제외, 증거 = 세트 id) · **선수 보고**('했어요') · **영상 제출** · **코치 확인**.
   자동 완료는 첫째만. 화면은 '기록으로 완료' / '선수가 했다고 함' / '영상 받음' / '코치 확인'을 따로 보인다. DB: `OrgAssignment` 에 `reportedAt` · `submittedAt` · `reviewedAt` · `reviewedById` · `evidence Json`(더하기만 — AGENTS 2번 절차 · 금윤호와 먼저).
3. C: 알림 · 받은 것 주소에 기록 번호 — `orgOpenHref(org, side, target, recordId)`, 대상 `note` · `homework` · `event` · `comment`. 앱에 일지 하나 · 숙제 하나 · 일정 하나(선수용) 화면, 열 때 그 조직 · 회원 것인지 서버가 확인. DB 변경 없음.
4. D: 공지 읽음 = **열어 봄**. 목록은 제목 + 두 줄, 누르면 공지 화면 → 그때 읽음. 코치 '열어 본 선수 n/m(앱 연결된 선수)'. 중요한 공지의 '확인했어요'는 나중 결정(9-8).

### 10-4. 권하는 첫 판 — 한 흐름(준비 → 배정 → 선수 확인 → 실제 수행 → 코치 검토 → 다음 계획)

1. **훈련 보드(A)** — 새 기능이 아니라 `OrgPlan` 을 블록으로 넓힌다. 블록 = 시간(또는 길이) · 목적 · 운동 · 드릴 · 대상(조 = 태그에서 골라 그 순간의 명단을 담음) · 담당 코치 · 장소 이름 · 안내 · 영상 하나.
   선수는 내 블록만 순서대로, 코치는 전체를 본다. 끝난 뒤는 ③ 그대로(선수 '운동하기' → 잇기, 코치 '메뉴대로'는 선수 기록이 있으면 멈춤, 참석 확인은 따로).
2. **다시 쓰기(B 일부)** — '지난 일정에서 블록 가져오기' · '이 주를 다음 주로 복사'. 복사는 새 계획일 뿐 — 참석 · 등판 · 수행은 안 옮기고, 원본을 고쳐도 복사본 · 지난 기록은 그대로.
3. **오늘 브리핑(D)** — 코치 오늘에 줄 셋을 더한다(있을 때만): 다가오는 7일에 답 안 한 선수가 있는 일정 · 확인 대기(선수가 이은 수행 · 선수가 했다고 한 숙제 · 받은 영상) · 연결 · 동의 대기(이미 '살필 선수'). 줄마다 원래 자리로 가고, 원래 일을 처리하면 빠진다.

까닭: ①~③으로 고친 흐름 위에 표 바꿈을 가장 적게 얹고, 팀 코치가 매주 되풀이하는 일(훈련 준비 → 선수에게 알리기 → 끝나고 확인)을 한 번에 닫는다. 이름 템플릿 · 담당은 이 흐름이 돌아간 뒤에 '같은 주를 또 짠다', '누가 답하지' 같은 실제 불편이 보이면 붙인다.

### 10-5. 미루기 · 빼기

- 1.5: 이름 붙은 템플릿(B 나머지 — 비 오는 날 실내 · 비시즌 주).
- 2: 담당 · 기한(C, 코치 셋 넘는 팀에서 필요가 보이면), 시즌 기간(H).
- 4단계: 집중 프로젝트(E) — 측정 기록 · 견주기가 생긴 뒤.
- 빼기: 플레이북 · 지도 자료(F, 김민 결정 — 조직 자료함을 따로 두지 않고 블록 안내 · 영상, 일지 · 숙제 글로 전한다), 멘토링 조(G) — 선수끼리 보는 공개 모델이 따로 필요하고 쓸모보다 위험이 크다. 경기 기록 · 라인업 · 이적 · 계약 · 능력치는 하지 않는다.

### 10-6. 흐름 셋

1. **팀 화요일 훈련** — 대표가 PC 에서 화요일 훈련 보드: 워밍업 10분(전원 · 운동장) → 투수조 불펜 30분(코치 B · 불펜장 · 안내 영상) / 야수조 내야 수비 30분(대표 · 내야) → 정리 10분(전원).
   2일 안이라 선수에게 '훈련 메뉴가 올라왔어요'. 투수 A 는 앱 일정 하나에서 워밍업 · 불펜 · 정리만 순서대로 본다. 당일 '가요' · 참석 확인은 수행이 아니다.
   훈련 뒤 A 는 '운동하기'로 처방 운동을 하고 이어진다. 코치 오늘에 'A 선수 기록 · 확인 대기' → 코치가 보고 참석 확인 · 필요하면 말. 금요일 훈련은 '지난 일정에서 가져오기'로 만들고 고친다.
2. **비 오는 날** — 코치가 실외 훈련을 열고 '지난 일정에서 가져오기'로 지난주 실내 보드를 덮어씀 → 대상 선수에게 '훈련 메뉴가 바뀌었어요'. 이미 남긴 수행 · 참석은 안 바뀐다.
3. **레슨장 단체 수업** — 토요일 소그룹 수업을 '이 주를 다음 주로 복사'로 반복. 회원은 내 블록(드릴 · 안내 영상)을 보고, 개인 숙제 · 일지는 지금처럼 따로. 코치 오늘의 '확인 대기'에 숙제 영상 · 했다고 한 숙제가 모인다.

## 11. 팀 훈련 — 전체 → 조 → 예외(2026-10-26 개정, 팀 공간의 기본 흐름 · 설계만)

김민 결정: 팀은 대부분 다 같이 훈련한다. 코치는 **훈련 하나를 한 번 적고, 참여나 수행이 달랐던 선수만 고친다.** 확인된 결과는 선수마다 개인 기록에 들어가고,
선수는 코치가 이미 적은 훈련을 다시 적지 않는다. **팀 공간에만** 해당한다 — 레슨장은 지금처럼 회원 한 명 중심(일지 · 숙제)이다.
이 절을 쓰는 동안 코드 · DB 는 바꾸지 않았다. 선수 한 명씩의 숙제 · 성장 계획은 보조 기능으로 남는다(기본 매일 흐름이 아님).

### 11-1. 선수별 흐름에서 바뀌는 것

| 지금(1~3단계 · 9 · 10절 구현) | 바뀜 |
| --- | --- |
| 일정 하나에 메뉴 여러 개(`OrgPlan`), 대상이 비면 **볼 때마다** 그 팀의 활동 선수 전부(`eventMemberIds` · `planMemberIds`) — 명단이 나중에 바뀌면 지난 일정 대상도 바뀐다 | 훈련 하나 = **전체 활동 · 조 활동 · 개인 더하기/바꾸기**. 대상 명단은 훈련을 준비할 때 **그 순간의 명단을 담아 고정**한다(11-4). 조 · 명단이 나중에 바뀌어도 지난 훈련 대상 · 기록은 그대로 |
| 기록은 선수마다 '메뉴대로' · '고쳐 적기' · '빼기'(`recordWork`). 한꺼번에는 '참석한 선수 모두 메뉴대로'(`recordAttendedAsPlan`) — 누르면 **참석 확인한 선수 모두를 계획대로 했다고** 남긴다. 조가 실제로 다르게 한 것 · 선수 예외를 한 화면에서 고칠 곳이 없다 | 조마다 **'실제로 한 것'을 한 번 확인**하고, 예외(빠짐 · 일부 참여 · 줄임 · 다른 운동 · 더 함)만 고친다. 참석 · 계획은 출발점일 뿐 — 코치가 '확인'을 눌러야 개인 기록 · 부하에 들어간다 |
| 한꺼번에 저장의 답은 숫자만(`done` · `skipped` · `own`) | **선수마다 결과**(기록함 · 내 기록으로 맞춤 · 확인 필요 · 남길 수 없음(까닭) · 실패) — 실패한 선수만 다시 보내고, 성공한 선수는 다시 써도 같은 결과 |
| 같은 날 같은 메뉴 운동이 선수에게 있으면 '메뉴대로'가 멈춤(`ownSetsOn` — 일정에 이었든 아니든) | **일정에 이은 선수 기록**이면 그 운동은 선수 기록으로 맞춘다(코치 세트 안 씀). 일정과 **안 이은** 같은 날 같은 운동은 합치지도 그냥 막지도 않고 '확인 필요' — 선수에게 묻는다(11-6) |
| 고침은 선수마다 다시 기록 | 조 실제를 고치면 **예외 없는 선수에게 다시 퍼진다**. 예외가 있는 선수는 바꾸지 않고 '조 기록이 바뀌었어요 — 예외 다시 보기' 표시 |
| 같은 운동이 두 메뉴에 있으면 앞 메뉴 것만(`planWork`) | 서로 다른 활동의 같은 운동은 **둘 다 실제**(워밍업 런지 · 근력 런지). 한 선수의 개인 '바꾸기'만 그 조 활동을 대신한다 |
| 선수가 코치 기록을 고쳐 달라고 할 길이 팀에는 없음(`OrgComment.eventId` 칸 대기) | 기존 말(`OrgComment` 'fix' 정정 요청)을 그 훈련에 달 수 있게(칸 하나) — 코치 받은 것으로 |
| 10-10 1 '조 = 태그로 충분한가' | **태그로 고르고, 그 순간 명단을 담는다**(따로 조 표 없음). 태그가 없으면 직접 고른다 |

10절 훈련 보드(A)의 '블록'이 이 절의 **활동**이다 — 보드 칸(10-8)과 이 절의 칸은 한 마이그레이션으로 같이 더한다(11-4).

### 11-2. 낱말

- **훈련** — 팀 일정(`OrgEvent`, 종류 training) 하나.
- **활동** — 훈련 안의 한 덩어리(`OrgPlan` 한 줄). 대상이 **전체** · **조** · **개인** 셋 중 하나. 개인 활동은 '더하기'(남들이 안 하는 것을 더 함) 또는 '바꾸기'(그 선수만 어떤 조 활동 대신).
- **조** — 태그(투수 · 야수 · 1학년 …)로 고른 선수 묶음. 훈련마다 명단을 담는다.
- **계획** — 활동의 처방(운동 · 드릴 · 세트 · 횟수 · 초). **실제** — 코치가 확인한 그 활동의 실제 수행(조 공통). 처음엔 계획으로 미리 채워진다.
- **값을 선수마다 받는 활동** — 투구(불펜 투구 수 · 강도 · 구속)와 측정. 조 공통값이 없다. 같은 값을 조 전체에 넣지 않는다.
- **예외** — 한 선수만 다른 결과: 빠짐 · 일부 참여(어느 활동까지 했나) · 줄임(세트 · 횟수 · 초를 고침) · 다른 운동(그 활동 대신 한 것) · 더 함.
- **확인** — 코치가 '이대로 확인'을 누른 상태. 이때만 선수 개인 기록 · 부하에 들어간다.

### 11-3. 흐름 — 준비 → 당일 → 실제 확인 → 결과 → 고침

**① 준비** — 코치 오늘의 '오늘 팀 훈련 준비'(오늘 훈련이 없으면) 또는 '지난 훈련 다시 쓰기'(지금 `copyPlansFrom` · `copyWeek`).
1. 훈련을 만들면 그 순간의 활동 선수를 명단으로 담는다(나중에 들어온 선수는 코치가 더할 때만).
2. 활동을 차례로 쌓는다: 전체 워밍업 → 투수조 불펜 / 야수조 수비 → 전체 근력. 조는 태그 칩을 눌러 고르고(그 태그의 지금 선수가 담김), 손으로 더하거나 뺄 수 있다.
3. 개인 더하기 · 바꾸기: 선수를 누르고 '이 선수만 바꾸기'(예: 재활 선수는 근력 대신 밴드 루틴) · '이 선수만 더하기'.
4. 운동 · 드릴 고르기는 지금 고르개(`native/src/org/picker.tsx` · `components/master/library-picker.tsx`), 알림은 지금 규칙(2일 안 일정만, `tellPlan`).

**② 당일** — 참석 응답 · 참석 확인은 지금 그대로(`replyEvent` · `setAttended` · `markAllAttended`). **참석만으로는 아무 기록도 안 생긴다.**

**③ 실제 확인**(끝난 훈련, 오늘까지) — 훈련 화면의 '실제 확인' 단계. 활동마다 카드 하나:
1. **조 실제**: 계획으로 미리 채운 세트 · 횟수 · 초. 실제로 다르게 했으면 여기서 한 번 고친다(예: 비로 근력 3세트 → 2세트). 무게는 조 공통으로 채우지 않는다(선수마다 다름 — 비워 두면 '무게 모름', 적고 싶으면 그 선수 예외에서).
2. **명단**: 그 활동 대상 선수 줄. 기본은 '조와 같음'. 참석 확인에서 '안 왔어요'인 선수는 '빠짐'으로 미리 표시(확인 전이라 바꿀 수 있음). 참석 확인을 안 했으면 모두 '조와 같음'으로 미리 채운다.
3. **예외**: 선수 줄을 눌러 [빠짐 · 일부 참여 · 줄임 · 다른 운동 · 더 함] + 까닭 한 줄(선택). 일부 참여는 '어느 활동까지 했나'를 고르면 나머지 활동이 빠짐으로 바뀐다.
4. **값을 선수마다 받는 활동**(불펜): 선수별 칸만(투구 수 · 강도 · 구속 — 지금 투구수표 `createPitchLogs` 와 같은 검사). 비우면 그 선수 투구는 안 남기고 결과에 '투구 수 안 적음'.
5. **확인 단추 하나**: 화면 아래 '이대로 확인 — 같음 20 · 예외 5'. 누르면 그 훈련의 모든 활동 · 모든 대상 선수에 한 번에 적용한다. 한 선수씩 같은 폼을 내지 않는다.

**④ 결과** — 확인 뒤 선수마다 한 줄(11-5 상태). 실패만 '다시 보내기'(실패한 선수만). 남길 수 없는 선수는 까닭(앱 연결 대기 · 트레이닝 비공개 · 투구 비공개 · 팀을 떠남)과 함께 남고,
코치 오늘의 '확인 대기'에 '기록을 마치지 못한 훈련'으로 올라온다.

**⑤ 고침** — 확인한 뒤에도 실제 · 예외를 고칠 수 있다. 다시 '이대로 확인'을 누르면 바뀐 선수만 다시 쓴다(같은 내용인 선수는 안 건드림). 바뀐 선수에게 '팀 훈련 기록이 바뀌었어요' 한 번.
훈련 취소 · 지우기는 지금 결정 4 그대로 — 남긴 기록이 있으면 '기록도 뺄까요'를 묻는다(기본 두기).

### 11-4. 데이터 — 다시 쓰는 것 · 더할 것(제안, 바꿀 때 AGENTS 2번 · 금윤호와 먼저)

**그대로 다시 쓴다**

**선수 한 명의 실제를 만드는 규칙**(순수 함수 하나, `lib/org/team.ts` — 시험이 본다)
1. 그 선수가 대상인 활동마다(담은 명단 기준): 예외가 없으면 조 실제, '줄임' · '다른 운동'이면 예외에 적은 것, '빠짐'이면 없음. 개인 '바꾸기'는 대신하는 활동을 빼고 그 활동을 넣는다.
2. 운동만 개인 운동 기록이 된다(지금 규칙 — 드릴은 세트가 아니다). 드릴 활동은 결과 화면 · 선수 기록 카드에 '함'으로만 보이고 부하에 안 든다.
3. 서로 다른 활동의 같은 운동은 둘 다 센다(세트가 이어 붙음 — `cleanOrgWork` 가 한 줄로 합치고 세트 번호는 지금처럼 이어짐).
4. 일정에 이은 선수 기록이 있는 운동은 그 운동을 빼고 '맞춤'으로(11-6).
5. 결과 → `writeOrgWork`(그 선수 · 그 훈련의 코치 세트를 통째로 바꿈) + 값을 선수마다 받는 활동은 `PitchLog`(열쇠로 고침 · 비면 지움). 선수마다 따로 처리한다 — 한 선수가 실패해도 다른 선수는 그대로.

### 11-5. 권한 · 잇기 · 정정 규칙

**권한**(지금 규칙 그대로 — 모든 동작이 `coachOrg` · `myMember` 부터)
- 쓰기는 대표 · 코치만. 선수 개인 기록에 남기는 조건도 지금과 같다: 앱 연결(`userId`) · 트레이닝 공유(운동) · 투구 공유(투구) · ACTIVE.
- 남길 수 없는 선수도 명단 · 예외 · 결과에는 남는다(코치가 무엇을 했는지는 팀 기록). 개인 기록 · 부하에만 안 들어간다. 결과의 까닭: `not_linked`(앱 연결 대기) · `training_private` · `pitch_private` · `left`.
  나중에 공유를 켜도 저절로 옮기지 않는다(계정 잇기 전 일지와 같은 뜻 — 결정 9). 코치가 그 훈련을 다시 '이대로 확인'하면 그때 쓴다.
- 선수는 **제 결과만** 받는다 — 다른 선수 이름 · 예외 · 값은 서버가 안 보낸다. 선수가 보는 활동은 전체 + 제 조 + 제 개인 활동(다른 조 활동은 안 보냄, 10-9 1 과 같음).

**잇기 · 두 번 세지 않기**

| 경우 | 처리 |
| --- | --- |
| 선수가 그 훈련에서 '운동하기'로 하고 일정에 이었다(선수 세트, `orgEventId` = 그 훈련) | 그 운동은 **선수 기록으로 맞춤** — 코치 세트를 안 쓴다(결정 3 선수 기록 우선). 결과 '내 기록으로 맞춤' |
| 선수가 그날 같은 운동을 따로 남겼는데 일정에 안 이었다 | **합치지 않고 막지도 않는다.** 그 운동만 '확인 필요'로 두고 코치 세트를 안 쓴다. 선수에게 '오늘 ○○가 팀 훈련이었나요?' [팀 훈련에 잇기 → 맞춤 · 따로 한 운동이에요 → 팀 기록도 남김]. 코치도 결과 줄에서 같은 둘을 고를 수 있다(지금 'plan-anyway') |
| 코치가 같은 확인을 다시 보냄 · 신호 끊김 뒤 다시 | `writeOrgWork` 통째 교체 + 투구 열쇠 — 몇 번 보내도 한 벌. 지문이 같으면 아예 안 씀 |
| 실제 · 예외를 고침 | 바뀐 선수만 다시 씀 · 그 선수의 코치 세트가 새 내용으로 바뀜(늘지 않음) |
| 훈련 취소 · 지우기 | 결정 4(기록도 뺄까요, 기본 두기) — 빼면 `clearEventWork` · 투구 열쇠 줄 지움 |
| 조 활동 + 개인 활동이 겹침 | '바꾸기'는 대신, '더하기'는 더함. 같은 운동이 두 활동에 있으면 둘 다 실제(11-4 규칙 3) |
| 같은 날 다른 훈련 · 개인 운동의 같은 운동 | 서로 다른 활동이라 따로 둔다(같은 운동 · 같은 날이라는 것만으로 합치지 않음) |

**정정**
- 선수는 다시 확인하지 않는다. 기록 카드의 '고쳐 주세요'로 정정 요청(`OrgComment` 'fix', `eventId`) → 코치 받은 것 · 훈련 화면 결과 줄에 표시.
- 코치가 그 선수의 예외를 고쳐 다시 확인하면 요청이 풀리고 선수에게 알림. 고칠 때까지 기록은 그대로(지우지 않음).
- 선수가 제 운동 화면에서 코치 세트를 직접 지우는 길은 없다(지금 그대로 — 코치 세트는 코치 것). 투구 기록은 지금처럼 선수가 제 화면에서 고칠 수 있다.

### 11-6. 화면

**코치**(지금 탭 그대로 — 오늘 · 일정 · 훈련 · 선수단 · 더보기. 새 위쪽 탭 없음)
- **오늘**: 오늘 훈련이 없으면 '오늘 팀 훈련 준비' · '지난 훈련 다시 쓰기' 두 단추. 있으면 오늘 훈련 줄에 단계(계획 · 오늘 · 확인 대기 · 확인함) · 결과 수(남길 수 없음 n · 확인 필요 n).
  브리핑 '확인 대기'(10-12)에 '실제 확인 안 한 훈련' · '확인 필요 선수' · '정정 요청'을 더한다(원래 일을 처리하면 빠짐).
- **일정 › 훈련 하나**(`org/team-event`): 위에 단계 띠 [계획 · 참석 · 실제 확인 · 결과]. 계획 = 전체 · 조 · 개인 활동(조 이름 · 인원), 실제 확인 = 활동 카드 + 아래 확인 단추, 결과 = 선수 줄(상태 · 까닭 · 다시 보내기).
  등판은 지금 칸 그대로(경기 일정만).
- **훈련**: 지난 · 다가오는 훈련 목록(지금 `loadTeamTraining`)에 '실제 확인 안 함' · '확인 필요 n'.
- **선수단 › 선수 카드**: 그 선수의 팀 훈련 결과 목록(제 예외 · 상태).
- PC `/manage/calendar/[id]`: 같은 단계. 긴 명단의 예외 고치기 · 조 짜기는 PC 가 편하다.

**선수**(오늘 · 일정 · 내 훈련)
- **일정 하나**(`org/my-event`): 내가 할 활동(전체 · 내 조 · 내 개인) 차례로. 끝나고 코치가 확인하면 '팀 훈련 기록 · 코치 확인' 카드 — 내가 한 것(내 결과), 출처(팀 · 훈련 · 적은 코치 · 확인 시각), '고쳐 주세요'.
  '확인 필요'면 그 운동에 '팀 훈련이었나요?' 두 단추. 지금 '운동하기' · '내 기록 잇기'는 그대로(코치가 확인하기 전에 스스로 한 선수용).
- **내 훈련**: '최근 팀 훈련 기록'(지금 `recent` — 코치가 남긴 내 수행) 줄에 확인 상태.
- **내 싱커**: 개인 운동 기록 · 달력 · 부하는 지금처럼 하나(코치 세트는 그날 판 안 '팀 · 레슨장 운동'). 다시 적을 것 없음.

### 11-7. 예: 25명 팀의 화요일 훈련(숫자는 예 — 팀 크기를 박아 두지 않는다)

팀 25명(태그 투수 10 · 야수 15). 훈련 '화요일 팀 훈련'.

**준비** — 코치가 오늘 '오늘 팀 훈련 준비' → 명단 25명이 담김(`rosterAt`). 활동 넷:
A 전체 워밍업(25): 밴드 외회전 2×15 · 워킹 런지 2×10 / B1 투수조 불펜(투수 10, 값은 선수마다) / B2 야수조 수비(야수 15): 펑고 · 중계 드릴 / C 전체 근력(25): 고블릿 스쿼트 3×8 · 덤벨 로우 3×10.
조는 '투수' · '야수' 태그 칩으로 골랐다. 2일 안이라 대상 선수에게 '훈련 메뉴가 올라왔어요'. 선수는 제 활동만 본다(투수: A · B1 · C, 야수: A · B2 · C).

**당일** — 응답 · 참석 확인. 23명 '왔어요', 2명(투수 K · 야수 L) '안 왔어요'. 이것만으로는 기록 0.

**실제 확인(한 번)** — 훈련 화면 '실제 확인': 활동 넷이 계획으로 미리 채워지고 K · L 은 '빠짐'으로 미리 표시. 코치가 고친 것 셋만:
- 투수 M · N: C 를 '줄임' — 고블릿 스쿼트 2×8 · 덤벨 로우 2×10(까닭 '어깨 피로').
- 야수 O: '일부 참여' — A 까지(병원). B2 · C 가 빠짐으로.
- B1 에 온 투수 9명의 투구 수를 칸마다(25 · 30 · 40 …) — 한 명은 비워 둠.

'이대로 확인 — 같음 20 · 예외 5'를 한 번 누른다.

**결과(선수마다)**

| 선수 | 개인 기록에 들어가는 것 | 결과 |
| --- | --- | --- |
| 같음 20명(투수 7 · 야수 13) | A 4세트 + C 6세트 = **코치 세트 10**(무게 모름) · 투수는 + 불펜 투구 1줄 · 야수 B2 는 '함' 표시만(드릴, 부하 안 듦) | 기록함 |
| 투수 M · N | A 4 + C 4 = **8세트** + 불펜 투구 | 기록함(예외: 줄임) |
| 야수 O | A **4세트** | 기록함(예외: 일부 참여) |
| 투수 K · 야수 L | 없음 | 빠짐 |
| 투구 수를 비운 투수 1명 | 세트는 그대로(같음이면 10) · 투구 없음 | 기록함 + '투구 수 안 적음'(그 칸만 다시 적으면 그 선수 투구만 남음) |

**선수가 보는 것** — 같음 투수 A: 일정 하나에 '팀 훈련 기록 · 코치 확인 — 워밍업 4세트 · 불펜 35구 · 근력 6세트, 기록 ○○ 코치 · 화 18:40'. 다시 확인할 것 없음.
내 싱커 트레이닝 달력의 그날 판에 '팀 · 레슨장 운동' 10세트, 투구 기록에 35구(코치가 적음). M 은 근력 4세트로 보인다. K 는 아무것도 안 생기고 일정에 '빠짐'. 남의 이름 · 결과는 아무도 못 본다.

**개인 합계** — 따로 셈하지 않는다. 같음 투수 A 의 그날 운동량 = 그날 판의 모든 세트(아침에 혼자 한 운동이 있으면 그 세트 + 코치 세트 10, 서로 다른 활동이라 합치지 않음)를
지금 요약(`summaryWrites` → `UserExerciseLog`)이 다시 셈하고, 투구 부하는 투구 기록(35구 × 강도)으로 지금 엔진이 셈한다. 팀 훈련이라고 다른 계산을 하지 않는다.

**선수가 먼저 적은 기록과 맞추기**
- 투수 P(같음 20 중 하나)는 훈련 중 일정 하나의 '운동하기'로 C 를 직접 적었다(선수 세트가 그 훈련에 이어짐). → C 는 P 의 기록으로 맞추고 코치는 A 4세트만 쓴다. 결과 '내 기록으로 맞춤'. C 를 두 번 세지 않는다.
- 야수 Q(같음 20 중 하나)는 아침에 집에서 고블릿 스쿼트 3×8 을 적었고 일정에 안 이었다. → 고블릿 스쿼트만 '확인 필요', 나머지(A · 덤벨 로우)는 씀. Q 에게 '오늘 아침 고블릿 스쿼트가 팀 훈련이었나요?'.
  '팀 훈련에 잇기'면 맞춤(코치 세트 안 씀), '따로 한 운동이에요'면 팀 스쿼트 3세트도 남김. 정할 때까지 코치 결과 줄에 '확인 필요 1'.
  (그래서 같음 20 = 기록함 18 + 맞춤 1(P) + 확인 필요 1(Q).)

**나중에 조 기록을 고침** — 다음 날 코치가 '비 때문에 근력은 모두 2세트였다'를 알고 C 실제를 2×8 · 2×10 으로 고쳐 다시 확인.
- 예외 없는 18명: 코치 세트 10 → 8 로 바뀜(늘지 않음, 통째 교체) · '팀 훈련 기록이 바뀌었어요' 한 번.
- P: C 는 P 의 기록이라 안 바뀜. Q: 덤벨 로우만 3 → 2세트, 고블릿 스쿼트는 아직 확인 필요.
- M · N: 예외(2세트)가 새 조 실제와 같아짐 — 값은 그대로, 코치 화면에 '조 기록과 같아졌어요 — 예외를 풀까요'. O · K · L: 그대로(C 를 안 함).
- 요약 · 부하는 바뀐 선수의 그날 판에서 다시 셈. 투구 수를 고치면 그 선수 투구 기록 한 줄이 고쳐진다(열쇠가 같음).

### 11-8. 지금 구현에서 다시 쓰는 것 · 빠진 것

### 11-9. 받아들임 시나리오(전용 시험 계정 · 순수 규칙 시험 — 운영 DB 에 자료를 심지 않는다)

1. **명단 고정**: 훈련을 준비한 뒤 선수 하나를 '투수'에서 '야수'로 바꾸고 새 선수가 들어와도, 그 훈련의 대상 · 조 명단 · 결과는 그대로.
2. **참석은 기록 아님**: 참석 확인 · 메뉴만 있고 '이대로 확인' 전이면 개인 세트 · 투구 · 부하 0.
3. **한 번 확인**: 11-7 처럼 같음 20 · 예외 5 를 한 번 눌러 선수마다 맞는 세트 · 투구가 생김. 한 선수씩 폼을 내지 않음.
4. **선수마다 값**: 불펜 투구 수는 적은 선수만 생김 · 비운 선수는 '투구 수 안 적음' · 조 전체에 같은 투구 수가 들어가는 길이 없음(소스 시험).
5. **일부 실패**: 같음 가운데 앱 연결 대기 1 · 트레이닝 비공개 1 · 쓰기 실패 1 → 결과 셋이 까닭과 함께 따로 · 다시 보내기는 실패 1명만 · 성공한 선수 세트는 늘지 않음.
6. **다시 보내기**: 같은 확인을 세 번(신호 끊김 흉내) → 선수마다 코치 세트 한 벌 · 투구 한 줄.
7. **선수 기록 맞춤**: 일정에 이은 선수 C 세트 → 코치 C 안 씀 · 부하 한 번.
8. **확인 필요**: 일정에 안 이은 같은 날 같은 운동 → 그 운동만 보류 · 합치지 않음 · 선수 '잇기'면 맞춤 · '따로'면 둘 다.
9. **조 실제 고침**: 예외 없는 선수만 바뀜 · 예외 있는 선수는 그대로 + '예외 다시 보기' · 바뀐 선수에게 알림 한 번.
10. **취소 · 지우기**: 결정 4 그대로(묻기 · 기본 두기 · 빼면 그 훈련의 코치 세트 · 투구 열쇠 줄만 지움, 선수가 이은 세트는 연결만 풂).
11. **겹침**: 같은 운동이 워밍업 · 근력 두 활동에 있으면 둘 다 셈 · 개인 '바꾸기'는 조 활동을 대신(둘 다 세지 않음).
12. **드릴**: 드릴 활동은 결과 · 선수 카드에 '함', 개인 세트 · 부하에는 0.
13. **선수 화면**: 선수는 제 활동 · 제 결과만(다른 선수 이름 · 예외 · 다른 조 활동이 응답에 없음). '고쳐 주세요' → 코치 받은 것.
14. **공유를 나중에 켬**: 훈련 뒤 트레이닝 공유를 켠 선수는 저절로 안 들어감 · 코치가 다시 확인하면 들어감.
15. **떠난 선수**: 확인 전에 떠난 선수는 결과 '팀을 떠남' · 지난 결과는 남음(선수 개인 기록도 그대로).
16. **레슨장 그대로**: 레슨장 공간의 일지 · 숙제 · 회원 화면이 이 변경 전과 같음.

### 11-10. 시간(Claude 기준) · 순서 · 정할 것

| | 서버 | 앱 | PC | 합 |
| --- | --- | --- | --- | --- |
| 전체 → 조 → 예외 | 10~14시간 | 14~18시간 | 6~8시간 | 30~40시간 |

순서: 표 칸 더하기(11-4 + 10-8 보드 칸, 한 마이그레이션 — 금윤호와 맞추고 백업) → 순수 규칙(선수 실제 · 맞추기 · 지문) + org:test → 서버 동작(준비 · 확인 · 결과 · 다시 보내기 · 확인 필요 풀기 · 정정) →
코치 앱(훈련 하나 단계 띠 · 활동 카드 · 결과) · 선수 앱(결과 카드 · 팀 훈련이었나요) → PC 같은 단계 → 11-9 시험 · 폰 확인(김민).

**정할 것(김민)** — 권고를 먼저 적는다.
1. 참석 확인을 안 했을 때 '실제 확인'을 모두 '조와 같음'으로 미리 채울지 — 권고: 채우고, 확인 단추에 '같음 n · 예외 m' 요약을 보인다(누르기 전에는 아무것도 안 씀).
2. 예외의 '줄임'을 그 선수의 실제 값으로(권고) 둘지, 조 실제에서 뺀 차이로 둘지 — 실제 값이면 조 실제를 고쳐도 그 선수 값이 안 흔들린다.
3. 무게를 조 공통으로 적는 길을 둘지 — 권고: 안 둠(선수마다 다름 · 비우면 '무게 모름').
4. 선수가 다른 조 활동을 흐리게라도 볼지 — 권고: 안 봄(10-10 2 와 같은 답).
5. 맡기: 서버 · PC 금윤호 · 앱 김민(7절과 같게).
