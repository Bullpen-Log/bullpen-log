## 세션 없이 열리는 것

`GET /api/intake/public/session`(정했는지 · 잠겼는지 · 이 기기 세션이 살아 있는지 — 이름은 안 줌), `POST session/enroll`, `POST session/unlock`, `POST session/end`. 나머지 공개 API(상태 · 초안 · 동의 · 칸 잡기 · 전송 토큰 · 업로드 주소 · 도착 확인 · 완료 · 결과)는 모두 `session_required` / `session_expired`(401).

## 수동 결과 묶음

```json
{
  "format": "intake-manual-result/1",
  "submissionId": "<선택>",
  "revisionId": "<선택>",
  "receiptCode": "<선택>",
  "sideSha256": "<지금 판 옆 원본의 서버 해시>",
  "rearSha256": "<지금 판 뒤 원본의 서버 해시>",
  "result": { "...": "lib/pitch-3d/v2/contract.ts Pitch3dV2Ok(ok:true)" }
}
```

매니페스트의 `manualTemplate` 이 접수마다 이 틀을 채워 준다(`result: null`). 파일 상한 960,000바이트(서버 동작 본문 1MB 안), 저장 결과 900KB. GLB · FBX · Blender 파일은 받지 않는다 — 지금 보기는 관절 움직임 보기라 따로 변환기가 필요하다.

막는 경우: 모양 · 판 · 유한 숫자 · 장면 · 관절 수가 틀림(`manual_result_invalid`), 해시가 지금 판과 다름 · 옆뒤 바뀜 · 다른 접수(`manual_result_mismatch`), 화면이 본 판이 지금 판이 아님(`manual_result_stale`), 검증 안 끝난 판(`manual_result_not_ready`), 손이 다름(`manual_result_hand`), 철회(`original_locked`). 실패하면 실행 줄이 안 생기고 쓴 파일은 지운다. 새 결과는 비공개 초안이고, 실행 수 · 마지막 실행이 바뀌어 앞서 남긴 검토 완료로는 공개할 수 없다. 지금 공개는 새 결과를 검토 완료 + 공개할 때까지 그대로다.

## 보유 · 보관(결정 대기)

90일 원본 삭제 규칙과 기존 보호(분석 중 · 고침 대기 등)는 바꾸지 않았다. 관리자 목록 · 상세 · 매니페스트에 서버 원본 삭제 예정일을 보이고, 내려받은 사본과 별개라고 적었다. **연구 보관(삭제 멈춤) 상태는 만들지 않았다** — 설계가 '사용자와 저장 · 삭제 범위를 확인한 뒤'로 둔 결정이라 GPT05 에 질의한다(납품 문서).

## 받는 사람 화면

관문 → 이름 · PIN 정하기 또는 다시 들어가기 → 촬영 안내(꼭 지킬 것 / 되면 좋은 것, 좌투 그림 뒤집기) → 선수 이름(처음 적은 이름으로 미리 채움) → 옆 · 뒤 원본(파일 칸 옆에 원본 고르는 법 · 메신저 사본 · 화면 녹화 · 자른 파일 주의 · 메뉴 이름은 기기마다 다름) → 보내기 전 확인 목록 → 보내기 → 접수증. 크기 한도(파일 1GiB · 짝 2GiB)는 고르기 전에 보이고, 넘으면 줄이지 말고 링크를 보낸 분에게 알리라고 한다. 세션이 끊기면(쉼 · 지움 · 나가기) 단계 화면을 떼지 않고 가린 채 다시 묻고, 고른 파일과 보내던 일을 이어 간다.

## 독립 검토(1회)에서 고친 것

| 지적 | 고침 |
|---|---|
| 다시 묻는 화면이 단계 화면을 떼어 쓰던 값이 사라짐(P2) | 단계 화면을 늘 같은 자리에 두고 가린 채 다시 묻기를 위에 띄움 |
| 고침 중 받는 분이 저장만 한 다른 손을 수동 결과의 손으로 덮음(P2) | 그 경우 `manual_result_hand`(reason `correction_draft`)로 받지 않음 |
| 잠긴 링크에서 살아 있는 세션까지 화면이 막음(P3) | 관문에서 세션을 먼저 봄(서버는 원래 잠금 = 맞히기만 막음) |
| 관리자가 지우거나 푼 직후 늦게 끝난 틀린 시도가 다시 잠금(P3) | 잠금은 같은 세대 · 이름 · PIN 있음 · 누적 한도일 때만 |

## GPT05 판정 반영(2026-11-13)

- **Q-R03-1**: 지금처럼 90일 삭제 · 기한 표시 · 로컬 사본 기록만. 연구 보관 상태는 만들지 않는다.
- **Q-R03-2**: 이 접수는 비공개 수동 수집이라 국외 이전을 **선택**으로 바꿨다(`lib/intake/consent.ts`).
  - 제출 글(`intake-submission-2026-11-13.4`)이 팀 내려받기 · 팀 컴퓨터에서 이 투구의 3D 결과 직접 만들기 · 검토 · 승인한 결과만 같은 링크로 전달을 말한다. 분석 모델 개발에 쓰는 것은 선택 항목에 따로 묻는다고 적었다.
  - 국외 이전 글(`intake-overseas-2026-11-13.3+…`)은 선택 · 기본 꺼짐이다. 거부해도 접수 · 직접 만든 결과는 그대로이고, 자동 분석 서버로는 보내지 않는다고 말한다. 모델 글(`intake-model-2026-11-13.3`)은 '분석' → '결과 만들기' 한 낱말만 고쳐 판을 올렸다.
  - 자동 GPU 문: `submissionBlockers` 가 필수 동의와 **따로** `overseasTransferAllowed`(지금 판 · 지금 보내는 사람 · 동의 · 미철회)를 본다. 없으면 `analysis_overseas_missing`. 문서 확정 전 우회(`INTAKE_ALLOW_DRAFT_ANALYSIS` · 확인)가 이 문을 대신하지 않는다. `ANALYSIS_CONSENT` 준비 상태 · `analysisRunGate` 는 그대로다.
  - 수동 결과 가져오기 · 원본 내려받기 · 검토 · 공개는 국외 이전을 보지 않는다(원래도 안 봤다).
  - 받는 분 화면: 국외 이전을 '선택 항목' 칸에 모델 개발과 같이 둔다(체크 글 `optionalCheckLabel`). 고침 · 다시 동의는 필수 글만 보낸다 — 앞서 한 국외 이전 답을 덮지 않는다.
  - 관리자: 상세에 '국외 이전(자동 분석) 동의/미동의', 받는 분이 알린 국외 이전 철회 기록(`withdrawIntakeOverseasConsent`, 감사 `consent.overseas_withdrawn_by_admin`, 자동 분석만 막힘). 필수 철회는 지금처럼 제출 · 국외 이전을 같이 거둔다(`STOP_WITHDRAW_KINDS`).
  - 매니페스트 접수마다 `consents: { required, overseasAutoAnalysis, modelUse }` — 내려받은 원본을 모델 개발 자료로 써도 되는지 팀이 본다.
  - 동의 줄을 만들거나 선택 동의를 저절로 켜지 않는다. 판이 오른 글이라 옛 판 동의는 '다시 동의'로 돌아간다(운영에는 아직 접수 자료가 없다).
