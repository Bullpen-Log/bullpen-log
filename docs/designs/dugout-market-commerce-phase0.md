# 덕아웃 장터 개편 — Phase 0 조사 · Phase 1 결과 (2026-10-25)

계획 `dugout-market-commerce-plan.md`, 지시 `dugout-market-commerce-claude-prompt.md`. 이 문서는 **사실 · 가정 · 아직 없는 것**을 가른다.

## 1. 저장소 조사 (사실)

| 자리 | 지금 | 비고 |
| --- | --- | --- |
| `prisma/schema.prisma` Listing | category · title · price · body · condition · specs(Json) · region · images(String[] ≤5) · status(ACTIVE · RESERVED · SOLD) · views · hiddenAt | 배송비 · 발송 약속 · 하자 칸 · 사진 캡션 · 주문 · 결제 · 환불 · 정산 · 본인 확인 **모두 없음** |

| `components/dugout/pay-shell.tsx` | 결제 수단 · 동의 · 잠긴 단추 — 레슨 · 장소 · 장터가 같이 씀 | 동의 글에 '거래가 끝난 뒤 판매자에게 보내요'가 있었다 → 뺌 |

| 더미 자료 | `scripts/market-dummy-2026-10-25.mjs` — 금윤호 계정 50개(글러브 '많이 씀' 4개 등, 그린 사진 1~3장) | 화면 확인에 씀. 실제 사진이 아니라 비율 · 흠집 확인은 못 함 |

## 2. 흐름 · 상태 (지금 → 목표)

- 지금: `ACTIVE → RESERVED → SOLD` 를 **판매자가 손으로** 바꾼다. 예약 · 결제 · 발송 · 확정 · 정산 상태 없음. 문의(채팅)는 물건을 묶지 않는다(맞음).
- 목표(계획 5절): 물건 → 결제 확인(배송지 · 배송비 · 총액 · 수단 · 동의) → 결제사 → 서버 확인 → 주문 타임라인 → 발송 → 수령 확인 → 구매 확정 → 정산.
  재고 예약 · 주문 · 결제 · 배송 · 분쟁 · 환불 · 정산은 **서로 다른 상태 기계**(한 enum 에 몰아넣지 않는다). Phase 2 에서 표를 더하기만으로 설계.

## 3. Phase 1 에서 바꾼 것 (작동하는 것)

- `lib/market/detail.ts`(순수): `buyerQuote`(수수료 라벨 소수 그대로 '3.5% (가정)', 배송비 null, 나눔은 결제 아님) · `sellerNet`(판매자 수수료 미정 → 물건값 그대로 '가정') ·
  `conditionStatement` · `knownDefects`(글에서 흔적 낱말만, 없으면 '적지 않았어요' — 하자 없음을 저절로 안 매김) · `sellerFacts`(본인 확인 · 정산 계좌 '아직 안 됨', 완료 거래 '0건 (준비 중)') · `fulfillmentOf`.
- `components/dugout/listing-gallery.tsx`: 썸네일 = 진짜 단추(aria-current) · 큰 사진 object-contain 4:3 고정 높이 · ‹ › · ← → · 전체 화면 `<dialog>`(Esc · ‹ › · 한 번 더 누르면 2배) · 사진 실패 칸 처리.
- `components/dugout/purchase-summary.tsx`: 제목 → 가격 → 금액 줄(수수료 · 배송비 '확인' · 거래 방법 · 발송 '확인' · 합계 '배송비 제외') → 판매자 확인 사실 → **안전하게 구매하기(준비 중)** → 문의하기 → 찜. 휴대폰 아래 고정 줄(탭 위 19px).
- 상세 아래: 상태 · 알려진 하자 → 같은 사진을 원래 비율로 세로로(캡션 자리 '사진 n / m') → 판매자 설명 → 규격(글러브 손 설명) → 판매자(투구 기록 수 뺌) → 거래 안내(배송 · 결제 보호 · 판매자 확인 · 반품 · 신고).
- 목록 카드: 상태 · 핵심 규격 · 택배/직거래 한 줄.
- 결제 미리보기(`/pay/listing/[id]`): 제목 '안전결제 미리보기', 3.5% 라벨, 배송비 미정 · 판매자 정산 가정 줄, 대금 보관 약속 문구 삭제, 안내는 '문의만' (직거래 · 계좌이체로 안 바꿈). 단추는 그대로 잠김.
- 판매 흐름 미리보기(`/market/sell-preview`, `components/dugout/sell-flow-preview.tsx`): 네 단계, **저장 없음**(띠로 늘 표시), 품목별 촬영 안내, 하자 여러 개 고르기('없음' 미리 안 고름), '모르겠어요', 배송비 · 발송 약속, 구매자 총액 · 판매자 정산(가정), 사실로 짠 설명 초안, 구매자 화면 미리보기, 올리기 단추는 '본인 확인 뒤(Phase 2)' 잠김.

## 4. 아직 없는 것 (가정 · 외부 의존)

- 결제 · 대금 보호 · 본인 확인 · 정산: 결제사 계약 전. 토스페이먼츠는 **후보**(C2C 개인 판매자 · 수단별 보호 · 정산 보류 · 환불 · 차지백 권한을 서면 확인해야 함).
- 수수료율 3.5% · 판매자 수수료 0: 가정. 라벨에 '(가정)'을 달아 둠.
- 배송비 · 발송 약속 · 하자 칸 · 사진 캡션 · 주문 표: Phase 2(더하기 마이그레이션, 백업 · 김민 알림 뒤).
- 사진 치수: 표에 없어 세로 사진 칸은 `min-h-48` 자리만 잡는다(완전한 layout shift 방지는 Phase 2 에서 치수 저장 뒤).

## 5. 정책 결정 목록 (사용자 · 사업 · 법률 검토)

1. 판매자 자격: 성인 본인 확인 + 정산 계좌 확인부터? 미성년 판매 · 구매와 보호자 동의 범위.
2. 반품 기준: 설명과 다름 · 미배송 · 파손 · 위조 · 단순 변심 — 비용 부담 · 검수 기간 · 자동 확정 기간(3일 고정 아님).
3. 수수료: 구매자 부담 3.5% 유지? 판매자 수수료? 100원 올림 규칙.
4. 직거래: 보호 없이 문의만으로 둘지, 별도 프로토콜을 만들지.
5. 결제사: 토스페이먼츠 외 후보, 에스크로 · 지급대행 · 본인확인을 한 곳에서 받을지.
6. 운영: 사건 목록 · 정산 보류 · 환불 승인 권한을 누가 갖는지(준관리자 범위).
