# 싱커 투구 영상 비교 · 분석 도구 설계

작성: 2026-11-02. 조사 기준 커밋: `83946b61`. **설계 문서이며 기능 구현·기기 검증·배포 완료 보고가 아니다.**

실행용 영어 명세: [sinker-pitch-video-workbench-claude-prompt.md](./sinker-pitch-video-workbench-claude-prompt.md).

## 1. 제품의 중심

사용자가 원하는 것은 영상 편집 메뉴를 늘리는 일이 아니라, 투구탭에서 바로 열어 두 투구를 같은 동작 시점에 맞춰 함께 보는 메인 기능이다. 이름은 **영상 비교**, 도구 안의 제목은 **투구 영상 분석**으로 제안한다. 첫 사용에 분석 보고서 작성이나 투구 기록 저장을 요구하지 않는다.

기본 흐름:

`투구탭 → 영상 비교 → 영상 A·B 선택 → 기준 맞추기 → 함께 재생 → 필요하면 측정·메모 → 자동 저장`

- 기록·내 영상에서 이미 고른 자료는 다시 고르지 않는다.
- 기준을 설정하기 전에도 두 영상을 볼 수 있으나 `시작점 기준`임을 표시한다. 이를 동작 동기화 완료로 표현하지 않는다.
- 기본 기준은 `앞발 착지`. 사용자가 `릴리스` 또는 `직접 선택`으로 바꿀 수 있다. 두 영상에서 각각 같은 사건을 짚는다.
- 한 영상을 먼저 가져오면 바로 볼 수 있고, `비교 영상 추가`로 두 영상 모드가 된다.
- 최근 비교는 저장된 A·B·기준·배속·그림·위치를 그대로 복원한다.

## 4. 투구탭과 인터페이스

### 메인 도크

기존 싱커의 색·서체·아이콘·부드러운 카드·눌림 반응을 사용한다. 새 기능만 검은 전문가 편집기처럼 고립시키지 않는다.

좁은 화면에서는 2×2 도크를 기본안으로 삼는다.

| 1행 | 2열 |
| --- | --- |
| 3D 동작 분석 | **영상 비교** |
| 구속 측정 | ABS |

- 카드 높이 시작값 120–136pt, 간격 12pt, 터치 44pt 이상. 글씨가 커지면 높이가 자연스럽게 늘어난다.
- 기존 도구 삭제·순서 의미 변경·권한 우회 없음. 큰 3D 그림의 독점 면적을 줄여 두 주요 분석 도구를 첫 화면에 함께 노출한다.
- 최근 비교는 아래의 간결한 1–2행으로 제공한다. 빈 상태에는 과장된 일러스트나 설명 카드를 쌓지 않는다.
- 베타 정책상 `/pitch/*`와 내 영상 기능은 제한될 수 있다. **메인에 노출하는 것과 일반 사용자에게 공개하는 것은 별개**다. 현재 잠금 정책을 유지하며, 공개 범위 변경은 별도 결정으로 기록한다.

### 비교 화면

세로 기본은 영상 위·아래 배치. 가로 회전에서는 나란히. 작은 화면에서 세로 영상 두 개를 지나치게 좁게 만들지 않는다. 각 영상의 원본 비율을 보존하고 레터박스를 허용한다. 배치를 사용자가 바꿀 수 있다.

상단: `뒤로 · 비교 이름 · 저장 상태 · 더보기`.

영상: `A/B · 촬영일 · 원본/반전 표시 · 기준 장면`, 선택 영상 테두리, 전체 보기.

기본 조작: 공통 타임라인, 이전/다음 장면, 함께 재생, 배속, 기준 맞추기. A/B 개별 조작은 선택한 영상에만 적용하고 연결 상태를 분명히 표시한다.

하단 도구: `맞추기 · 그리기 · 투구 장면 · 메모 · 내보내기`. 필요할 때 패널을 열고 영상 영역을 남긴다. 키보드·하단탭·안전영역 때문에 닫기·저장·재생 버튼이 가려지면 안 된다.

## 5. 기능 범위와 완성 기준

상세 식별자와 각 완료 기준은 영어 명세 R01–R42에 있다. 전체 범위를 단계로 나누되 뒤 단계 요구사항을 없애는 의미가 아니다.

### A. 빠르고 믿을 수 있는 비교

사진 앱·파일·앱 내 영상·투구 기록에서 선택, 바로 촬영, A/B 교체·순서 교환, 가져오기 취소/진행/실패, 실제 FPS·회전·코덱·슬로모션 정보, 개별/연결 재생, 구간 반복, 음소거 선택, 핀치 확대·이동, 반전 표시, 겹쳐 보기와 투명도, 분할 비교.

두 촬영이 다른 동작이면 기준 하나로 전체 동작이 일치하지 않는 것이 정상이다. 기본은 원래 시간 차이를 보존한다. 선택적 구간 정규화 모드는 `동작 길이 맞춤`으로 분리하고 시간 왜곡을 항상 표시한다. 두 모드를 섞어 실제 속도나 소요 시간으로 해석하지 않는다.

### B. 설명하고 남기는 분석

자유선·선·화살표·사각형·원·텍스트·각도·기준선·포인트, 선택/이동/삭제/undo/redo, 특정 장면·구간 주석, 두 장면 간 시간, 보정 조건을 충족하는 2D 거리, 정지 화면·비교 이미지·비교 영상 내보내기, 음성 메모, 재생·정지·그림·말을 함께 담는 분석 녹화, 컬렉션·검색·태그·공유·오프라인·동기화.

### C. 투수 특화

- 무릎 최고점, 손 분리, 앞발 착지, 사용자가 확인한 최대 외회전 장면, 릴리스, 팔로스루. 모두 먼저 수동 표시로 제공한다. 명확하지 않으면 미지정으로 둔다.
- 착지→릴리스 등 구간 시간과 차이, 주석 각도의 A/B 값·차이. 2D 투영 각도로 명시한다.
- 기준 투구 즐겨찾기, 오늘/지난 투구, 같은 날 잘된/아쉬운 투구 비교, 같은 구종·투구 손·촬영 방향 필터.
- 스트라이드·릴리스 위치의 수동 비교, 스케일·촬영 방향 조건 표시. 관절 부하·부상 확률·구속을 2D 영상만으로 생성하지 않는다.
- 기존 3D 리포트·실제 구속 기록 연결. 연결 자료의 출처·시간·신뢰도·정의 버전을 보여 주고 없는 값은 비워 둔다.
- 3개 이상의 반복 투구는 선택 집합에서 순차 A/B 교체로 검토. 기준 투구는 고정한다.

### D. 고급 기능

4개 이상 뷰를 가진 문서 탐색, 여러 사건 플레이리스트와 해설, 다른 기기 촬영 즉시 리플레이, 외부 카메라/네트워크 스트림, 권한 기반 팀·코치 검토, 광학 흐름/포즈 기반 사건 후보. 모두 명세와 검증 항목을 유지한다. 두 영상 기능의 단순함을 해치지 않도록 고급 메뉴에 둔다.

## 6. 기술 결정

- 네이티브 앱 `native/src`가 구현 대상이다. 기존 웹 비교 화면으로 넘겨 완료했다고 하지 않는다.
- UI·문서 상태와 재생 엔진을 분리한다. `expo-video` SDK 58 문서와 실제 설치 API를 확인한다.
- 첫 비교·주석·자동 저장은 계정별 로컬 문서로 구현 가능하다. 새 DB가 필요하다고 즉시 마이그레이션하지 않는다.
- 원본은 불변, 편집은 별도 문서. 서명 URL 대신 안정적인 자산 식별자를 저장한다.
- 주석은 회전 보정된 영상 좌표에 저장하고 확대·이동·반전·레터박스 변환을 적용한다. 화면 좌표를 그대로 저장하지 않는다.
- 실제 프레젠테이션 타임스탬프(PTS), 촬영 시간, 편집된 재생 시간을 구분한다. 슬로모션 정보 미확인 시 실제 투구 소요시간 계산을 보류한다.
- 두 플레이어 단순 `play()` 호출로 정밀 동기화를 주장하지 않는다. 공통 시간축·탐색 완료·버퍼링·복귀·드리프트를 시험한다. 필요하면 AVFoundation 기반 모듈을 추가한다.
- 네이티브 합성 내보내기는 별도 작업이다. 영상 표면이 빠지는 일반 화면 캡처로 대체하지 않는다. 해설 녹화는 실제 화면 기록 또는 동일 이벤트를 재현하는 렌더러로 재생 속도·정지·그림·음성을 보존한다.
- 서버 동기화/협업은 소유권·선수 공개 범위·코치 권한·삭제·버전 충돌 처리를 먼저 설계하고 기존 조직/동의 체계를 재사용한다.
- Swift/패키지 변경은 새 앱 바이너리가 필요할 수 있다. OTA로 배포된다고 가정하지 않는다.

## 7. 구현 순서와 점검

1. 현재 코드·출시 잠금·영상 소유권·미디어 성능 조사 및 R01–R42 추적표 작성.
2. 메인 진입 + 두 영상 선택 + 기준 동기화 + 로컬 자동 저장의 실제 작동 묶음.
