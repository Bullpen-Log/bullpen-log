# 덕아웃 장터: 쇼핑형 구매 · 신뢰 기반 중고거래 개편안

작성: 2026-10-25. 상태: 조사·제안. 구현·계약·운영 정책 확정 전.
실행용 영어 문서: `docs/designs/dugout-market-commerce-claude-prompt.md`.

## 1. 제품 방향

“물어보고 흥정해야 살 수 있는 게시판”에서 “상태를 확인하고 바로 주문하는 야구 장비 장터”로 발전시킨다. 문의는 선택, 거래 보호는 기본이다. 목표는 중고거래 특유의 불확실성을 줄여 구매와 판매 모두 편하게 만드는 것이다.

추천 조합: 토스의 명확한 행동 흐름 + 네이버식 상세 정보 + 일반 쇼핑몰의 주문 관리 + 중고거래의 거래 보호 + Apple 기본 앱의 절제된 화면 구성. 어느 서비스의 화면을 그대로 복제하지 않는다.

이번 조사는 공개 공식 문서와 현재 저장소 코드에 근거한다. 로그인한 앱의 모든 구매 화면을 직접 실사용 비교한 결과는 아니다. 아래 성과 이유와 단점은 UX 가설이며 기업별 매출 성패의 인과관계를 입증한 주장이 아니다.

## 2. 서비스 비교와 채택 기준

| 참고 서비스 | 확인한 특징 / 참고할 패턴 | 덕아웃이 채택할 것 | 그대로 적용하면 생길 위험 |
| --- | --- | --- | --- |
| 네이버 안전거래 | 공식 도움말은 채팅 없이 구매·제안하고 결제·취소·배송 단계가 채팅으로 안내되는 구조를 설명 | 바로 구매 + 거래 타임라인, 자세한 상품 설명 | 판매자마다 상세 이미지 품질이 다르면 사실 확인이 어려움. 전문 상세페이지 제작을 요구하면 개인 판매자가 이탈 |
| 쿠팡 | 공식 자료에 구매내역 중심의 취소·반품·환불 흐름과 판매자·결제수단별 차이가 설명됨 | 총액, 배송 상태, 주문 이후 도움을 같은 흐름으로 제공 | 물류·정책 기반 없이 빠른배송·무료반품을 약속하면 운영 손실과 불신 |
| 토스쇼핑 | 공식 기술 글은 목적형/탐색형 사용자 구분과 개인화 추천 구조를 설명 | 사진과 가격이 빠르게 읽히는 탐색, 쉬운 결제, 적은 선택지 | 초기 거래·재고가 적은 덕아웃에서 대형 추천 모델과 보상형 이벤트를 먼저 만들면 비용만 늘어남 |
| 당근 안심결제 | 공식 자료에 구매확정 후 대금 전달, 바로구매·안심결제 보호 안내 존재 | 거래별 대금 보호와 쉬운 거래 진행 | 동네·프로필 친숙함만으로 물품 상태나 정품 여부가 보장되지는 않음 |
| 번개장터 | 공개 웹은 브랜드·상품 중심 검색/탐색 구조 | 장비 사진과 브랜드·모델 중심 탐색 | 범용 중고장터의 신뢰 문구·수수료를 확인 없이 복사하면 안 됨. 이번 조사에서 세부 정책은 충분히 확인되지 않아 수치 인용 제외 |
| KREAM | 공식 FAQ는 검수센터·상품 검수·거래 시세를 설명 | 상태 증거와 신뢰의 근거를 눈에 보이게 제공 | 실물 검수망 없이 검수 완료·정품 보장 배지를 붙이는 것은 부적절. 운영 비용이 큰 초기 전면 검수는 보류 |
| Apple 기본 앱 / HIG | 사진·폼·확인 흐름의 일관성을 참고할 디자인 방향 | 선명한 계층, 자연스러운 사진 보기, 절제된 색과 동작 | 모든 콘텐츠에 유리 효과를 쓰거나 맥에서도 휴대폰 화면을 크게 늘리면 가독성과 효율 저하 |

우리 장터의 경쟁력은 “야구 장비를 잘 고를 수 있다”에 둔다. 포지션·손 방향·크기·사용감·수리 이력처럼 실제 구매를 결정하는 정보를 우선한다.

## 3. 현재 구현에서 확인한 문제

- 상품 상세에서 채팅이 주요 버튼, 안전결제는 보조 링크다. 실제 결제 버튼은 비활성 상태다.
- 사진은 가로 넘김, 정사각형 object-cover 처리. 썸네일은 클릭으로 선택하는 기능이 없는 이미지다.
- 아래 설명은 텍스트만 있어 사용자가 요청한 세로 상세 사진 흐름이 없다.
- 사진 최대 5장, 등록은 긴 단일 폼이다. 사진 역할·캡션·하자 정보가 체계화되어 있지 않다.
- 로그인과 업로드 소유권 검사는 있지만 실명 본인확인 판매 자격과 같지 않다.
- 판매자 소개에 투구 기록 수를 노출한다. 거래 신뢰의 증거로 적절하지 않고 별도 서비스 활동 노출 문제도 있으므로 거래 정보로 교체한다.
- 결제 페이지의 대금 보관 주체 및 3일 자동 지급 문구는 구현·계약으로 뒷받침되지 않는다.
- 계산상 수수료는 임시 3.5%인데 표시에서 반올림해 4%로 나온다. 100원 단위 올림도 포함된 임시 정책이다. 실제 요율과 책임 주체를 확정하기 전 확정 정책처럼 안내하지 않는다.
- 실제 주문·환불·분쟁·정산 흐름은 새로 설계해야 한다. 기존 판매중/예약중/판매완료 상태만으로 구현하지 않는다.

## 4. 화면 설계

### 장터 목록

배너를 다시 넣지 않는다. 검색 → 필요한 필터 → 사진 중심 상품 목록 순서. 필터는 글러브 손 방향·포지션·인치, 배트 길이·무게·소재 등 품목에 맞게 노출한다. 카드에는 사진, 제목, 가격, 핵심 규격, 상태, 배송비 여부만 둔다. 상품 정보가 부족하면 임의로 채우지 않는다.

### 상품 상세 PC

상단 왼쪽 약 60% 사진, 오른쪽 약 40% 구매 요약을 기본안으로 삼되 기존 컨테이너와 실제 화면 폭에 맞춰 조정한다. 아래는 읽기 좋은 폭의 상세 콘텐츠. 구매 요약은 필요한 경우에만 고정한다.

```
[선택 가능한 썸네일 + 큰 사진]   [브랜드·모델 / 제목]
                               [가격 / 배송비 / 수수료]
                               [핵심 상태 / 규격]
                               [판매자 확인 사실 / 발송 약속]
                               [안전하게 구매하기]
                               [문의하기] [찜]

[상태 요약 · 알려진 하자]
[원래 비율의 전체 사진]
[선택 캡션]
[다음 사진: 사용감 또는 하자 확대]
[판매자 설명]
[규격]
[판매자 · 실제 거래 후기]
[배송 · 반품 · 보호 범위 · 문제 신고]
```

대표 사진은 빠른 판단, 아래 사진은 자세한 확인을 담당한다. 같은 업로드에서 재사용하며 판매자가 상세페이지 이미지를 따로 제작하지 않는다. 하자는 위 요약과 아래 증거에서 모두 쉽게 찾을 수 있게 한다. 사진을 모두 합친 초장문 이미지와 배너형 문구는 피한다.

### 상품 상세 휴대폰

상단 사진 → 가격·상태 → 하자·세로 사진 → 판매자·정책. 아래에는 가격과 구매 버튼을 고정하되 키보드·안전영역·탭 막대와 겹치지 않게 한다. 문의는 보조 행동이다. 판매완료·예약·본인 상품은 해당 상태에 맞는 동작을 제공한다. 실제 구현은 현재 앱 웹뷰 경로를 먼저 확인한다.

### Apple 같은 느낌의 구체적 기준

- 사진 앱처럼 확대·넘김·닫기가 예측 가능해야 한다.
- 설정 앱처럼 관련 정보는 단순한 묶음과 행으로 정리한다.
- Wallet처럼 최종 결제 금액과 확인 행동을 명확히 한다.
- 흰색/테마 배경, 강한 본문 대비, 작은 보조 텍스트, 초록색 주요 행동 하나.
- 모든 항목을 둥근 카드로 감싸지 않는다. 여백과 얇은 구분선으로 묶는다.
- 투명 효과는 상단·하단 제어 영역에 제한하고 본문은 불투명하게 한다.
- 사진의 생활감과 실제 흠집은 보존한다. AI 보정으로 상태를 좋게 보이게 하지 않는다.
- 동작은 짧고 기능적이어야 한다. 반복 로고 애니메이션이나 불필요한 팝업은 넣지 않는다.
- 대비·키보드·확대·스크린리더·동작 줄이기를 함께 검증한다.

## 5. 구매 흐름

택배 고정가 단품 거래부터 시작한다. 수량 1개인 중고품에 여러 판매자를 묶는 장바구니는 초기 효용보다 복잡도가 크다.

1. 상품과 상태를 확인한다.
2. 구매 버튼 → 배송지·배송비·정확한 총액·결제수단 확인.
3. 결제사의 실제 결제창/간편결제를 이용한다. 저장 결제정보는 제공업체가 관리한다.
4. 서버 검증 후 주문 완료 및 주문 타임라인을 보여 준다.
5. 판매자는 발송과 운송장을 등록하고 구매자는 배송을 확인한다.
6. 구매자는 상품을 확인한 뒤 구매확정 또는 문제 신고를 선택한다.
7. 분쟁·환불·계정 제한이 없고 계약상 조건을 만족하면 정산한다.

결제 중 다른 구매자는 예약 상태를 보되 조회·채팅만으로 재고를 묶지 않는다. 결제 대기 만료, 중복 결제 알림, 늦게 도착한 성공 응답, 환불 실패도 설계한다. 돈을 받았는데 재고가 이미 배정된 경우 자동 복구/환불 경로가 있어야 한다.

직거래는 별도 설계 대상으로 둔다. 택배 배송완료로 위장해 처리하지 않는다. 무료 나눔도 결제 주문과 구분한다.

## 6. 신뢰·안전 구조

### 판매 자격

초안 작성은 로그인으로 허용하고 공개 등록 전에 본인확인과 정산 계좌 확인을 완료하게 한다. 인증 완료의 의미와 확인 시점을 보여 주며 신용평가 또는 정품 인증으로 표현하지 않는다. 만료·정지 상태를 서버에서 반영한다. 판매 제한을 다른 등록 경로로 우회하지 못하게 한다.

초기 제안은 성인 인증 판매자부터 시작하는 것이다. 청소년 이용자가 많은 야구 서비스 특성상 미성년자 구매·판매와 보호자 동의 범위는 별도 확정해야 한다. 일반 회원가입 전체를 판매자 인증으로 막지는 않는다.

### 상품 증거

품목별 기본 촬영 안내, 명시적 하자 선택, 구매 당시 내용의 변경 불가능한 사본을 둔다. 사진·설명·가격·배송 조건·수수료를 주문에 남긴다. 거래가 진행되면 상품 삭제로 증거가 사라지지 않아야 한다.

### 거래 보호

본인확인 + 적격 판매자 등록 + 계약에 맞는 대금 보호 + 배송 증거 + 분쟁 처리 + 정산 통제가 함께 필요하다. 에스크로도 내용물이 설명과 같은지 자동으로 보장하지 않는다. 문제 신고가 열리면 자동 구매확정과 정산을 보류할 수 있어야 한다.

PG, 본인확인, 에스크로, 지급대행은 서로 다른 기능이다. 토스페이먼츠는 후보이며 C2C 개인 판매자 허용 범위, 결제수단별 보호, 정산 보류·환불·차지백·분쟁 권한을 확인하고 선택한다. 임의의 자체 지갑이나 회사 계좌로 대금을 보관하는 구조를 먼저 만들지 않는다.

### 판매자도 보호

발송 증거, 구매확정 안내, 부당한 신고에 대한 소명, 반품 도착 및 상태 확인 절차가 필요하다. 자동 확정 기간은 임의로 3일로 고정하지 않는다. 배송 지연·분쟁 중에는 멈춰야 한다. 약관·법률·계약과 맞춰 확정한다.

### 운영 도구

운영자 사건 목록, 증거 보기, 정산 보류, 승인된 환불, 기한 알림, 조치 이력, 권한 구분이 출시 요건이다. 실제 거래 후에 관리자 화면을 만드는 순서를 피한다. 판매자 유형별 반품 기준, 비용 부담, 위조품·미배송·설명과 다름·운송 중 파손·단순 변심 처리 기준은 검토 후 공개한다.

## 7. 판매 등록

사진 → 장비·상태 → 가격·배송 → 미리보기, 네 단계.

사진은 선택·순서 바꾸기·대표 지정·실패 사진 재시도를 지원한다. 8~12장을 초기 제안으로 두고 비용과 성능을 확인한다. 장비·상태는 필요한 항목만 질문하고 모르는 정보는 모른다고 답할 수 있게 한다. 하자 없음은 기본 선택하지 않는다. 가격 단계는 구매자 부담 총액과 판매자 정산 예상액을 명확히 구분한다.

입력한 정보로 편집 가능한 설명 초안을 조합한다. AI 없이도 충분히 가능하다. 실제 거래 표본이 없으면 적정가 추천을 만들지 않는다. 판매 전 실제 상세페이지를 미리 보여 준다. 초안 자동 저장과 이탈 후 복귀를 지원하고 인증 중에도 작성 내용이 유지된다.

## 8. 단계별 개발과 완료 기준

| 단계 | 주요 결과물 | 완료 조건 / 선행 조건 |

| 0. 설계 확인 | 현재 화면·코드 조사, 상태도, 계약 기능 비교표, 운영 정책 질문 | 사실·제안·외부 의존성을 구분하고 개발 범위 확정 |

| 2. 판매 기반 | 초안, 사진 역할·캡션, 본인확인, 계좌 확인, 배송 조건 | 허가된 추가형 DB 변경, 기존 데이터 보존, 미인증 게시 우회 차단 |

에이전트는 0~1단계의 리뷰 가능한 결과를 먼저 만든다. 계약 심사·정책 검토는 코딩 시간과 별개이므로 근거 없는 전체 완료 시간은 제시하지 않는다. 개발 일정은 실제 1단계 결과와 결제사 계약 범위가 확인된 뒤 갱신한다.

## 9. 측정과 시험

제품 지표: 등록 시작→완료율, 등록 소요시간, 상세→주문 시작률, 결제 완료율, 취소율, 발송 준수율, 완료 거래 100건당 분쟁, 환불 해결시간, 고객지원 문의율. 개선 목표는 베이스라인 측정 뒤 정한다. 구매 전환율만 올리고 분쟁이 늘어나는 결과를 성공으로 보지 않는다.

UI: 폰 390px, 태블릿 768px, PC 1440px 및 낮은 화면 1536×700; 320px 넘침, 200% 확대, 키보드, 긴 한글, 사진 실패·세로 사진·심한 하자·거래 이력 없는 판매자 확인.
