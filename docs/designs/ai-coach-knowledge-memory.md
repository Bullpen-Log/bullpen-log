# AI 코치 2판 설계 — 학습 없이 가르치기(지식 · 기억 · 채점표)

2026-11-16 · 김민 결정: "C 로 설계 다시 해줘". 앞 설계는 `docs/designs/ai-coach.md`(일정 틀 · 조정 · 대화). 이 문서는 그 위에 얹는다.
상태: **설계만. 코드 변경 없음.**

## 0. 왜 다시 짜나

- 코치 모델(Haiku 5.5)은 따로 학습시킬 수 없다(Anthropic 에 그 기능이 없고, 아마존에서 학습되는 Claude 는 2024년 Claude 3 Haiku 뿐 — 11-16 공식 문서 확인).
- 학습시킬 재료도 없다: 검증된 표본 0 · 실제 대화 0. 자료 폴더 v0.3(`coach-authorities-20261105`)은 앱에 연결돼 있지 않았다.
- 지금 코치가 아는 것 = 규칙 글 39줄 + 그 사람의 오늘 기록. 대화가 끝나면 다 잊는다.

그래서 모델은 빌려 쓰고, **우리만 가진 것 셋**을 매번 건네준다. 모델이 바뀌어도 이 셋은 남는다.

| | 무엇 | 지금 | 2판 |
|---|---|---|---|
| 지식 | 우리가 정리한 코칭 기준 | 규칙 글 39줄에 섞여 있음 | 카드 파일로 떼어 관리 · 출처 · 검토 상태 |
| 기억 | 그 선수에 대해 아는 것 | 없음(매번 처음 봄) | 기록에서 뽑은 요약 + 대화에서 들은 말 |
| 채점표 | 좋은 답의 기준 | 실제 호출 여덟 상황 | 30상황 + 자동 검사 · 실제 대화 검토 |

## 1. 한 번 부를 때 건네는 것(AI 호출은 지금처럼 1번)

```
① 규칙 글            고정 · 모든 사용자 같음 ┐ 캐시(다시 읽는 값 1/10 · 더 빠름)
② 지식 카드 전부      고정 · 모든 사용자 같음 ┘
③ 선수 요약          사람마다 · 기록에서 계산(저장 안 함)
④ 코치가 기억하는 것   사람마다 · DB
⑤ 오늘 맥락          지금 그대로(이번 주 7칸 · 체크인 · 투구 · 팔 상태)
⑥ 대화               최근 마디 + 지금 말
```

답은 지금의 `{ reply, adjusts }` 에 `remember`(기억할 말 0~2개) 한 칸만 더한다.

## 2. 결정(권고 — 바꾸고 싶으면 말해 주세요)

- **D1 숫자는 엔진만.** 투구 수 · 휴식일 · 세트 · 무게는 앱 엔진이 계산한 값만 말한다. 카드에 숫자 처방을 넣지 않는다. 엔진과 코치가 다른 숫자를 말하면 사용자는 둘 다 안 믿는다.
- **D2 카드는 고르지 않고 전부 싣는다(40장까지).** 카드 한 장 100토큰쯤 · 40장이면 4,000토큰. 고정 글이라 캐시에 올라가 모든 사용자가 같이 읽는다. '상황에 맞는 카드 고르기'(검색)는 40장을 넘으면 그때 만든다. 고르기 단계가 없으니 느려지지 않고 틀릴 곳도 없다.
- **D3 카드는 두 종류.** 안전 카드('이건 하지 마라 · 이럴 땐 전문가로')는 초안이어도 싣는다. 코칭 카드('이럴 땐 이렇게 권해라')는 **사람이 검토한 것만** 싣는다(검토자 · 날짜를 카드에 적음).
- **D4 카드는 코치가 할 수 있는 일로만 쓴다.** 코치가 하는 일은 일정 바꾸기 넷(시간 · 쉬기 · 옮기기 · 바쁜 주) · 설명 · 되묻기 · 다른 화면으로 보내기(체크인 · 투구 기록 · 암케어 · 전문가)다. 이 밖의 주제(종목 · 영양 · 영상 분석) 카드는 만들지 않는다.
- **D5 기억은 사용자가 보고 지운다.** 코치 설정에 '코치가 기억하는 것' 목록. 건강 얘기는 건강정보 동의가 있을 때만 남긴다. 20개까지.
- **D6 기억 고르기도 AI 를 한 번 더 부르지 않는다.** 같은 답 안에서 `remember` 로 받는다. 서버가 거른다(길이 · 개수 · 건강 · 이름 · 연락처).
- **D7 실제 대화를 품질 개선에 쓰려면 동의 글을 고친다.** 지금 동의에는 '대화를 30일 둔다'만 있다. 검토 · 표본 만들기에 쓰는 것은 없다. 법 검토 뒤(사용자 몫).

## 3. 지식 카드

파일 하나 `lib/coach/cards.ts`(순수). 한 장의 모양:

```ts
{ id: 'S03', kind: 'safety' | 'coaching',
  when: '기록에 없는 투구를 말할 때',
  do: '구수와 강도를 한 번 묻고 투구 기록에 남겨 달라고 한다. 부담되면 오늘 쉬기를 제안한다.',
  dont: '기록 없이 "적게 던졌으니 괜찮다"고 말하지 않는다.',
  ages: 'all' | '14-16' | '17+',
  sources: ['PS01', 'ZA18'],            // 내부 추적용 — 화면 · AI 답에는 기관 이름을 쓰지 않는다
  review: { by: null, at: null } }       // 코칭 카드는 by 가 있어야 실린다
```

시험이 지키는 것: 카드에 숫자 처방 없음 · 코칭 카드는 검토자 있음 · 출처 id 가 출처 표에 있음 · 전체 4,000토큰 안.

## 4. 기억

**① 선수 요약(기록에서 계산 · 저장 없음 · AI 안 씀)** — 최근 4주 기록으로 서버가 만든다. 예:
```
[선수 요약 · 최근 4주]
계획한 운동 12번 중 8번 함. 못 한 날은 주로 목요일(3번).
못 한 까닭: 시간 2 · 피곤 1.
운동 힘듦 평균 6 · 지난주부터 오름.
등판 주 1번쯤(선발) · 평균 78구.
이번 달 조정: 시간 줄이기 3 · 쉬기 1.
```
재료는 이미 DB 에 있다(주 틀 · 운동 완료 · 어제 이어보기 답 · 힘듦 · 투구 기록). 새 표 없음.

**② 코치가 기억하는 것(대화에서 들은 말)** — 기록에 없는 것만. 예: '토요일은 알바라 운동 못 함' · '내년 3월 대회가 목표' · '집에는 밴드만 있음'.
- AI 가 답과 함께 `remember: ['…']` 로 제안 → 서버가 거름 → `CoachProfile.answers.memory`(새 표 없음) → 다음 대화부터 건넨다.
- 사용자가 코치 설정에서 보고 지운다. 코치에게 '그거 잊어 줘'라고 하면 `forget` 으로 지운다.
- 안 남기는 것: 이름 · 연락처 · 건강 얘기(동의 없을 때) · 기록에 이미 있는 것 · 그날만의 일.

## 5. 채점표

- `scripts/coach-ai-live.mts` 를 30상황으로(지금 8). 상황마다 합격 기준을 코드로: 금지어(구수 숫자 · 진단 낱말 · 영양제) · 꼭 해야 할 것(되묻기 · 체크인 권하기) · `adjusts` 모양 · 말투.
- 규칙 글 · 카드 · 모델을 바꿀 때마다 돌린다(Haiku 로 30상황 약 25원).
- 실제 대화: 관리자 화면에서 표본을 읽고 좋음 · 나쁨 · 고친 답을 남긴다(D7 동의 뒤). 이것이 쌓이면 훗날 공개 모델 학습의 재료가 된다.

## 7. 속도 · 값

- 읽는 양: 지금 약 4,000토큰 → 약 6,500토큰(카드 +1,600 · 요약 +300 · 기억 +300). 그중 규칙 글 + 카드(약 4,000)는 캐시로 읽는다.
- 응답 시간: 지금 1.5~3초 → 0.1~0.3초 늘 것으로 어림(재지 않음 — 1단계 끝에 실제 호출로 잰다).
- 값: 한 마디 약 $0.0006 → 약 $0.0007 어림.
