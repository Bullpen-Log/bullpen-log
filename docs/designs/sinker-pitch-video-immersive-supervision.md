## 총괄 절차

- 한 세션만 동일 생산 파일을 수정하게 한다. 대기·실행·완료·인계·앱 반영 완료를 구분한다.
- 현재 단계에 필요한 지시만 보낸다. 종료된 서브1은 메인 인계 후 다시 깨운다. 같은 실행 요청을 중복 전송하지 않고, 새 메시지와 실행 표시를 확인한다.
- 새 모듈이 생산 코드에서 실제 사용되는지, 이전 OverlayBox·좌표 변환과 경쟁 경로가 남는지 확인한다.
- IM01–IM12와 SS01–SS07을 함께 검토한다. 검은 배경만 적용하거나 숨긴 도구의 공간을 그대로 두는 것으로 완료하지 않는다.
- 통합 완료 후 필요한 범위의 시험을 원래 종료코드·전체 로그와 함께 확인한다. 소스 변화나 실패가 없으면 같은 검사를 반복하지 않는다. 기존 타입 오류를 가리거나 다른 협업자 파일을 임의 수정하지 않는다.
- 부족한 부분은 서브1에 구체적인 파일·원인·통과 조건으로 교정 요청한다. 총괄자가 같은 생산 파일을 동시에 편집하지 않는다.
- 실제 아이폰 화면·영상 합성·동기화·키보드·IME·VoiceOver·성능을 보지 않았다면 미검증으로 보고한다. 모의 시험 수를 기기 검증 완료로 표현하지 않는다.

## 후속 확인

이 대화에 `싱커 영상 비교 개발 총괄` heartbeat를 생성했다. 도구 반환 자동화 ID는 `automation`, 상태 ACTIVE이며 5분 간격을 요청했다. 이후 변경/중지 전에는 도구에서 실제 ID와 현재 설정을 다시 조회한다. 같은 자동화를 중복 생성하지 않는다.

상태가 그대로면 알리지 않는다. 의미 있는 진전·실패·차단·완료만 한국어로 보고한다. 전체 로컬 구현·독립 검토가 끝나면 해당 후속 확인을 중지 또는 삭제한다. 앱·호스트 접근이 끊기거나 계정 한도가 막으면 구체적인 한계를 알린다. 후속 확인은 이 앱이 실행·접근 가능한 조건에서 동작하므로 무조건적인 상시 감시로 약속하지 않는다.
