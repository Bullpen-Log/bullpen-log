# 메커니즘 처방 전후 비교 — 4단계

구현 범위: 처방 시작 기준 보존 → 본인 재측정 연결 → 비교 가능성 확인 → 사용자의 유지/재연습/새 처방 검토 선택. 자동 개선 확정·자동 처방 교체·3D 엔진 정확도 변경은 포함하지 않는다.

## 저장과 권한

- DB 스키마를 바꾸지 않는다. `MechanicsProgram.progress.focus.review`와 `reviewHistory`, 프로그램의 `focusHistory`를 사용한다.
- 시작 기준에는 샘플/작업 번호, 엔진 지문, 판정/수치 정의 버전, 당시 수치·신뢰도·적용 조건, 원본 확인 결과, 등록 시각과 연습 횟수를 저장한다. 최신 리포트를 다시 읽어 과거 저장본을 바꾸지 않는다.
- `context-{jobId}.json`은 기존 비공개 영상 폴더에 분석 요청 전에 한 번 저장하며 `upsert:false`다. 서버가 읽은 원본 지문과 녹화 시각을 사용한다. 서버 확인 실패를 클라이언트 입력으로 채우지 않는다.
- 지문은 기존 `labServerFacts` 정의(파일 크기 + 앞/뒤 각 최대 1MB SHA-256)다. 영상 전체의 해시나 실제 촬영 장면의 정답 검증을 뜻하지 않는다. 연결 시 원본 지문을 다시 읽는다. 확인 실패·변경은 비교 보류이며 알려진 변경 결과로 새 처방을 시작하지 않는다.
- 본인 결과만 연결한다. 관리자 공유 접근 권한으로 남의 분석을 자기 처방에 붙이지 못한다. 완료된 현재 작업 번호를 선택·저장 직전 다시 확인한다. 실패/진행 중/교체된 작업은 연결하지 않는다.
- 처방 교체는 확인한 작업 번호와 기존 처방 실행 번호가 같을 때만 한다. 종료도 실행 번호를 확인한다. 지연된 이전 화면의 요청이 새 처방을 교체·종료하지 못한다.
- 새 기준을 명시적으로 등록하면 이전 비교 라운드 전체를 `reviewHistory`에 보존한다. 이후 기준은 처방 시작 전 측정으로 표시하지 않는다. 교체·종료·프로그램 초기화에서도 이전 처방·수행·비교를 보존한다. 초기화는 수준 선택을 해제하고 누적 실제 수행 기록을 남긴다.

## 비교 판정

- 같은 분석 자체는 연결하지 않는다. 한쪽이라도 같은 원본 지문이면 재계산으로 구분하고 새로운 투구의 전후 변화로 해석하지 않는다.
- 엔진·판정·수치 정의, 손·지면·키·성장기 적용·촬영 속도가 같아야 한다. 동시 촬영 원본이고 양쪽 실제 녹화 시작 시각(Apple)이 확인돼야 한다. 파일 생성 시각(mvhd)은 녹화 시작 시각으로 간주하지 않는다.
- 재측정은 기준 등록 이후의 새 촬영이어야 한다. 업로드/분석을 늦게 한 옛 영상이나 분석 요청보다 미래인 시각은 보류한다.
- 촬영 위치·배율·투구 세기의 동일 여부는 사용자 자가 확인이며 서버가 측정했다고 표현하지 않는다. 다름/미확인은 보류한다. 연결한 응답은 저장본에 남는다.
- 같은 지표 정의·단위가 양쪽에 있고, 양쪽 측정 신뢰도/검증/적용 조건이 충족된 행만 차이를 계산한다. 현재 정책에서는 참고 지표를 자동 변화 평가에 포함하지 않는다. 드리프트·드롭은 키 대비 %, 나머지 해당 지표는 각도 단위다. 판정 문구를 수치로 역변환하지 않는다.
- 한 구씩의 수치 차이다. 검증된 반복 측정 오차와 최소 검출 변화량이 없으므로 개선/악화/운동 효과/통계적 유의성으로 결론 내리지 않는다. 비교 가능한 행이 없으면 전체도 보류로 표시한다.
- 수치 정의/단위/추출 방식이 바뀌면 `COMPARISON_METRICS`를 올린다. 판정 변경은 `REPORT_CRITERIA`, 엔진 변경은 결과의 엔진 지문으로 별도 구분한다. 과거 두 버전을 임의로 호환한다고 선언하지 않는다.

## 사용자의 처방 검토

- 유지: 선택만 기록하며 진행은 유지한다.
- 현재 단계 재연습: 사용자 확인 후 현재 단계에서 `reviewFrom=evidence.length` 이후의 새로운 수행 확인을 시작한다. 과거 근거·횟수는 남긴다. 통증/현재 제한/진행 중인 당일 세션이 있으면 보류한다. 단계는 낮추거나 자동으로 올리지 않는다.
- 새 처방 검토: 선택 기록과 리포트 이동만 제공한다. 리포트에서 최신 결과의 처방과 교체를 별도로 확인한다.
- 같은 비교에 대한 동일 선택 재요청은 진행을 다시 초기화하지 않는다. 선택 대상과 원본 저장본은 유지한다.

## 검증과 배포

앱 API 6. 새 비교 동작과 프로그램 로드·처방 시작/종료/확인 시트에만 최소 6을 적용한다. 기존 기록/완료는 5, 나머지 공통 최소는 1을 유지한다. 새 앱은 이전 서버의 프로그램 응답이면 안내한다.

`node --import ./scripts/alias-register.mjs` 뒤에 다음 스크립트를 실행한다.

- `scripts/mechanics-comparison-test.mjs`: 실제 비교·파싱·역사 보존·재연습 근거 분리
- `scripts/mechanics-analysis-load-test.mjs`: 실제 결과 파서/리포트/분석 로더, 저장소만 대체
- `scripts/mechanics-context-store-test.mjs`: 실제 조건 저장과 중복 덮어쓰기 거부, 메모리 버킷
- `scripts/mechanics-record-test.mjs`: 실제 서버 액션의 동시 저장·재전송·선택·교체·종료·초기화, 메모리 DB
- `scripts/mechanics-progress-render-test.mjs`: 실제 앱·웹 표시, 네이티브 기본 뷰와 실행하지 않는 동작만 대체

운영 계정의 테스트 쓰기나 GPU 실행, 실기기·시뮬레이터 검증을 수행하지 않는다. 엔진 정확도 검증과 실제 운동 효과 검증을 위 검사로 대신하지 않는다. 4단계 구현 승인은 배포 승인을 포함하지 않는다.
