### 0-2. 권장안(이 문서가 제안 — 바꿀 수 있음)

- R1 일을 넷으로 나눈다: A 하단바 → C 주간 자동 일정(규칙) → D AI 층. B 가입 · 동의는 출시 전 필수라 A 와 나란히.
- R2 주간 일정은 **날마다의 틀(무엇 · 몇 분 · 어느 쪽)만** 미리 짓고, 운동 목록은 **그날** 기존 엔진으로 만든다(상태가 날마다 바뀌어 미리 짠 목록은 낡는다).
- R3 AI 는 운동 · 무게 · 투구 수를 직접 내지 않는다. **구조화된 조정 요청(CoachIntent)** 만 내고 규칙 엔진이 적용 · 검증한다.
- R4 '하루의 주인' 규칙 — 사용자가 직접 만들거나 고친 날은 코치가 덮지 않는다(4-3).
- R5 코치는 투구 양을 짜지 않는다 — 등판 · 투구 계획(`buildPitchPlan`)은 읽기만.
- R6 건강정보 동의(가입 때)와 **AI 회사로 보내는 국외 이전 동의(코치를 처음 켤 때)** 를 나눈다. 쓰는 사람만 두 번째에 동의한다.
- R7 유료 여부는 서버의 권한 표(Entitlement)로 본다. 인앱결제 전에는 관리자가 직접 켠다.

## 2. 아키텍처

```
[질문 답 · 앱 정보] ─┐
[체크인 · 기록 · 달력]─┼─▶ (1) 주간 계획기(규칙, 순수) ──▶ CoachWeek(7일 틀)
[되먹임(힘듦 · 교체)] ─┘            ▲                         │ 그날
                                    │ CoachIntent              ▼
 (3) AI 층 ── 자유글 해석 ──────────┘          (2) 그날 운동 = 기존 generateTodayPlan(틀을 fence 로)
     └─ 설명 문장(오늘 이유 · 주간 리뷰)                     │
                                                              ▼ 기존 안전 층(arbiter · selectCandidates)
 (4) 권한 · 동의 · 한도 ── 모든 코치 동작 맨 앞            DailyTrainingSetup(auto.by='coach') → 운동 → 기록
```

1. **주간 계획기**(`lib/coach/week.ts`, 순수 · 시험): 입력 = 질문 답 · 앱 정보(장비 · 수준 · 하루 시간) · facts(부하 · 등판 · 통증) · 고정 일정 · 지난주 되먹임.
   출력 = 7칸 `DaySlot { date, kind: 'train'|'armcare'|'rest'|'fixed', fence: {goals, minutes, focus, heavyLower}, reason, owner: 'coach'|'user', status }`.
   날 종류는 기존 `dayKindOf`(microcycle) · `outingOf` · 팔 예산 규칙을 재사용한다(새 규칙을 만들지 않는다).
2. **그날 운동**: 그날이 오면(또는 사용자가 코치 메인을 열면) `generateTodayPlan` 의 자동 길에 **슬롯의 fence 를 넘겨** 기존 `decideAutoFence` 가 그 안에서 고른다.
   안전 층 · 저장 · 운동 화면 · 기록은 그대로 공유 — 트레이닝 탭과 같은 `DailyTrainingSetup` 한 줄이라 완료가 서로 보인다.
3. **AI 층**: ① 자유글("이번 주 수요일 팀 훈련 생겼어 · 덤벨만 있어 · 30분만") → `CoachIntent`(아래) ② 오늘 이유 · 주간 리뷰 문장. 운동 id · 무게 · 투구 수 · 진단은 만들지 않는다.
   `CoachIntent = { moveDay?, minutes?, equipment?, focus?, skipDay?, fixedEvent? }` 만 받고, 모양 검사 → 계획기가 적용 → 미리보기 → 사용자 확인 뒤 저장.
4. **권한 · 동의 · 한도**: 모든 코치 RPC 맨 앞에 `allowFeature('coach')`(베타) + `requireEntitlement('coach')`(유료) + AI 를 부를 때만 국외 이전 동의 · 하루 호출 상한 · 전체 비용 상한.
   AI 가 실패 · 느림 · 상한이면 규칙 결과만으로 그대로 돈다(문장은 정해진 문장).

## 5. AI 층(D 트랙)

- **하는 것**: 대화(자유글 → 답 + `CoachIntent`, 모양 검사 통과분만 — 첫 판, U39), 오늘 이유 · 주간 리뷰 문장(정해진 숫자를 넣은 글을 다듬기). 확정 설계는 10-6.
- **안 하는 것**: 운동 id 만들기 · 무게 · 세트 · 투구 수 · 진단 · 통증 해석. 모든 적용은 계획기 → 기존 안전 층을 지난 결과만, 저장 전에 바뀐 점을 보여 준다. 대화 속 '하자'는 예정, 확정 기록과 구분.
- **보내는 것 줄이기**: 이름 · 이메일 · 생년월일 · 메모 원문은 안 보낸다. 나이대 · 정해진 신호 코드(예: `shoulderPain:true`) · 이번 주 칸 · 사용자가 쓴 자유글만.
- **한도**: `CoachLog` 로 사람마다 하루 N번(Q4) · 같은 입력(사용자 · 날짜 · fingerprint)은 다시 안 부름 · 전체 월 비용 상한(환경변수) · 시간 초과면 규칙 결과로.
- **비용**: 외부 AI 기다리는 시간은 Vercel 계산 시간이 아니라 기다림이라 크지 않다. 대화 답은 짧게(2~4문장) 둔다.
- **법**: 처리방침 4조에 AI 회사 한 줄 · 국외 이전 항목(나라 · 보내는 항목 · 때 · 보관 — 학습에 안 씀 조건) · 2조 목적 · 9조 변경 기록, 3조 '무료' 문구는 유료가 시작되면 결제 기록 보관(5년)으로.

2. **날 종류**: 등판을 기준으로 `dayKindOf`(R1~R7 — 등판 날 · 다음 날 회복 · 앞 3일 무거운 하체 없음 …).
3. **고정 일정 날**: 팀 훈련 날 = 가볍게(보조 · 암케어 · 메커니즘 중 하나, 큰 하체 없음) · 레슨 '한 일'은 그날 운동량에 더함(U28).
4. **운동 날 놓기(U25)**: 가능한 요일 안에서 —
   - 프로그램이 있으면 주당 횟수만큼 프로그램 날(이어진 이틀 큰 하체 없음 — `keepsLowerBudget`).

   - 쉬는 날은 적어도 하루.
5. **암케어 제안(U23)**: 강화 주 3번(`decideArmcare` STRENGTH_PER_WEEK) — 등판 다음 날은 회복 암케어. **제안**이라 그날 안 해도 '못 함'으로 세지 않는다(암케어는 언제든 — 사용자 결정).
6. **메커니즘 드릴(U23)**: 메커니즘 프로그램의 주당 세션을 팔을 다 쓴 날 · 통증 날을 피해(`mechanicsFoldOf` 규칙) 운동 날 앞 · 가벼운 날에.

**언제 짜고 고치나(U24)**

- `train` → `generateTodayPlan` 자동 길에 칸의 `fence`(목표 · 분 · 쪽 · 큰 하체 여부)를 넘김 → `decideAutoFence` 가 그 안에서 고름 → `DailyTrainingSetup.plan.auto.by = 'coach'`.

- 모두 기존 안전 층을 지난다 — 칸이 '운동'이어도 그날 상태가 쉬라고 하면 엔진이 이긴다(그 사실을 칸에 표시).

**프로그램 제안(U26)**: 질문 답(목표 · 경험 · 장비 · 시즌 · 주당 가능 날)으로 `lib/program/program.ts` 의 7개 + 시즌 중 둘에서 맞는 것을 고르는 순수 함수 `suggestProgram`(지금 프로그램 고르기 화면의 조건 — 나이 · 장비 · 시즌 막기 — 를 그대로) → 첫 주 미리보기에서 [이 프로그램으로 | 프로그램 없이].

### 10-5. 5단계 — 코치 메인 화면 · 되먹임(U34~U38 확정)

**코치 메인(앱, 한 화면 위→아래 — U34)**
1. **(일요일 저녁 ~ 월요일) 주간 리뷰 카드** — U37. [확인]하면 접힘.
2. **오늘 계획(크게)** — 칸 종류(운동 · 프로그램 · 암케어 제안 · 메커니즘 · 쉬기 · 팀 훈련) · 예상 시간 · 이렇게 짠 까닭 한두 줄(까닭 코드 → 정해진 문장) · [시작](운동 · 프로그램 · 암케어 · 메커니즘 각자 지금 화면).
   체크인 전이면 [체크인부터](오늘 상태를 모르면 맞출 수 없음). 그날 상태가 계획을 바꿨으면 '오늘 상태에 맞춰 가볍게 바꿨어요' 한 줄.
3. **이번 주 7칸** — 날마다 작은 표시(한 것 ✓ · 오늘 · 못 함 · 쉬기 · 팀 훈련 · 등판 · 내가 고친 날). 칸을 누르면 그날 내용(미래 날은 틀만 — 운동 목록은 그날 만든다, R2).
4. **조정 단추(U35)** — [오늘 시간 −/+] [오늘 장소 · 장비] [이 날 ↔ 다른 날] [오늘 쉬기] [이번 주 바빠요]. 누르면 계획기를 다시 돌린 **바뀐 점 미리보기**(칸 몇 개가 어떻게) → [적용](저장) / [취소].
   이미 시작한 오늘 운동 · 지난 날은 못 바꿈. 단추 조정은 그 칸을 `owner:'coach'` 로 둔다(사용자가 코치에게 시킨 것).
5. **리뷰 요약 카드** — 이번 주 한 날 / 계획 날 · 힘듦 흐름 한 줄 → 누르면 리뷰 자세히 = 1단계의 분석(투구 · 트레이닝) + 코치 주간 기록.
6. 맨 아래: '코치 설정'(질문 화면 다시 · 일시 멈춤 · 코치 끄기) · '더 알려 주기'(4단계).

**하루의 주인(U38)**
- 트레이닝 탭(오늘 운동 만들기 · 다시 만들기 · 운동 넣기/빼기 · 프로그램 날 바꾸기)에서 그날을 바꾸면 그 칸 `owner:'user'` → 코치는 그날을 다시 맞추지 않는다. 다음 날부터 다시 코치.
- 코치 진행 중 트레이닝 탭 첫 화면: 오늘 칸이 코치 것이면 '오늘은 코치 계획이 있어요' + [코치 계획으로 | 직접 만들기]. 직접 만들기 = 그날 주인 바뀜(되돌리기: 코치 메인 [오늘 다시 코치에게]).
- 암케어 · 메커니즘을 칸과 다른 날에 해도 '한 것'으로 센다(암케어는 언제든 — 사용자 결정).

**되먹임(U36)**
- 운동 끝 화면(지금 '힘듦' 단추 — `rateWorkoutEffort`) 밑에 '불편했던 동작이 있었나요?' — 오늘 한 운동 중에서 고르기(여럿 · 건너뛰기). 코치 진행 중 · 건강 동의가 있을 때만.
- 저장: `DailyTrainingNote` 에 `discomfort Json?`(운동 id · 움직임 열쇠) — 더하기 칸. 건강정보라 동의 철회 때 지운다.
- 반영: 계획기가 지난 7일 불편 동작을 읽어 같은 움직임 열쇠를 그 주 fence 에서 뒤로 미룬다(빼지는 않음 — 지금 엔진의 '최근 바꾼 운동 미루기'와 같은 방식). 같은 부위가 두 번 넘게 나오면 리뷰에 '전문가와 상의' 한 줄 — 진단은 하지 않는다.

**칸 상태는 저장하지 않고 기록에서 읽는다**: 한 것 = `TrainingSession`(마침) · `UserExerciseLog` · `DailyArmcare` · 메커니즘 기록 · 프로그램 진행. 못 함 = 지난 날 · 계획 있음 · 기록 없음. 한 곳(기록)만 진실이라 트레이닝 탭 · 코치가 어긋나지 않는다.

**주간 리뷰(U37)**
- 순수 `lib/coach/review.ts`: 지난주 칸 + 기록 → 한 날 / 계획 날 · 못 한 날 · 날마다 힘듦 · 반복된 불편 동작 · 다음 주가 바뀐 까닭(계획기 까닭 코드 차이). 글은 정해진 문장(6단계에서 AI 가 다듬을 수 있음).
- 알림: 일요일 18시(한국) — `lib/notify.ts`(Expo 푸시, 지금 있음)로 코치 진행 중인 사람에게 한 번. [확인] 전까지 카드는 맨 위.

**정해진 시각 작업(새로)**: `vercel.json` crons 하나 — 매일 18시(한국 = UTC 09:00) `/api/cron/daily`(비밀 머리로만 열림): ① 2단계 14세 미만 7일 지나 지우기(매일) ② 주간 리뷰 알림(일요일만). 다음 주 계획 짓기는 크론이 아니라 처음 열 때(3단계 그대로) — 알림을 누르면 열리며 짓는다.

**홈**: 유료 · 진행 중이면 '오늘의 코치 계획' 요약 카드 하나(오늘 칸 · 시간 · [시작] · 누르면 코치 탭). 아니면 지금 홈 그대로.

**PC 웹(U33)**: 리뷰 + 이번 주 7칸 읽기만.

**서버(`app/actions/coach.ts` 더함)**: `loadCoachHome()` · `previewCoachAdjust(kind, value)` · `applyCoachAdjust(previewId)`(미리본 것과 같을 때만 — 그새 상태가 바뀌었으면 다시 미리보기) · `takeBackToday()` · `ackWeeklyReview(weekStart)` · `saveDiscomfort(date, ids)`.

**시간(Claude 기준)**: 코치 메인 · 조정 · 하루의 주인 8~10h · 되먹임 · 리뷰 · 알림 · 크론 5~7h · 홈 카드 · 트레이닝 탭 안내 2~3h.

### 10-6. 6단계 — AI: 대화 · 설명 문장(U39~U44 확정, 기준 origin/main `83946b61`)

**AI 가 하는 일은 둘(U39)**. 자유글 칸을 따로 두지 않고 대화 하나로 합친다.
1. **대화** — 사용자 말 → 답 글 + 바꿀 거리(`adjusts`, 0~3개). 2절의 `CoachIntent` 는 `{ reply, adjusts: CoachAdjust[] }` 로 확정한다.
   바꿀 거리는 5단계 조정 단추와 **같은 모양**이라 미리보기 · 적용은 `previewCoachAdjust` · `applyCoachAdjust` 를 그대로 쓴다. AI 가 저장하지 않는다.
2. **설명 문장** — 오늘 칸의 까닭 코드 · 숫자 → 한두 문장, 주간 리뷰(`lib/coach/review.ts` 결과) → 세 문장. 실패하면 같은 자리에 정해진 문장이 나온다.

| `CoachAdjust.kind` | 값 | 같은 단추(5단계) |
|---|---|---|
| `minutes` | date · 10~120 | 오늘 시간 −/+ |
| `place` | date · 'home'\|'gym'\|'field' · equipment?(우리 장비 열쇠만) | 장소 · 장비 |
| `move` | from · to | 이 날 ↔ 다른 날 |
| `skip` | date | 오늘 쉬기 |
| `busy` | weekStart | 이번 주 바빠요 |
| `fixed` | date · 'team'\|'lesson'\|'game' | (대화에만) 달력 일정 한 줄 — 기존 달력 저장 길 · 계획기 다시 돌림 |

- 서버가 다시 거른다(`sanitizeAdjusts`): 날짜는 이번 주 오늘~일요일만 · 지난 날과 시작한 오늘 운동은 못 바꿈(5단계 규칙) · 장비는 목록 안 · 값은 범위 안. 남은 것만 미리보기.
- **안 하는 것**: 운동 고르기 · 무게 · 세트 · 투구 수 · 진단 · 통증 해석. 통증 · 부상 말이 나오면 정해진 안내(체크인에 적기 · 계속 아프면 전문가) + [체크인] 단추.
  답 글이 이상해도(프롬프트 주입 포함) 일정을 바꾸는 길은 `adjusts` → 거르기 → 사용자 [적용]뿐이다.

**모델 · 부르는 법(U40)** — `@anthropic-ai/sdk`(10-07 에 지운 것을 다시) · 서버에서만 부른다(앱 → rpc → 서버 → Anthropic). 열쇠 `ANTHROPIC_API_KEY` 는 Vercel 환경변수(사용자 몫), 저장소에 안 적는다.

| 일 | 모델(환경변수 · 기본값) | 방식 |
|---|---|---|
| 대화 | `COACH_MODEL_CHAT` = `claude-opus-5-5` · effort `low` · max_tokens 2000 | `client.messages.parse` + `output_config.format`(zod 스키마 `{ reply, adjusts }`) — 답 모양이 늘 맞다. 도구 · 반복 고리 없음 |
| 설명 | `COACH_MODEL_EXPLAIN` = `claude-haiku-5-5` · effort `low` · max_tokens 600 | 같은 parse(`{ text }`) |

- **스트리밍은 첫 판에 안 한다**: 답이 짧아(몇 초) 지금 rpc(한 번에 답하는 모양) 그대로 + '쓰는 중' 점. 답답하면 그때 스트리밍 길을 따로 낸다.
- 생각(thinking)은 두 모델 다 켜진 채다(Opus 5.5 는 끌 수 없음). effort 로 줄이고, 생각 글은 보이지도 저장하지도 않는다.
- 대화 기록은 **글만** 다시 보낸다(생각 블록 없이 · 최근 20마디). 앞을 잘라도 '기록 편집 검사'(2026-08-31 뒤 만든 계정, Opus 5.5 도 적용)에 걸릴 블록이 없다.
- 거절(`stop_reason: 'refusal'`)을 늘 먼저 본다. 대화는 `fallbacks: "default"`(베타 `server-side-fallback-2026-07-01`)로 다른 모델이 이어받는다. 그래도 거절 · Haiku 거절 · `parsed_output` 이 null · 15초 넘김(SDK 재시도 2번 뒤) → 정해진 문장.
- 말투는 시스템 글에: 해요체 · 2~4문장 · 줄표 없음(앱 글 규칙과 같게).

**보내는 것(줄이기)**
- **시스템 글**(고정, 판 번호 `COACH_PROMPT_V`): 역할 · 할 것과 안 할 것 · `adjusts` 규칙 · 말투 · 장비 열쇠 목록. 날짜 · 사람마다 다른 것은 넣지 않는다(캐시가 깨지지 않게).
- **오늘 맥락**(마지막 사용자 말 앞에 붙이는 덩이, 코드 · 숫자만): 나이대(14~16 · 17~19 · 20+) · 역할(선발 · 불펜) · 이번 주 7칸(종류 · 분 · 까닭 코드 · 한 것) · 다음 등판까지 일 · 목표 순위 · 장비 열쇠 · 오늘 신호 코드(**건강 동의가 있을 때만**).
- **안 보내는 것**: 이름 · 이메일 · 생년월일 · 사용자 id · 체크인 메모 원문 · 영상 · 위치. 사용자가 대화에 쓴 글은 그대로 가므로 입력 칸 밑에 '이름 · 연락처는 적지 마세요' 한 줄.
- **학습 · 보관**: API 로 보낸 내용을 모델 학습에 쓰지 않는다는 조건과 Anthropic 쪽 보관 기간은 **사용자가 약관 · 콘솔에서 확인해 처리방침에 적는다**(이 문서는 값을 단정하지 않음).

**프롬프트 캐시**: 요청에 `cache_control: { type: 'ephemeral' }`(자동 — 마지막 블록까지). 같은 대화 5분 안 다음 마디는 시스템 글 + 지난 마디를 캐시로 읽는다(Opus 5.5 캐시 읽기 $0.20/MTok, 보통 입력의 1/20).
시스템 글이 512토큰을 넘어야 캐시된다(규칙 · 장비 목록으로 넘음). 확인은 `usage.cache_read_input_tokens`.
설명 문장은 프롬프트 캐시가 아니라 **DB 에 하루 한 번** 둔다 — (사용자 · 날짜 · 칸 지문)이 같으면 다시 안 부르고 안 센다(U41).

**한도 · 비용(U41 · U42)** — `lib/coach/ai-gate.ts` 의 `aiGate(userId, kind)` 하나가 부르기 전에 판정한다. 하나라도 걸리면 AI 없이 규칙으로:
1. 국외 이전 동의 없음(U43) → 대화 칸 숨김 · 정해진 문장
2. 만 14세 미만(U21)
3. 사람마다 하루 30마디(대화만 셈, 한국 날짜) → '오늘 대화는 다 썼어요. 내일 다시' · 단추 조정은 그대로. `CoachLog` 줄 세기(`lib/community.ts rateLimitError` 와 같은 방식)
4. 이번 달 전체 비용 ≥ `COACH_AI_MONTHLY_USD`(기본 30) → 그달 남은 동안 규칙만(설명 포함). **0 이면 AI 끔** — 비상 스위치 겸
5. 열쇠 없음
- 비용 셈: 응답 `usage`(입력 · 캐시 쓰기 · 캐시 읽기 · 출력, 생각 포함) × 값표(`lib/coach/ai-price.ts`, 모델별 $/MTok) → `CoachLog.costMicro`. 이번 달 합 = `CoachLog` 합. 동시에 들어온 요청이 상한을 몇 센트 넘을 수 있는데 괜찮다.
- 겉 안전망: Anthropic 콘솔 작업 공간 지출 한도(예: 월 $40)를 사용자가 걸어 둔다 — 코드가 틀려도 거기서 막힌다.
- 어림: 대화 한 마디 ≈ 입력 3~4천 토큰(절반 캐시) + 출력 0.5~1천 토큰(생각 포함) ≈ $0.02~0.03 → 월 $30 ≈ 대화 1,000~1,500마디. 설명(Haiku 5.5)은 한 번에 $0.001 밑.
  **한 사람이 매일 30마디를 다 쓰면 월 약 $20** — 베타 몇 명으로도 상한에 닿을 수 있다. 첫 2주 `CoachLog` 실제 값을 보고 상한 · 모델을 다시 묻는다(모델은 환경변수 한 줄).

**동의(U43)** — 코치 시작 흐름(4단계) 소개 다음 화면 하나에 따로 체크 둘: 건강정보(2단계, 아직 없으면) · AI 회사로 보내기(국외 이전). `AnalysisConsent` purpose `'coachAi'`(3절) · 판 번호 · 철회.
- 거부해도 코치가 시작된다(대화 칸 없음 · 정해진 문장). 코치 설정 › 'AI 끄기' = 철회 → 대화 기록 지움 + 규칙만.
- 동의 화면에 알릴 것(개인정보보호법 국외 이전): 받는 자 Anthropic, PBC · 연락처 · 나라 미국 · 때와 방법(대화 · 설명을 부를 때마다, 암호화된 연결) · 항목(위 '보내는 것') · 목적(코치 대화 · 설명) · 보유 기간(확인한 값) · 거부 방법과 거부하면 어떻게 되는지.
- 처리방침: 위탁 · 국외 이전 표에 Anthropic 한 줄 · 2조 목적 · 9조 바뀐 날(5절 그대로).
