# 영상 검수 — 맥 미니·맥북 공통 재개 지점

2026-11-11 사용자 승인. 운동영상과 메커니즘 영상 검수의 **비민감 진행 기록**을 원격 Git으로 공유한다. 채팅 기억이나 컴퓨터별 외부 JSON만을 재개 근거로 쓰던 방식을 대체한다. 앱 기능·영상·DB를 바꾸는 작업이 아니다.

## 경로와 담당

- 운동영상: `exercise/yunho/` — 금윤호의 파워·코어·암케어·회복보강. 김민 기록은 별도 `exercise/min/`에 두며 현재 동기화 도구 허용 범위는 yunho뿐이다.
- 메커니즘: `mechanics/yunho/` — 메커니즘 영상 담당의 실제 순서·판정. 운동영상과 합치지 않는다.
- 각 담당이 `checkpoint.json`과 영상별 메모를 유지한다. 원본 로컬 기록은 백업으로 보존한다. 공유용 파일과 로컬 원본이 다른 경우 복원 근거와 누락 범위를 명시한다.

## 검수 기록에 반드시 남길 내용

1. 검수자·파트·기록한 컴퓨터·세션·수정 시각(시간대 포함), 실제 근거와 원본 기록의 범위.
2. 현재 영상 ID·제목·분류·목록 순서·영상 버전/비밀 없는 식별자. 다음 영상 ID와 제목, 다음 행동, 보류·미재생·재검수 항목.
3. 실제 확인 범위(전체/일부/미재생), 반복 재생 확인 여부, 촬영 필요 여부.
4. **사용자 판정/원문 수정 지시와 GPT 관찰·제안을 분리.** 시간대별 편집 지시·설명 수정 후보·촬영 필요·결정 대기·반영 여부를 기록한다. 제안을 승인/적용 완료로 바꾸지 않는다.
5. 검수 방법: 영상·설명 대조, 확인한 장면, 학술/공식 출처와 적용 한계, 국가별 확인 필요. 근거가 없으면 미확인으로 남긴다.
6. 완료/보류의 의미와 다음 이동 승인 여부. 완료 목록만 옮기고 실제 메모를 빠뜨리지 않는다. '종료·멈춤'은 현재 영상을 보존하며 '오케이/다음'만 기존 규칙에 따라 이동한다.

## 작업 시작·재개 — 사용자가 다시 인계하라고 할 필요 없음

1. AGENTS/WORKFLOW/SESSION_COORDINATION과 이 문서를 읽고 session-guard를 실행한다.
2. 작업 시작 때 `python3 scripts/video-review-sync.py receive`로 원격 기록을 확인한다. 다른 세션이 같은 로컬 파일을 수정 중이면 해당 claim을 먼저 조율한다. 전체 체크아웃에 무작정 pull/reset/stash하지 않는다.
3. 자기 파트의 체크포인트와 실제 영상별 메모를 **직접 읽는다.** 마지막 확정·남은 메모·다음 행동을 짧게 안내하고 해당 영상부터 연다. 원격 파일 수신만으로 로그인·실제 영상 재생까지 확인됐다고 하지 않는다.
4. 맥북에 미공유 기록이 있으면 보존하고 대조한다. 같은 판에서 두 컴퓨터가 각각 바꿨으면 최근 시간만으로 승자를 정하지 말고 양쪽 사용자 판정을 병합한다. 충돌 범위만 보류한다.
5. 네트워크/권한/도구/기록이 없으면 '최신 수신 미확인'을 명시한다. 완료를 지어내거나 1번부터 초기화하지 않는다. 오프라인 기록은 로컬에 남기고 동기화 가능한 다음 작업 시 재시도한다.

## 매 영상 판정·메모·종료 후 자동 인계

- 사용자 의견/판정이 생기면 현재 영상별 메모와 체크포인트를 저장하고 다시 읽어 확인한다. 특히 다음 영상으로 넘어가기 전과 세션 종료 전에 누락을 확인한다.
- 공개 저장소에 올려도 되는 내용인지 사람이든 담당 에이전트든 실제 검토한 뒤 `python3 scripts/video-review-sync.py publish --reviewed-public-safe`로 **검수 기록만** 커밋·푸시한다. 이는 이번 사용자 지시의 지속 승인으로 매번 별도 '올려줘'를 기다리지 않는다.
- 앱 코드·DB·영상 업로드·OTA·제품 배포는 이 승인에 포함되지 않는다. 검수 의견은 실제 콘텐츠 적용 승인이 아니다. 정상 Git push가 운영 패치노트 DB를 쓰므로 기록 전용 도구는 그 push에서만 hook을 생략하고 기존 전역 설정은 유지한다.
- 원격 ref와 대상 파일이 일치한 것을 확인한 뒤에만 '공유 완료'다. 받는 컴퓨터에서 receive한 ref를 확인하기 전에는 '맥북 수신 완료'라 하지 않는다.
- 앱 간 채팅/탭/로그인은 자동 복제되지 않는다. 두 컴퓨터가 꺼져 있어도 계속 실행되는 감시기가 아니다. **검수 세션이 실행 중일 때 판정 후 공유, 재개 시 수신**하는 구조다. 새 상주 자동화·무한 폴링은 만들지 않는다.

## 공개 저장소에 넣지 않는 내용

인증정보·키·서명 URL/초대 토큰·영상 원본·비공개 촬영/재생 주소·개인 건강정보·제3자 개인정보·비공개 논문 전체를 넣지 않는다. 운동/드릴 ID, 허용된 제목, 초 단위 수정 메모, 공개 출처 링크와 검수 운영 기록만 공유한다. 민감한 원문은 로컬에 보존하고 공유 기록에는 제외 사실과 비밀 없는 참조를 남긴다. 자동 탐지는 보조 장치이며 전체 안전성을 보증하지 않는다.

## 기존 기준

반복 재생은 각 체크포인트에 복원된 최신 사용자 지시가 우선이다(예: 직접 촬영 영상은 새 플레이어 적용 전 반복 설정 생략). 과거 공통 안내로 최신 유형별 예외를 덮어쓰지 않는다. 운동영상의 상세 순차 시청·반복·학술 근거·사용자 승인 기준은 `docs/shoot/exercise-video-review-guide.md`를 따른다. 메커니즘은 실제 해당 파트의 사용자 지시·기록을 함께 따른다. 반복 종료/시간 경과/컴퓨터 변경은 자동으로 다음 영상으로 넘어가는 승인이 아니다.

## 맥북 최초 수신

이미 공유된 정상 checkout에서 기존 담당 세션이 `git fetch origin` 후 `git show origin/main:AGENTS.md`와 `git show origin/main:docs/reviews/handoff/README.md`를 읽어 새 규칙을 적용한다. 아직 로컬에 도구가 없고 전체 pull이 다른 미완료 변경과 충돌하면 원격의 검수 도구만 저장소 밖 임시 파일로 받아 해당 저장소를 현재 폴더로 두고 receive를 실행한다. 원격에도 도구가 없으면 도구 준비 중으로 알리고 기록을 git show로 읽기만 한다. 원격의 변경을 무조건 실행하거나 전역 초기화하지 않는다. 최신 검수용 도구가 공개·검사된 ref임을 확인한다. 맥북에서 실제 fetch/receive를 확인하기 전에는 초기 설치·수신 완료가 아니다.
