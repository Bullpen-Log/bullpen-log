이 문서는 금윤호의 운동영상과 메커니즘 영상 검수를 맥북에서 이어가기 위한 진입점이다. 검수는 두 분야에서 별도로 이어가며, 현재 사용자의 확인을 기다리는 항목을 임의로 완료하거나 다음 영상으로 넘기지 않는다. 컴퓨터 변경은 다음 영상 승인이나 제품 배포 승인이 아니다.

## 먼저 최신 기록 받기

1. 맥북의 기존 저장소에서 `AGENTS.md`, `docs/WORKFLOW.md`, `docs/SESSION_COORDINATION.md`, `docs/reviews/handoff/README.md`를 읽고 자기 세션 ID로 협업 확인을 한다. 기존 로컬 미공유 기록이 있으면 보존한다.
2. 저장소에서 `python3 scripts/video-review-sync.py receive`를 실행해 최신 검수 전용 기록을 받는다. 로컬과 원격 충돌, 연결 실패, 권한 문제는 덮어쓰거나 초기화하지 말고 해당 범위를 보고한다. 전체 `git pull`, reset, stash로 다른 작업을 덮지 않는다.
3. `docs/reviews/handoff/mechanics/yunho/VIDEO-REVIEW-RULEBOOK.md`를 최신 원격 기록에서 열어 전체를 읽는다. 운동·메커니즘 공통 필수 룰북이다. 받은 원격 ref와 실제 파일을 확인한다. 탭·로그인·개인 대기열은 컴퓨터 사이 자동 복제되지 않는다.
4. 아래 각 분야의 `checkpoint.json`과 `video-records.json`을 함께 읽는다. 오래된 README, 날짜가 지난 순서 계획, 과거 완료 수와 현재 상태가 다르면 최근 명시적인 사용자 판정·영상별 기록을 우선하고 모순은 보고한다. 양쪽 기록은 합치지 않는다.
5. 새 컴퓨터에서 실제 항목 ID, 영상과 설명, 재생을 확인하고 사용자가 보는 오른쪽 화면에 현재 항목을 보여 준다. 반복 재생은 지원되는 플레이어에서 켜짐만 확인하며 반복 종료를 기다리지 않는다. 영상이 안 열리면 완료했다고 말하지 않는다.

원격 저장소: https://github.com/Bullpen-Log/bullpen-log. 접근 가능한 기존 checkout에 도구가 없다면 먼저 원격의 `docs/reviews/handoff/README.md` 안내를 따라 공개된 최신 sync 도구를 확인하고 받는다. 맥북에서 실제 receive와 ref를 확인하기 전에는 수신 완료가 아니다.

## 운동영상 — 금윤호

- 재개 기준: `docs/reviews/handoff/exercise/yunho/checkpoint.json`, `video-records.json`, `RESUME.txt`. 검수자 범위는 파워·코어·암케어·회복 및 보강이다. 김민의 워밍업·상체·하체·모빌리티와 분리한다.
- 이 안내 작성 시점의 현재 항목: **밴드 저항 데드리프트**, ID `50298d2b-fd1f-4265-8b67-e95c7815335e`, 사용자 확인 대기. 제목과 네 항목의 설명은 저장과 화면 표시를 확인했다. 기존 **강도 높음, 상급, 바벨·밴드, 3세트 × 5회, 180초 휴식**을 유지했다.
- 현재 확인할 것: 영상에서 밴드의 실제 고정 위치, 시작과 끝, 썸네일. 바벨 무게와 밴드 저항의 함께 기록은 코드 기준으로 확인했으나 실제 사용자 기록 저장·재조회는 미검증이다. 기존 설명에는 밴드가 같은 길이로 고정된다는 안내가 있으므로 실제 시범과 대조한다.
- 직전 케틀벨 스윙은 사용자 지시에 따라 사라지는 효과 없이 끝을 잘라 실제 연결·재생을 확인했다. 원본은 보존했다. 기기별 영상 캐시나 다운로드 갱신은 미검증이다.
- 세트·횟수·휴식, 부위·강도·난이도·장비·좌우·기록 단위와 밴드 역할, 영상 및 설명을 매번 검수한다. 바뀐 값은 이전 값과 함께 보고한다. 촬영 필요와 재촬영 사유는 영상별 기록과 체크포인트에서 구분해 누적한다.

## 메커니즘 영상 — 금윤호

- 재개 기준: `docs/reviews/handoff/mechanics/yunho/checkpoint.json`, `video-records.json`, `provenance.json`, `VIDEO-REVIEW-RULEBOOK.md`와 해당 분야 담당의 최신 인계. README에 남은 예전 1번 상태는 역사적 기록이다.
- 메커니즘 담당이 실제 대조한 재개 위치는 **14번 힌지 홉 스로우 (큰 메디신볼)**, drill ID `f0f70f7e-1b6a-479f-9647-d626fea53c3f`다. 참고 영상·촬영 필요·사용자 확인 대기이며 발 순서와 드롭·드리프트 분류는 미확정이다. 사용자가 비교를 요청해 기존 브라우저에는 13번이 표시되어 있지만, 검수 위치를 13번이나 15번으로 옮긴 뜻은 아니다. 같은 체크포인트의 예전 `current`에는 12번이 남아 있다. 담당이 확인한 최신 위치와 영상별 기록을 사용하고, 실제 확인 전 14번 완료나 다음 이동을 추정하지 않는다.
- 담당의 다른 분리 작업 폴더에는 기준이 확인되지 않은 서로 다른 로컬 기록이 있어 수신 충돌로 보존 중이다. 이 기록은 덮어쓰지 말고 맥북 기록과도 대조·조율한다. 맥 미니의 현재 본 저장소 기록 세 파일은 원격과 일치함을 확인했다.
- 드릴 설명 작성·수정 전 Driveline 공식 공개 자료를 확인하고 실제 시범과 대조한다. Tread를 주장할 때는 해당 원자료도 확인한다. 직접 연구와 유사 동작의 간접 근거를 구분하고 출처·확인 범위·한계를 기록한다.

## 공통 작업 방식

- 제목, 장비 명칭과 원본 의미, 시범과 설명의 일치, 영상 편집·자체 촬영 썸네일, 근거와 안전·국가별 권리/표현 검토를 확인한다. 직접 촬영본 없음과 참고 영상만 있음을 구분한다. 영상별 사용자 요청은 즉시 반영하고 원본 및 이전 편집본은 보존한다. 사용자가 지정한 끝 장면을 우선한다. 자동 반복을 위해 사용자가 금지한 종료 페이드 효과를 넣지 않는다.
- 설명은 `어떤 운동인가 / 이렇게 하세요 / 투수에게 왜 필요한가 / 강도`의 네 항목, 쉬운 말, 장비 명칭 통일, 문장과 화면의 실제 줄바꿈·번호 정렬을 확인한다. 보조 운동은 투구에 억지로 직접 연결하지 말고 보조 능력 → 적합한 후속 훈련 → 투구에 필요한 능력을 근거 수준에 맞춰 설명한다. 효과·구속·전이를 단정하지 않는다.
- 설명과 수행 설정은 코드로 정확한 ID·이전 값을 확인하고 필요한 부분만 조건부 변경한 뒤 저장값을 다시 읽는다. 실제 화면 표시 확인은 별도다. 공유 운영 DB에 바로 반영되므로 다른 세션의 변경을 보존하고 이전 값이 달라졌으면 멈춰 확인한다. 영상 변경 뒤 재생 주소 캐시 갱신과 실제 재생을 확인한다. 종전 케틀벨 사례에서는 직접 변경 직후 재생 실패가 발생해 관리자 저장 동작으로 캐시를 갱신했으며, 이 과정에서 목표 부위 순서가 바뀌어 DB에서 원래 순서를 복원했다. 안전한 코드 기반 갱신 방법과 다른 기기 캐시는 별도 확인이 필요하다.
- 각 영상의 수정 전후와 사용자 지시·검토 근거·미확인 사항을 기록하고 비민감 검수 기록만 승인된 `video-review-sync.py publish --reviewed-public-safe`로 공유한다. 사용자 ‘다음/오케이’ 전에는 현재 영상에 머문다.
- 실제 사용한 참고자료는 공통 룰북과 `docs/reviews/review-evidence-registrar.md`의 운영 준비·본인 계정·정확한 도구 판 조건이 확인된 경우 등록한다. 맥북이 수정된 도구를 실제 받았는지와 운영 준비 여부는 맥북에서 확인한다. 대기·시험 결과를 중앙 등록 완료라고 적지 않는다.
