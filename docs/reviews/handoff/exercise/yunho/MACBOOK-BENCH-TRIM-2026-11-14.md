# 밴드 스피드 벤치 프레스 영상 편집 요청

2026-11-14. 사용자 원문: “영상의 마지막 횟수에서 한번끊겼다가 어색하게 한번 더 하는 걸 영상에서 편집으로 잘라줘”. 현재 운동은 계속 `EX-Y-NEW-BAND-SPEED-BENCH`; 다음 이동 승인은 없었다.

맥북에서 라이브러리 재생 영상의 1920×1080, 약 60fps 사본을 내려받아 보존했다. 화면별 확인에서 약 7.2~7.55초 정상 밀기 완료 후 7.9초 부근 다시 움직이므로, 0~7.65초의 편집 파일을 별도로 만들었다. 내보내기 성공, 길이 7.65초 및 끝 장면을 확인했다. 연속 재생을 통한 자연스러움의 사람 확인은 남았다.

영상 라이브러리 교체·업로드는 하지 않았다. 촬영 관리자 기본 편집기의 기존 서버 동작은 새 영상 연결 후 기존 저장소 영상과 썸네일을 지울 수 있어 사용하지 않았다. 기존 라이브러리 원본은 그대로다. 맥북에 원본 사본과 편집본이 있으며, 원본 사본이 촬영 카메라의 원본과 동일한지는 확인하지 못했다. 영상 파일·서명 주소는 이 공유 기록에 넣지 않았다.

## 사용자 승인 후 운영 라이브러리 적용

사용자가 “이거로 적용시켜줘”라고 명시해 편집본을 해당 운동에 연결했다. 저장소의 기존 원본을 내려받아 맥북 재생 사본과 해시가 일치함을 확인하고, 원본을 지우지 않는 단일 운동 전용 `shoot-trim/apply.mjs` 절차로 새 영상·썸네일을 새 경로에 올렸다. 대상은 운동 ID `c0e39a5a-b78d-48ed-b1ba-f2fd7b265009` 한 개. 이전 경로와 새 경로 및 되돌리기 정보는 맥북 작업 폴더의 `applied.json`에 보존했다. 실제 DB에 새 영상이 연결됐고 저장소의 이전 원본과 새 영상이 각각 로컬 사본과 일치함을 확인했다. 카메라 촬영 원본과의 동일성은 미확인이다.

사전 `npm run backup`은 BigInt JSON 직렬화 오류로 실패했다. 저장소 코드를 수정하지 않고 BigInt를 십진 문자열로 직렬화하는 임시 실행 방식으로 다시 백업에 성공했다. 이 백업은 현 맥북 Prisma 스키마가 아는 표를 기준으로 하며 다른 스키마의 완전한 백업이라고 단정하지 않는다. 백업에 개인정보가 있어 공유하지 않는다.

처음 운영 검수 화면에서 새 영상 주소가 캐시에 등록되지 않아 재생 오류가 났다. 해당 운동의 기존 설정을 관리자 화면에서 변경 없이 다시 저장해 라이브러리 캐시를 갱신한 뒤 검수 화면에서 약 7초 편집본이 재생됨을 확인했다. 다른 계정·기기 및 앱에 내장된 영상 갱신 여부는 미확인이다. 사용자에게 현재 운동은 그대로 유지하며, 다음 운동 이동 승인은 아직 없다.
