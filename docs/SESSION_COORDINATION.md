# 싱커 전체 세션 공통 협업 규칙

2026-11-09 사용자 지시. Claude·GPT의 메인/서브/기능별 세션과 이후 생성되는 모든 싱커 작업에 적용한다. 역할·발주·검수는 `WORKFLOW.md`가 최신 기준이다. 즉시 알림을 보장하는 시스템은 아니다. **시작·재개·수정 직전 확인**을 필수로 한다.

## 책임

- 사용자 명시(2026-11-09): **GPT의 현재 전체 총괄 세션이 싱커 프로젝트 전체 책임자**다. GPT·Claude 모든 작업의 우선순위, 역할, 공통 파일 담당과 충돌 조정, 최종 검토를 총괄한다. Claude 메인은 전체 총괄 아래에서 Claude 작업을 조율한다. 공통 파일의 실제 수정 담당은 한 세션만 둔다. 사용자 지시가 최우선이고 중요한 제품·정책 결정 및 배포 승인은 사용자에게 있다. 이 역할은 도구 접근 권한이나 보안 제한을 확대하지 않는다.
- 서브1은 세션 준비·분배를 도울 뿐 총괄 권한을 넘겨받지 않는다. 기능별 세션은 승인된 범위만 수행한다.
- GPT는 발주·설계·검수, Claude는 발주된 구현을 맡는다. 초기 'Claude 분석 전용'을 영구 제한으로 해석하지 않는다. 구체적인 발주가 분석이면 그 건은 분석만, 구현이면 그 승인 범위의 구현을 수행한다. 협업 규칙만으로 미발주 기능·DB·배포 권한을 새로 부여하지 않는다.

## 매 작업 시작·재개 시

1. 현재 AGENTS.md, CLAUDE.md, 이 문서, 관련 HANDOFF.md를 다시 읽는다. 이전 대화의 요약을 현재 파일 상태로 간주하지 않는다.
2. 아래 check를 실제 실행한다. 자신의 고유 채팅 ID를 사용한다(Claude/GPT 접두사 권장). 현재 경로·브랜치·HEAD, 이전 확인 이후 바뀐 파일과 다른 세션의 담당 파일을 확인한다.
3. git status --short, git log -5 --oneline과 관련 파일의 git diff를 읽는다. check 출력은 변경의 원인을 특정하지 않으므로 자기 변경/다른 변경을 직접 구분한다. 첫 확인에는 현재 변경 전체를 검토한다. HEAD가 바뀌면 해당 커밋과 HANDOFF도 확인한다.
4. 다른 세션이 작업 중인 파일, 공개 계약(경로/데이터/언어/권한 등)이 겹치면 해당 수정만 보류하고 메인과 담당을 조율한다. 독립적인 읽기·다른 파일 작업은 계속할 수 있다. 기록 없는 기존 변경도 주인 없는 파일로 간주하지 않는다.

```sh
python3 scripts/session-guard.py check --session '<고유 채팅 ID>'
```

## 수정 직전·수정 중

- 수정할 정확한 파일을 claim으로 등록한다. 디렉터리는 좁은 범위에만 사용한다. 상위/하위 경로 겹침도 충돌로 판정한다. 종료코드 2이면 수정하지 말고 원인을 확인한다. 오류를 무시하고 진행하지 않는다.
- 등록 전 현재 파일을 다시 읽는다. 등록은 다른 세션에 대한 협조 요청이지 실제 파일 쓰기를 막는 잠금이 아니다. 등록 후에도 각 수정 묶음 직전에 check와 해당 파일 내용/diff를 다시 확인한다.
- 예상 밖 변경이 보이면 이전 사본을 덮어쓰지 않는다. 멈춰 재독하고 작은 패치로 통합한다. 공통 auth/RPC/player/layout/release/schema/package와 문서도 동일하다.
- 체크아웃/브랜치 전환, reset/stash, 의존성·서버·빌드 설정 변경은 다른 세션에 영향을 준다. 미완료 변경과 실행 중 작업을 먼저 조율한다. 이 도구는 그런 작업의 허가가 아니다.

```sh
python3 scripts/session-guard.py claim --session '<고유 채팅 ID>' --paths 'path/to/file.ts' --note '승인된 작업과 목적'
python3 scripts/session-guard.py check --session '<고유 채팅 ID>'
```

## 수정 완료·중단·인계 시

- 자신의 claim을 release하고 note에 변경 파일/동작/검사/미검증/후속 작업을 요약한다. 부분 완료면 수정 중인 파일만 유지한다. 다른 세션의 기록은 임의로 해제하거나 오래됐다는 이유만으로 탈취하지 않는다. 종료된 세션은 메인이 실제 종료와 변경 보존을 확인한 뒤 조율한다.
- 다른 파트에 영향을 주면 메인에 변경을 통지한다. 사용자가 승인한 세션 간 채널만 이용하며, 전송 성공/수신 확인/아직 미전달을 구분한다.
- 컴퓨터 간 공유는 HANDOFF.md와 승인된 커밋/푸시 전달로 한다. 이 요청만으로 푸시·배포하지 않는다. 수신 컴퓨터가 실제 받은 커밋과 문서를 확인하기 전에는 전달 완료로 간주하지 않는다.

```sh
python3 scripts/session-guard.py release --session '<고유 채팅 ID>' --note '변경 요약; 검사와 한계; 다음 작업'
```

## 도구 범위와 한계

- 표준 Python3만 사용하며 서버·DB·네트워크를 건드리지 않는다. 상태는 git common directory의 sinker-session-coordination/registry.json에 저장되어 같은 저장소의 로컬 작업트리들이 공유한다. 앱에 노출되거나 커밋되지 않는다.
- 변경된 추적 파일과 무시되지 않은 새 파일을 해시로 비교한다. .env·일반적인 키 파일은 읽지 않는다. 비밀/사용자 자료를 note에 적지 않는다. 다른 경로·별도 복제본·다른 컴퓨터의 미전달 변경, 무시된 파일과 실시간 변경 전체를 감지하지 못한다.
- check는 직전 확인과 비교한 뒤 기준을 갱신한다. 변경 목록을 반드시 검토한다. 실제 충돌 방지는 모든 세션의 규칙 준수, 현재 내용 재확인, 한 파일 한 담당 합의에 달려 있다. 자동 알림·완전한 파일 잠금·자동 병합으로 표현하지 않는다.
- 기존 실행 중 세션은 최초 통지 이후 다음 안전한 구분점부터 적용한다. 진행 중 작업을 중복 시작하거나 불필요하게 중단하지 않는다. 새 전문 세션을 만드는 담당은 이 문서를 초기 지시에 반드시 포함한다.
