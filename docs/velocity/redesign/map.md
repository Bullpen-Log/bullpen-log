# 구속 측정 재설계 — 능력 지도(2026-10-23 승인 · 김민)

모듈마다 스펙은 이 폴더의 `SPEC-<id>.md`. 지도 · 스펙 · 계획은 이 폴더 하나가 색인이다. 1판 목표는 아래 '정할 것' 3번 그대로(김민 승인).
진행: 최종 설계안 `DESIGN.md`(10-23) · `bench` Task 1~6 끝(`bench-findings.md`), Task 7(사파리) · 다음 현장 대기.

## 왜 다시 하나

- 9-27 ~ 10-22 엔진 판 65번 · 커밋 95개. 고칠 때마다 손에 있던 13~43구로 맞추고 같은 공으로 확인 → 새 현장에서 무너짐.
- 10-23 현장 19구: 앱이 잰 것 3구, 셋 다 스피드건보다 8~15% 낮음(127 → 110 · 108, 132 → 119). 10구는 시도 기록조차 없음.
- 구속 = 공이 화면에서 움직인 각 × 거리. 줄자 없이 거리를 공 크기(5~35px)로 재는데, 엔진의 공 크기는 진짜보다 평균 12% 크고 공마다 ±8%
  흔들린다(`docs/velocity/size-model-2026-10-22.md`). 구속 2km/h 안이면 ±2% 가 필요. 이 한 값의 오차를 세션 거리 · 문 · 보정 상수로 덮어 왔다.
- 길이 길다: 폰 공 알림(Swift 휴리스틱) → 클립 → 웹뷰 엔진(밝기 덩어리) → 세션 규칙 → 화면. 단계마다 어림 규칙이라 어디서 놓쳤는지 모른다.

## 방향 — PitchLab 벤치마킹(2026-10-23 김민)

"PitchLab 의 시스템을 벤치마킹 · SmartScout 같은 시스템은 구현이 힘들 것 같다." SmartScout 은 장면마다 공 크기로 깊이를 재는데, 우리 공 크기는
공마다 ±6.7%(목표 ±2%)라 그 길은 막혔다(`size-model-2026-10-22.md`). PitchLab(`pitchlab-method` 메모 — IPA 로 본 것):

- 폰을 투수 뒤 삼각대 · 4K60 · 분석은 폰 안 실시간.
- 거리는 **사용자가 고른다**(40 · 50 · 54 · 60.5ft) + 홈플레이트 자리에 존 네모를 맞춰 깊이 기준.
- 학습 모델: 공 감지 · 손 감지(손 떠난 순간) · 자세(릴리스 자리), 고도로 공기 보정.

우리에게 뜻하는 것:
- 엔진 2.0.0(10-07)이 이미 '넣은 거리 + 물리 궤적'이었다. 2.1.0 에서 공 크기 자동 거리로 바꾼 까닭은 실제 자리가 14~22m 로 갈리고 값이 안 맞아서였다.
  그런데 10-23 진단으로 **실제 거리를 넣어도 구속이 9% 낮은 날**이 있다(`SPEC-bench.md`) — 공 크기 상수가 이것을 덮어 왔다. 거리 입력 방식이 살려면
  이 9% 부터 잡아야 한다 → `bench` 의 첫 진단 과제 그대로.
- 걸림돌: 망에 던지는 사용자는 폰 → 망 거리를 정확히 모른다. 거리 5% 틀리면 구속 5.4% 틀린다. 그래서 고른 거리를 확인할 수단(플레이트 · 망 자리
  네모, 공 크기 어림으로 크게 어긋날 때만 알림)이 `range` 의 일이다.
- Ultralytics YOLOv8 은 AGPL — 그대로 앱에 넣지 않고, 같은 일을 하는 자체 모델(지금 MobileNetV3 공 감지처럼)로 만든다.

## 모듈

| id | 맡는 것 | 기대는 것 |
| --- | --- | --- |
| `bench` | 고정 시험대 — 현장 영상 + 스피드건 짝 + 공 라벨, 앱과 같은 길로 다시 재서 조건별 재현율 · MAE · 90% 를 낸다. **모든 변경의 문.** | — (처음엔 지금 엔진을 기준선으로 감쌈) |
| `capture` | 찍기 — 해상도 · fps · 줌 · 셔터 · 손떨림 보정 · 초점 · 기울기(IMU) · 렌즈 값, 최근 몇 초 쥐기, 클립 · 세션 녹화 | — |
| `detect` | 던짐 · 공 찾기 — 장면마다 공 상자(가운데 · 지름) · 확신, 손에서 떠난 때. PitchLab 처럼 공 감지 + 손 감지 학습 모델(지금 MotionTrigger · 밝기 덩어리 · 훑기 셋을 대신) | `capture` |
| `range` | 거리 — PitchLab 처럼 사용자가 고른 거리(목록 · 지난 거리 기억)를 기준으로, 플레이트 · 망 자리 네모(ABS `lib/abs` 플레이트 찾기 재사용)로 확인, 공 크기는 크게 어긋날 때 알림만 | `detect`, `capture` |
| `speed` | 구속 — 공 상자 + 거리 → 손에서 떠날 때 구속 · ± · 믿음 | `detect`, `range` |
| `session` | 사용자 흐름 — 자리 안내 · 설정 · 공마다 결과 · 못 잰 까닭 · 저장 | `speed`, `capture` |

화살표는 한쪽으로만: `capture` → `detect` → `range` → `speed` → `session`. `bench` 는 `detect` · `range` · `speed` 의 경계(입출력 모양)를 불러 잰다 —
모듈이 `bench` 를 부르지는 않는다.

만드는 차례: `bench` → `capture` · `detect`(나란히) → `range` → `speed` → `session`.

## 가정(바로잡아 주세요)

1. 폰 한 대, 투수 뒤만(포수 뒤는 1판 밖). 아이폰 새 앱(`native/`)이 대상, 웹 측정 화면은 따라가지 않는다.
2. 줄자는 안 쓴다 — 거리는 PitchLab 처럼 목록에서 한 번 고르고 기억한다. 스피드건은 우리(검증용)만 쓴다.
3. 다시 만드는 동안 지금 앱은 그대로 두고(새 엔진 판을 올리지 않음), `bench` 에서 새 길이 이길 때 바꾼다.
4. 공 크기 라벨은 스피드건으로 되짚는 방식(사람 손 없이)을 쓴다.
