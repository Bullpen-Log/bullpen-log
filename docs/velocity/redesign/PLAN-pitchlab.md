# 구속 측정 — PitchLab 방식으로 마무리(2026-10-25, 한 장)

**한 줄:** 거리는 사용자가 고르고(공이 멈추는 곳까지), 공은 폰 안 학습 모델이 찾고, 엔진 2.0 궤적으로 구속만 낸다. 공 크기 거리는 고른 거리를 확인 · 보정하는 데만
(공 크기 거리가 22% 넘게 짧거나 15% 넘게 길면 거리 오류로 측정 불가 — 김민 10-25). 4K · 회전수는 뺀다.
`DESIGN.md`(10-23)의 남은 단계(range · session)를 지금 아는 것으로 줄인 것.

## 2026-10-25 설계안('싱커 구속측정 신뢰성 개선', 금윤호 전달용)이 고친 결론 셋

아래 '왜 이렇게' 의 세 결론은 그대로 두되 이렇게 읽는다(설계안 02).

1. **"자 하나만 맞으면 엔진은 된다" → 가능성이다.** 사후 거리 배율로 일부 공이 맞는 것은 정답을 본 뒤의 결과다. 정답을 보지 않은 **새 세션**에서도 성립해야 결론이 된다 —
   시험대는 확인용(holdout) 묶음을 문으로 둔다(`report.mjs --strict`).
2. **"모델 좌표 전달은 필요하면 속도 개선용(4번)" → 정확한 공을 끝까지 추적하기 위한 우선 작업.** 재디코딩을 없애는 것은 따로 가는 성능 일이다. **10-25 작업 B 로 코드는 끝**
   (폰 모델 후보 → 클립 `hits` → 계산기 netHits, 폰 확인 전). 보관 투구에서 분석창 · 씨앗을 0.217초 옮기자 내부 값이 89.7 → 133.2km/h 로 바뀐 것이 거리 밖 '궤적 선택' 문제의 증거다.
3. **"4K 는 회전용이라 뺀다" → 근거가 모자란다.** 1080p 의 유효 공 픽셀이 모자라면 4K 가 중심 추정에도 도움이 될 수 있다. 화각 · 노출 · 발열과 함께 **시험하고** 정한다(넷째 묶음).

덤으로: "같은 세션 안의 비교는 늘 정확하다"도 유지하지 않는다 — 고정 거리 오차는 공유되지만 공마다 다른 추적 오류는 공유되지 않는다. 공 크기 거리는 **보조 진단**으로 두고
고른 거리 길의 선행 성공 조건으로 두지 않는다(둘이 어긋나면 사용자가 틀렸다고 단정하지 않고 추적 · 크기 · 설치 중 어느 증거가 약한지 본다 — 두 번째 묶음에서 가른다).

## 왜 이렇게(숫자)

- **자 하나만 맞으면 엔진은 된다** — 10-03 · 10-23 망 세션 21구, 세션 비율만 맞추면 ±3km/h 안 19/21 · MAE 1.6(`bench-findings.md` 6-2).
- **거리의 함정** — 망 앞면까지 거리를 넣으면 5~11% 낮다(24구 중 ±3 안 0). 공은 망 안쪽 1~2.6m 뒤에서 멈춘다. 미트로 받은 10-09 는 +2%(6구 중 5구 ±3 안).
- **공 크기 거리만으로는 모자란다** — 1080p 에서 끝의 공이 5~6px 라 공마다 5~7% 흔들리고, 앱 녹화(10-23)에선 빠른 공일수록 짧게 잡혔다(까닭 모름 — 셔터는 이미 1/6289, 압축 다시 하기 시험은 분명하지 않음). 그래서 값은 고른 거리로, 공 크기는 문으로만.
- **4K 는 지금 안 한다** — PitchLab 의 4K 는 실밥(회전) 모델용으로 보이고, 거리는 사용자에게 묻는다.

## 현장 확인(사용자 몫, 한 번)

- 앱으로 잰다: 설정에서 받는 곳 · 거리를 고른 그대로, 폰은 투수판 뒤 2m, 세션 녹화 켬, 스피드건 15~20구.
- 같은 공으로 두 값이 남는다 — 고른 거리 값(화면) · 공 크기 거리 값(`analysis.distance.kmhAtSize`). `field-report.mjs` 로 스피드건과 견준다.
- 줄자는 정답용으로만: 폰 → 공이 멈추는 곳. 사용자가 고른 거리가 이것과 얼마나 다른지가 핵심이다.
- 학습 모델 공 알림(D4)도 같이 본다.
- **합격선(미리 정함):** 던진 공 90% 잡음 · 잡은 공 80% 가 ±3km/h 안 · MAE 2.5 밑.

## 정직하게 — 남는 위험

- 망 쓰는 사람이 '공이 멈추는 곳'을 1m 틀리면 구속이 5% 틀린다(120km/h 에서 6km/h). 스피드건 없이 막을 길은 없다.
  대신 ± 를 거리 어림만큼 넓혀 보이고, 같은 세션 안의 비교(지난 공보다 +2km/h · 오늘 최고)는 정확하다(세션 안 비율 ±1.5%).
- 플레이트 매트로 거리 재기(`DESIGN.md` 4-4 의 1번 · 10-23 정한 것 1)는 망 앞면까지만 재서 같은 함정이 있다 — 이번엔 안 한다.
