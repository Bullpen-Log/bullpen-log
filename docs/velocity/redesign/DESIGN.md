## 0. 한 줄

**PitchLab 처럼 거리를 사용자가 한 번 고르고(플레이트 · 매트가 보이면 앱이 재서 확인), 학습 모델로 공과 손 떠난 순간을 찾고, 물리 궤적을 '받는 면에 닿은 때'에 묶어
구속을 낸다. 모든 변경은 고정 시험대(`bench`)의 확인용 점수로만 들어간다.**

## 2. 원칙

1. **PitchLab 벤치마킹** — 투수 뒤 삼각대 · 폰 안 계산 · 사용자가 고른 거리 + 플레이트 네모 · 공 / 손 감지 모델(`pitchlab-method` 메모).
2. **시험대가 문** — 확인용(떼어 둔) 현장 묶음 점수가 나아지고 다른 묶음이 나빠지지 않을 때만 바꾼다. 확인용을 보고 상수를 맞추지 않는다.
3. **사용자 손은 설정 때 한 번** — 던질 때마다 거리를 재거나 누르지 않는다. 줄자는 우리(정답용)만 쓴다.
4. **단계마다 남긴다** — 공마다 어느 단계에서 틀렸는지(찾기 · 거리 · 궤적 · 끝 판정)를 결과에 싣는다. 지금은 못 잰 공이 어디서 빠졌는지 모른다.
5. **설명할 수 있는 것만** — 상수로 다른 오차를 메우지 않는다(공 크기 상수 1.129 · 세션 거리 규칙이 그랬다).

## 3. 전체 흐름

```
[session]  설정: 폰 자리 안내 → 거리 고르기 → 플레이트 · 매트 자동 찾기(네모) → 수평 확인
    │
[capture]  1080p60 · 2배(기준) · 셔터 상한 · 렌즈 값 · 기울기 · 고도 · 최근 8초 쥠
    │ 장면
[detect]   ① 던짐 알림: 폰 안 공 감지(관심 영역)          ← 지금: MotionTrigger 휴리스틱 + 5초 훑기
    │ 클립(공 시각 −0.4 ~ +1.55초)
           ② 장면마다 공 상자(중심 · 지름 · 확신) · 손 떠난 때   ← 지금: 밝기 차 덩어리
    │
[range]    D(폰 → 받는 면, m) ± σ · 받는 면의 화면 자리       ← 지금: 공 크기 자동 거리 + 세션 규칙
    │
[speed]    물리 궤적 맞추기(엔진 2.0 그대로) — 처음 = 손 떠난 때, 끝 = 받는 면에 닿은 때(기하로) → 구속 · ± · 믿음 · 단계 진단
    │
[session]  공마다 결과 3초 안 · 못 잰 까닭 · 저장

[bench]    detect · range · speed 경계를 고정 현장 자료로 잼 — 모든 변경의 문
```

화살표는 한쪽으로만. `bench` 는 경계 모양만 부른다.

## 4. 모듈

### 4-1. `bench` — 고정 시험대(먼저)

스펙 `SPEC-bench.md` · 계획 `PLAN-bench.md` · 할 일 `TODO-bench.md` 그대로. 공마다 ① 앱 그대로 ② 실제 거리 넣음(PitchLab 길 — 주 판정, ±5% 로도) 두 길로 잰다.
옛 판 다섯을 같은 자료로 재서 '코드 탓인가 조건 탓인가'에 답하고, 9% 의 자리를 짚는다(5절).

**문 규칙:** 확인용 묶음의 MAE · ±3 안 비율이 신뢰구간 밖으로 나아지고, 어느 묶음도 MAE 가 1km/h 넘게 나빠지지 않을 때만 앱에 올린다.

### 4-2. `capture` — 찍기

- **기준: 1080p · 60fps · 2배 · 손떨림 보정**(지금 그대로 — 현장 자료가 다 이 조건). 공은 20m 에서 약 10px.
- 후보 둘, 현장 자료로 시험대에서 정한다:
  - **4K60 · 1배**(PitchLab): 공 크기는 거의 같고(20m 약 11px) 화면이 넓어 릴리스 · 받는 면이 늘 들어온다. 값: 발열 · 메모리 · 계산량.
  - **셔터 상한 1/2000 → 1/6000**(SmartScout 1/6289): 번짐이 줄어 중심 · 끝 판정이 또렷해진다. 가지 `lab/shutter-6000` 에 코드, 폰 확인 전.
- 클립마다 싣는 것: fps · 잰 화각(기종별 `fovProbe`) · 렌즈 값 · 기울기 · 셔터 · ISO · 카메라 시계 · **고도**(공기 밀도, PitchLab — 1000m 에서 구속 약 1%).

### 4-3. `detect` — 공 찾기

두 단계로 나눈다.

1. **던짐 알림(폰 안, 늘 켬)** — 지금 공 절반을 놓친 곳. 바꿀 것: 공 감지 모델을 폰에서(CoreML) 관심 영역(릴리스 둘레 + 날아가는 길)에 초당 15~30번 돌려 공이 손을
   떠나 멀어지는 것을 알린다. 지금 MotionTrigger(세 장면 차이 휴리스틱)와 5초 훑기는 대체 · 비상용. **먼저 시험대 Task 6 으로 10-23 에서 놓친 10구가 알림 탓인지
   재기 탓인지 가른 뒤** 만든다. Swift 라 폰 확인이 필요하다.
2. **장면마다 공 상자 · 손 떠난 때(클립마다)** — 밝기 차 덩어리 대신 학습 모델. speed 는 공 **중심**을 주로 쓰고 지름은 거리 확인에만 쓴다. 공 감지는 지금 모델
   (MobileNetV3, 3판 — 스피드건으로 되짚은 진짜 지름)을 바탕으로 10-23 자료를 더해 다시 배운다. **손 떠난 때**는 새 손 감지 모델(라벨: 세션 녹화에서 릴리스 장면 찍기 —
   공 자리 찍기 도구 `ball-labeler.tsx` 에 '릴리스' 표시 하나 더함). 자세 모델은 1판 밖.
- 모델 틀: Ultralytics YOLOv8 은 AGPL 이라 앱에 그대로 넣지 않는다. 자체 모델(torchvision MobileNet, Modal 학습 — 지금 길)로.
- 실행 자리: 클립 재기는 처음엔 지금 웹뷰 계산기(onnxruntime-web)에서. 결과 3초를 못 맞추면 CoreML 로 옮긴다.

### 4-4. `range` — 거리

차례대로 쓴다(위가 있으면 위가 이김).

1. **플레이트 · 매트가 보이면 앱이 잰다** — 홈플레이트 앞변 43.18cm 의 화면 폭으로 폰 → 플레이트 거리. ABS 코드(`lib/abs/plate-detect.ts` 앞변 찾기 · `calib.ts
   calibFromPlate`)를 그대로 쓴다. 2배 · 20m 에서 앞변 약 60px, 끝점 ±0.3px 면 거리 ±1% 안. 망에 던지는 사용자에게는 **망 앞에 플레이트 매트 놓기**를 권한다.
2. **사용자가 고른 거리** — 두 가지 중 하나(김민 10-23, 투수판 → 받는 면): **14m**(리틀 · 초등) · **20m**(중학교 이상 정식 18.44m + 포수 · 망이
   조금 뒤). 폰은 투수판 뒤 0.5m 에 두게 안내해 폰 → 받는 면은 **14.5m · 20.5m**. 지난 값을 기억한다. 다른 거리에 망을 두면 두 값 중 가까운 쪽을 고르게 하고,
   공 크기 확인(아래 3)이 크게 어긋나면 알린다.
3. **공 크기는 확인만** — 세션의 공 크기 거리 가운데 값이 고른 거리와 10% 넘게 다르면 "거리가 고른 값과 달라 보여요"(지금 2.3.10 의 `INPUT_SIZE_MISMATCH` 를 세션
   단위로). 값을 바꾸지는 않는다.

**잴 수 있는 거리(폰 → 받는 면, 1080p · 2배 · 화각 37.7° — 초점거리 약 2810px):**

| 폰 → 받는 면 | 끝의 공 | 플레이트 앞변 | 손 떠난 뒤 비행 장면(120km/h) | 판단 |
| --- | --- | --- | --- | --- |
| 10m | 21px | 121px | 약 14장 | 장면이 적어 ± 가 커짐 |
| 14.5m(리틀) | 14px | 84px | 약 22장 | 현장 자료 있음 |
| 18.9m(정식) | 11px | 64px | 약 30장 | 현장 자료 있음 |
| 22m | 9px | 55px | 약 35장 | 현장 자료 있음(가장 먼 곳) |
| 25m | 8px | 49px | 약 41장 | 계산상 가능, 자료 없음 |
| 30m | 7px | 40px | 약 50장 | 공이 너무 작음 — 안 권함 |

현장 자료로 확인된 곳은 **14~22m**(14 · 16 · 18.5 · 20.5 · 21.6 · 22.2m), 설계상 받는 범위는 **12~25m**. 고르는 두 거리(폰 기준 14.5 · 20.5m)는 모두 확인된 범위 안이다 — 단 스피드건 짝이 있는 14m 현장은 아직 적어 다음 현장에서 채운다(6절).
범위 밖은 '너무 가깝다 / 멀다'만 알린다. 25m 를 넘기려면 4K 나 셔터 1/6000 을 현장에서 시험한 뒤(4-2).

내보내는 것: `{ D, sigma, source: 'plate' | 'chosen', plane }` — `plane` 은 받는 면의 화면 자리(네모). 고른 거리만이면 σ 를 5% 로 두고 결과 ± 에 넣는다.

### 4-5. `speed` — 구속

- **엔진 2.0 의 물리 궤적 맞추기를 그대로 쓴다**(`trajectory-fit.ts` — 화면 자리에 3차원 궤적, 깊이 비율은 원근에서, 끝 깊이 = D). 공 크기를 정확히 재지 않아도 되는 길.
- **바꿀 곳은 끝과 처음.** 지금 끝 시각 te 는 '맞고 튄 줄과 가장 가까운 때' 아니면 '마지막으로 잡힌 장면 + 반 장'(`analyze-distance.ts impactTime`)이라, 공이 망에
  박혀 느려지는 장면을 비행으로 세면 te 가 늦어지고 구속이 낮게 나온다(5절 H1). 새 끝 = **궤적이 받는 면(`range.plane`, 깊이 D)에 닿는 때**를 기하로 정하고,
  그 뒤 장면은 잔차가 커지는 곳에서 자른다. 처음 = 손 감지 모델의 손 떠난 때.
- 공기저항은 고도로 밀도 보정, 기울기는 IMU(지금처럼).
- 내보내는 것: 구속 · ±(거리 σ + 궤적 공분산) · 믿음 · **단계 진단**(찾은 장면 수 · 처음 / 끝 시각과 그 근거 · 잔차 · 거리 근거).
- 버리는 것: 공 크기 자동 거리(`AUTO_BLOB_SIZE_RATIO`) · 세션 거리 규칙 · 거리 보정 상수.

### 4-6. `session` — 사용자 흐름

새 앱(`native/`)의 지금 카메라 화면 · 모드 시트를 그대로 쓰고 속만 바꾼다.

1. 설정(한 번): 폰 자리 그림(투수 뒤 · 투수판 뒤 0.5m · 삼각대) → 거리 고르기 → 플레이트 · 매트 자동 찾기(못 찾으면 건너뜀 또는 직접 맞추기) → 수평.
2. 재기: 공마다 3초 안 결과. 못 재면 까닭 한 줄(공을 못 찾음 · 끝이 안 보임 · 거리 확인 필요 …).
3. 저장: 지금 서버 동작 그대로.

## 5. 거리 밖 9% — 가설과 시험

엔진은 te 의 깊이를 D 로 놓는다. 그래서 te · 처음 시각이 틀리면 구속이 그대로 틀린다(비행 0.55초에서 9% ≈ 50ms ≈ 60fps 3장).

| 가설 | 뜻 | 예측 | 시험대에서 |
| --- | --- | --- | --- |
| H1 끝이 늦음 | 망에 박혀 느려지는 장면을 비행으로 셈 | '튕김' 끝 공은 치우침이 작고 '끝' 끝 공은 낮다(10-06 −1% 는 튕김일 것) | 끝 종류별로 가름 · 사람이 찍은 닿은 장면으로 te 를 바꿔 다시 잼 |
| H2 처음이 틀림 | 손 떠난 때 · 처음 깊이를 잘못 잡음 | 처음 잡힌 깊이가 깊을수록 치우침 | 릴리스 라벨로 바꿔 다시 잼 |
| H3 화각 | 초점거리가 틀림 | 깊이 비율은 화각에 거의 안 변해 작아야 함 | 화각 ±5% 흔들기 |
| H4 기울기 · 공기저항 | 숙임 · 저항 배율 | 날씨 · 폰 자리별로 갈림 | 숙임 · K 흔들기 |
| H5 폰 → 망 거리 | 폰이 0.5m 보다 훨씬 뒤 | 9% 면 폰이 약 1.8m 더 뒤 — 낮을 것 | 다음 현장에서 줄자로 폰 → 망 |

한 가설이 9% 의 대부분을 설명하면 `speed` 를 그쪽부터 고친다. 둘 다 아니면 자료(장면 번짐 · 빠진 장면)를 본다.

## 6. 자료 계획

- **현장 세션 프로토콜**(다음부터 매번): 세션 녹화 켬 + 앱 측정 켬 · 스피드건 값 순서대로 · 줄자로 **폰 → 받는 면** · 플레이트(또는 매트)가 화면에 들어오게 · 메모에 날씨.
- **두 거리 모두**: 투수판 → 망을 **14m · 20m** 로 줄자로 맞춰 각 15구 넘게(같은 날이면 좋음). 14m 묶음은 지금 거의 없다.
- **확인용 묶음**: 10-23 + 10-21 줄자 세션, 앞으로의 현장은 처음엔 확인용으로 넣는다. 확인용을 보고 고치면 맞추기용으로 넘긴다.
- **라벨**: 공 지름은 스피드건으로 되짚기(사람 손 없이, 3판 방식), 손 떠난 장면 · 닿은 장면은 사람이 찍는다(컷마다 두 번 누름).
- **4K · 셔터 비교**: 같은 날 같은 투수로 조건만 바꿔 각 15구 넘게.

| P3 | `detect` — Task 6 로 놓친 곳 가르기 → 던짐 알림(CoreML) · 공 / 손 모델 | 16~24시간 + 폰 확인 | 확인용에서 던진 공 90% 이상 잡음 · 헛 알림 분당 1번 밑 |
| P4 | `capture` — 4K · 셔터 비교(현장) | 4시간 + 현장 1번 | 시험대에서 이기는 조건만 |
| P5 | `session` — 흐름 묶기 · 앱에 올림(TestFlight) | 8시간 | 1판 목표 전부(지도 3번) |

P1 과 P3 의 Task 6 은 나란히 할 수 있다. 사용자 몫: 현장 세션 2번 이상(줄자 · 매트 · 스피드건).

**1판 목표**(지도 승인): 확인용 현장에서 던진 공 90% 이상 잡음, 잡은 공 80% 이상이 스피드건 ±3km/h 안, MAE 2.5 밑, 던진 뒤 3초 안, 100~145km/h.

## 10. 정한 것(김민 10-23)

1. 망에 던지는 사용자에게 **망 앞에 플레이트 매트 두기를 권한다**(없으면 고른 거리로).
2. 거리는 **14m · 20m 두 가지**(투수판 → 받는 면, 폰 → 받는 면 14.5 · 20.5m).
3. 시험대 WebKit 은 **맥 사파리(safaridriver)** — 새 패키지 없이 진짜 사파리 엔진. Task 7 전에 사파리에서 '원격 자동화 허용'을 한 번 켠다(관리자 암호).
4. 확인용 = 10-23 + 10-21 줄자 세션, 맞추기용 = 10-07 · 10-09 · 10-21(기준 20m) · 녹화 셋, 진단용 = 카메라 앱 파일 31구.
