# Spec: 공 라벨 자료 — 물리 엔진 분리 진단(2026-10-25, 설계안 작업 D)

설계안 '싱커 구속측정 신뢰성 개선'(2026-10-25) 첫 묶음 작업 D: **성공 · 실패를 섞은 30~50구에 공 중심 · 가림 · 릴리스 · 종점 라벨**을 만들어, 같은 영상에
① 실제 검출 ② 사람이 확인한 연결 ③ 사람이 확인한 중심 ④ 실측 공간을 단계로 적용해 **검출 · 연결 · 공간 설정 · 물리 모델 중 다음 수정 대상을 증거로 정한다.**
자료가 부족하면 어느 정답 항목이 부족한지 명시한다(아래 5절). 라벨은 사용자(현장을 아는 사람) 몫 — 도구는 `scripts/velocity-bench/overlay.html`.

## 1. 공 하나 = JSON 하나

`~/bullpen-velocity-lab/bench/labels/<공 id 를 파일 이름으로>.json` (id 의 `/ : #` 같은 글자는 `_` — `run.mjs --dump` 와 같은 규칙, `labels.mjs labelFileOf`).
저장소에는 올리지 않는다(영상과 같은 자리, 사람 · 날짜가 든다).

```json
{
  "schema": 1,
  "id": "1023:b6b85fa7#3",
  "video": "c3.mp4",
  "fps": 60,
  "frame": "upright",
  "by": "금윤호",
  "at": "2026-10-26",
  "centers": [[0.2667, 0.512, 0.488], [0.2833, 0.515, 0.47]],
  "release": 0.25,
  "end": 0.8667,
  "occluded": [[0.3, 0.3333]],
  "notes": "손이 떠난 뒤 두 장은 글러브에 가림"
}
```

| 칸 | 뜻 |
| --- | --- |
| `schema` | 이 모양의 판(지금 1). 칸을 더하면 올린다 — 읽는 쪽(`labels.mjs`)은 다른 판을 건너뛰고 알린다 |
| `id` | 시험대 공 id(`fixtures.mjs loadBalls` 의 id — 묶음:녹화#차례 또는 묶음:파일) |
| `video` · `fps` | 본 영상(참고) · 장면 간격의 기준 |
| `frame` | 좌표 기준 — `upright`(세운 화면 비율 0~1, 왼쪽 위 원점). 앱 클립 · 시험대 영상 · 모델 후보(Clip.hits) 모두 같은 기준 |
| `centers` | `[시각(초, 영상 시각 · 장면 시각으로 반올림), x, y]` — 공의 **중심**. 가린 장면은 적지 않는다(또는 occluded 로) |
| `release` | 손을 떠난 장면 시각(보이면). 모르면 null — 외삽 범위 검증(설계안 3.4)에 쓴다 |
| `end` | 받는 면(그물 · 미트)에 닿은 장면 시각(보이면). 모르면 null |
| `occluded` | 공이 가려진 구간 `[시작, 끝]` 목록 — 이 구간의 중심은 연결 안내에서 뺀다 |
| `notes` | 자유 메모(흰옷 · 그물 무늬 · 공 줍기 등 실패 유형) |

## 2. 어떤 공을 라벨하나

- **성공 · 실패를 섞어** 30~50구. 실패는 시도 기록(`VelocityAttempt`)의 `rejectCode · why` 로 고른다 — 못 찾음(no-flight) · 늦게 잡힘(late-start) · 끝 놓침(end-early · end-unseen) ·
  밝은 배경(extended) · 흔들림 · 낮은 믿음을 각각 몇 구씩.
- **날짜 · 시설 · 선수 · 기기로 나눈다** — 학습(맞추기) · 개발 검증 · 최종 시험을 투구 단위 무작위가 아니라 **그룹 단위**로 가른다(설계안 05). 같은 투구의 중복 영상은 뺀다.
- 스피드건 값이 있는 공을 우선 — 단계 ④(실측 공간)까지 가려면 **폰 → 받는 면 줄자 거리**도 그 세션에 있어야 한다(fixtures.json `trueDistM`).

## 3. 찍는 법(overlay.html)

1. `npm run velocity:bench -- --set=all --group=<묶음> --modes=app --dump=<폴더>` 로 공마다 덤프 JSON 을 만든다(궤적 · 후보 · 영상 경로).
2. `scripts/velocity-bench/overlay.html` 을 브라우저로 열어 덤프 JSON 과 그 영상(mp4)을 고른다. 빨강 후보 · 파랑 덩어리 · 초록 궤적이 영상 위에 겹친다.
3. '라벨' 을 켜고 ←/→ 로 한 장씩 가며 공 중심을 누른다(한 장에 하나, 다시 누르면 바뀜, Backspace 지움). `r` 릴리스 · `e` 끝 · `o` 가린 구간 시작/끝.
4. '라벨 내려받기' → 위 JSON. `labels/` 폴더에 둔다. `by` 는 손으로 적는다.

중심은 공의 **한가운데**(흐려 길어진 공은 그 길쭉한 모양의 가운데). 반 장(0.5/fps) 넘게 어긋난 시각은 장면이 아니라 사이에 찍힌 것 — 도구가 장면 시각으로 반올림한다.

## 4. 단계 적용(시험대)

| 단계 | 무엇을 바꾸나 | 지금 되나 | 명령 |
| --- | --- | --- | --- |
| ① 실제 검출 | 앱 그대로(모델 후보 안내 포함) | 된다 | `--modes=app,guided --net=<netseen.json>` |
| ② 사람이 확인한 연결 | 라벨 중심을 공 길 안내(netHits — 점수 1 · 지름 없음)로 넘겨 엔진이 그 둘레에서 덩어리를 찾아 잇는다 | 된다 | `--modes=app,label-link --labels=<폴더>` |
| ③ 사람이 확인한 중심 | 덩어리 중심 대신 라벨 중심을 관측으로 두고 궤적 · 거리만 돌린다 | **아직** — 엔진에 '관측을 밖에서 받는 입구'가 없다(analyze-distance 는 장면에서 덩어리를 찾는다). 입구를 만들 때 `ball-track.ts` 의 guide(모델 자리 둘레에서 찾기)를 '그 자리로 고정(pin)' 하는 옵션이 가장 작다 | — |
| ④ 실측 공간 | 폰 → 받는 면 줄자 거리 · 설치 각 | 된다(거리) | `--modes=true,true-5,true+5` — fixtures `trueDistM` 이 있는 묶음만 |

①→② 가 좋아지면 **연결(추적)** 이, ②→③ 이 좋아지면 **중심 추정** 이, ③ 까지 맞는데 ④ 에서 틀리면 **공간 설정 · 물리 모델** 이 다음 수정 대상이다. 레이더 값에 맞게 역산한 거리로
물리 엔진을 합격시키지 않는다(설계안 작업 D) — ④ 는 줄자 거리만.
