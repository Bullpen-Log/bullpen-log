## 1. 한 줄 요약

데스크톱 세션은 10-16 부터 **엔진 쪽**을 맡았어요. 빠른 공이 느리게 나오던 것(2.6.0), 알림이 침묵하면 공을 놓치던 것(2.7.0 훑기 · 세션 녹화),
공 찾기를 학습 모델로(2.7.1)까지 했어요. **10-19 에 사용자가 엔진을 금윤호에게 넘겼어요**("금윤호가 이어서 할거야"). 금윤호가 거리 보정 · 거리 고르기(2.7.2),
새 앱에 훑기 · 모델 옮기기, 새 앱 구속 측정 실패 복구(Phase A~D1)를 했어요. 지금 남은 큰일은 **새 앱 판을 Release 로 다시 구워 현장에서 확인하는 것**이에요.

## 2. 역할과 규칙(사용자가 정한 것)

- 2026-10-16 사용자가 세션마다 역할을 나눴어요. 이 줄기는 **구속측정 엔진 엔지니어**예요. 목표는 안정성(잡히는 비율 · 같은 공 같은 값)과 정확성(스피드건 대비 오차)이에요.
  영역은 `lib/velocity-engine` · `lib/velocity-*.ts` · `scripts/velocity*` · `scripts/velocity-lab` · `docs/velocity` · `services/velocity-detector` 예요.
  측정 화면은 UI/UX 세션도 고쳐요 — 꼭 필요할 때만, 먼저 말하고.
- **1배 줌은 엔진 개선에 쓰지 않아요.** 검증 · 문턱 · 오차표는 2배 줌 영상만(사용자: "모든 건 2배 줌으로").
- **빠른 공 = 110km/h 이상.** 합격 기준은 `engine-2.4-plan.md` G1(110~135 |평균| ≤ 1.5 · p90 ≤ 3.5).
- 엔진을 고치면 `lib/velocity-engine/version.ts` 판을 올려요(큰 · 가운데 · 작은 자리 규칙은 그 파일). 지금 **2.7.2**.
- 공용 폴더는 여러 세션이 같이 써요. **커밋은 내 파일 · 내 줄만** 골라 담아요(통째 `git add` 로 남의 미커밋 줄이 올라가 빌드가 깨진 적이 있어요).
- 사용자는 비개발자예요. 한국어 쉬운 말로, 할 일부터, 묻는 건 한 줄 + 선택지 둘.
- 학습 모델(AI)은 써도 된다고 사용자가 정했어요(쓸 때 비용 0 — 폰 안에서 돌고, 학습만 Modal 로 한 번에 150원쯤).
