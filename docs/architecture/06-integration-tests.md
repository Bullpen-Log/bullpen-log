# 6. 통합 시험 계획 · 결과 (초안 v0 · 2026-10-16)

## 6-1. 원칙

- **운영 DB 에 쓰지 않는다**(개발 = 운영). 통합 시험은 순수 함수 사슬(입력 줄 → gather 와 같은 모양 → buildFacts → 계획 · 영양 계산)을 가짜 줄로 돌린다.
  지금 셀프테스트 방식(`node --import ./scripts/alias-register.mjs …mts`)을 그대로 쓰고 새 틀은 들이지 않는다.
- 한 시험 = 한 카테고리 경계. 실패하면 어느 쪽 계약이 깨졌는지 이름으로 알 수 있게.
- DB 를 거치는 길(서버 동작 · API)은 순수 시험이 못 본다 — 사용자 흐름 확인(6-3)은 시험 계정 + 사람 확인으로.

## 6-3. 실제 사용자 흐름(사람 확인 — 시험 계정, 폰 · PC)

1. 새 계정 가입 → 투구 · 트레이닝 · 영양 첫 설정 → 탭 잠금 풀림 · 튜토리얼 한 번.
2. 아침 체크인(어깨 통증) → 트레이닝 일정이 팔 쉬기 · 암케어 회복 · 메커니즘 접힘 · 영양 조언이 같은 날 같은 말.
3. 불펜 기록(손) → 구속 측정 세션 저장 → 투구 탭 · 홈 달력 · 내일 트레이닝 일정의 투구 수가 한 번만 셈.
4. 운동 시작 → 세트 몇 개(비행기 모드 섞어) → 마치기 두 번 빠르게 → 운동 시간 · 기록 하나.
5. 프로필 체중 바꿈 → 영양 목표 · 홈 링이 바로 바뀜.
6. 3D 분석: 올리기 → 분석 → 결과. 같은 영상 다시 · 엔진 바뀐 뒤 다시.
7. 자정 넘기기(시험 계정 '다음날로') → 모든 탭이 같은 날짜.
