# 타자 시점 공 크기·속도 검토 — 2026-10-27

## 유지한 실제 치수와 고정 시점

[2026 공식 야구규칙](https://mktg.mlbstatic.com/mlb/official-information/2026-official-baseball-rules.pdf)의 2.04·3.01을 확인했습니다. 투수판 앞면부터 홈 뒤 꼭짓점까지는 60피트 6인치, 공 둘레는 9–9¼인치입니다. 모델의 거리 18.4404m, 지름 7.32cm(둘레 약 9.05인치)는 이 범위에 있습니다.

카메라는 기존 우타석 x=−0.70m, 눈높이 1.60m, z=18.2904m, 가로 35°를 유지합니다. 좌완을 상대한다고 타자의 눈 위치나 시야각을 바꾸지 않습니다. 1× 공은 모든 투수·구종·거리에서 동일한 반지름 3.66cm입니다. 멀 때 강제로 키우거나, 가까울 때 크기를 제한하거나, 공을 따라 확대하지 않습니다. 1.8×는 명시적으로 선택하는 식별 보조입니다.

[Statcast CSV 문서](https://baseballsavant.mlb.com/csv-docs)의 릴리스 구속·익스텐션 구분을 참고했습니다. 속도는 손을 떠나는 초기 속도이며, 비행 시간은 전체 18.44m가 아닌 실제 릴리스 지점부터 홈 앞면까지 중력·항력을 적분한 값입니다. 위 구속은 가상 프로필이며 샘플 3·4 선수의 실측 구속이 아닙니다.

## 수정한 표시와 재생

- 공 구면의 분할 수를 32×24로 늘렸습니다. 물리 반지름과 카메라는 유지합니다.
- 실밥의 고정 1px 선이 먼 공의 테두리를 강조하던 현상을 줄였습니다. 투영 지름 12px 아래에서는 숨기고 12–24px에서 점진적으로 표시합니다. 공의 이동과 동일한 장식 회전이며 구종별 회전 단서로 사용하지 않습니다.
- 화면 아래로 다가오는 공을 회색으로 어둡게 만들던 장식 그라데이션을 타자 시점에서 숨깁니다. 기본 구장 조명과 하늘은 유지합니다.
- 검수의 기본 재생을 0.5×에서 **1× · 실제 속도**로 변경하고 느린 재생에 표시를 붙였습니다. 직접 선택한 0.25×/0.5×는 계속 사용할 수 있습니다.
- 정답 후 타자 시점을 고르면 같은 공을 처음부터 1×로 재생합니다. ‘다시 보기’는 현재 선택한 시점을 유지합니다. 투수 → 홈 공 추적만 기존 0.65×와 존 부근 연속 감속을 사용합니다. 공 읽기 훈련은 기존처럼 1×이고 타이밍·가림 시간·판정·저장 점수는 바꾸지 않습니다.

## 검증과 한계

단위 검증은 두 투구 손의 공 치수·거리별 각지름 증가·홈 앞면 도착·항력 감속을 확인합니다. 브라우저 검수는 가로 1440px/844px에서 우완·좌완 각각 약 25/150/300ms의 화면과 투영 좌표를 저장합니다. `scripts/check-ball-projection.py`는 Pillow로 흰 공의 연결 영역을 읽고 계산 지름과의 차이가 안티앨리어싱을 포함해 2px 이내인지 확인합니다. 공 픽셀 검수 전의 실패 사례에서 휴대폰 하단 그라데이션이 공의 대비를 떨어뜨리는 것을 발견해 제거했습니다.

같은 브라우저 검수에서 여섯 구종을 모두 재생하고 DOM에 표시되는 비행 시계와 경과 시간을 대조합니다. 시작·마지막 클램프 프레임을 제외하고 1× 비율이 0.92–1.08 안에 드는지 확인합니다. 프레임이 오래 끊긴 훈련은 기존 정책대로 중단하며 시간을 느리게 늘려 점수에 넣지 않습니다.

가로 35°는 고정한 가상 카메라의 시야각입니다. 모니터/휴대폰의 실제 폭과 눈–화면 거리를 측정하지 않으므로, 사람이 화면을 볼 때의 망막 각지름까지 현실과 같다고 주장하지 않습니다. 평면 화면은 양안 입체감·주변시야·눈 추적을 재현하지 않습니다. 휴대폰 크기의 Chromium 검수이며 실제 아이폰 기기의 프레임·체감 검증은 별도입니다.
